Check when upgrading: AppShell's `header` slot is now the first part of `<main>`, not a banner landmark before it. The workspace holds `main.app-shell-main` alone and `div.app-shell-header` is main's first child, still sticky, so "Skip to content" lands on the page's title and the page's `h1` is inside the main landmark; a `header` element in the slot is no longer a banner. A selector such as `.app-shell-workspace > .app-shell-header` no longer matches (`.app-shell-main > .app-shell-header` does), and a click on the header's empty space now focuses `<main>` rather than the body. Once hydrated, AppShell measures its header with a `ResizeObserver` and writes its height as `--page-sticky-top` on `<main>`, so a DataTable's header row and a SidePanel stick under it with nothing set by you. Nothing is measured for the first paint, and nothing is written on the root element. A `--page-sticky-top` you set on the shell's own `style` is now a first-paint estimate that main's measured value overrides; to set the offset yourself, pass the new `measuresHeader={false}`. A control that focus lands on under the stuck header, by Shift+Tab or `focus()`, is scrolled just clear of it once hydrated, whether or not the shell measures, and focus on the header's own controls never moves the page; a header compensation of your own for focus, such as a `scroll-padding-top` on `html`, would now add to it, so remove it.
