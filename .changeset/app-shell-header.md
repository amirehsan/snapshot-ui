Check when upgrading: AppShell's `header` slot is now the first part of `<main>`, not a banner landmark before it. The workspace holds `main.app-shell-main` alone and `div.app-shell-header` is main's first child, still sticky, so "Skip to content" lands on the page's title and the page's `h1` is inside the main landmark; a `header` element in the slot is no longer a banner. A selector such as `.app-shell-workspace > .app-shell-header` no longer matches (`.app-shell-main > .app-shell-header` does), and a click on the header's empty space now focuses `<main>` rather than the body. Once hydrated, AppShell measures its header with a `ResizeObserver` and writes its height as `--page-sticky-top` on `<main>`, so a DataTable's header row and a SidePanel stick under it with nothing set by you, and as `--app-shell-header-block-size` on the root element, whose new `scroll-padding-block-start` keeps a control that focus moves to clear of the stuck header. Nothing is measured for the first paint. A `--page-sticky-top` you set on the shell's own `style` is now a first-paint estimate that main's measured value overrides; to set the offset yourself, pass the new `measuresHeader={false}`. DataTable's `--data-table-scroll-start`, the scroll margin of its rows, list items and day headings, now subtracts `--app-shell-header-block-size`, which the root's padding already holds, so a row that focus reaches is not pushed down twice; a stylesheet of yours that reads or overrides it should do the same.
