### `feat/shell-overlays` (PR #9)

All 13 plan tasks are complete, each task-reviewed and fixed. The whole-branch final review and its fix wave are complete. The full visual check passed 1034/1034, and `pnpm verify` and the docs e2e passed before the last commit.

The last commit, `16f856a fix: give focus back at once when an overlay stacked over a dialog closes`, fixes a real race that CI exposed:
- React Aria's dialog re-focuses itself 500ms after mount when focus is on the body;
- its restore after an overlay unmounts waits for the next animation frame;
- on a slow machine the timer wins, and focus sticks on the outer dialog instead of the trigger.

A review of that commit says **Needs fixes**: the hook is too loose for Popover uses.
1. In a ComboBox inside the library Popover, pressing a blank part of the page pulls focus back into the input.
2. It calls `focus()` without React Aria's `react-aria-focus-scope-restore` event, so a link preview reopens after Escape (WCAG 1.4.13).

The reviewer's candidate replaces the hook body in `packages/react/src/overlay/useGiveFocusBack.ts`. It passed all 248 overlay tests and probes, against 246 for the committed hook:

```ts
export function useGiveFocusBack(originRef: RefObject<Element | null>): void {
  const isOriginRead = useRef(false);
  useLayoutEffect(() => {
    if (isOriginRead.current) return;
    isOriginRead.current = true;
    originRef.current = document.activeElement;
  }, [originRef]);
  // Layout cleanups of a removed subtree run before React detaches its DOM, so this is where focus was.
  const focusAtRemoval = useRef<Element | null>(null);
  useLayoutEffect(() => () => {
    focusAtRemoval.current = document.activeElement;
  }, []);
  useEffect(() => () => {
    const left = focusAtRemoval.current;
    // Only when focus was inside what just left the page.
    if (left === null || left === document.body || left.isConnected) return;
    const active = document.activeElement;
    if (active !== null && active !== document.body) return;
    const origin = originRef.current;
    if (!(origin instanceof HTMLElement) || origin === document.body || !origin.isConnected) return;
    // React Aria's own restore event, so a trigger that owns its restore (a link preview, a collection) handles it.
    const restore = new CustomEvent('react-aria-focus-scope-restore', { bubbles: true, cancelable: true });
    if (origin.dispatchEvent(restore)) origin.focus({ preventScroll: true });
  }, [originRef]);
}
```

## The roadmap and its order

The order comes from the first consumer, the Esizone Wallet app, which is being rebuilt on this library.

1. **Batch 1, the app shell.**
   - The overlays: done, in PR #9.
   - The shell (`feat/app-shell`, plan `docs/plans/2026-10-12-app-shell.md`): compact density, AppShell, Sidebar, BottomTabBar, and the routing docs page.

   When both are merged, merge #8 to publish, then tell the owner that batch 1 is out.
2. **Batch 2, Home:**
   - **StatTile:** a label, a hero-size value, a change line with an arrow and a word (never color alone), a caption, an optional sparkline slot, and the whole tile as a link.
   - **Meter:** several segments in one bar (spent, and held hatched), a marker for where spending would be today, an over-limit state, and label and value text.
   - **Avatar:** an image with an initials fallback at 24, 32 and 40px, squarish for merchant and bank logos.
   - **Line and sparkline charts:** SVG rendered on the server, points reachable by keyboard with tooltips, a table alternative, and labels passed in already formatted.
3. **Batch 3, Transactions:**
   - **DataTable:** sorting controlled from outside (from the URL); selection with select-all and a bulk-action bar; arrows or J/K to move, Enter to open, X or Space to select; a row opens a detail panel through a link; a sticky header; right-aligned tabular numbers; a totals row; skeleton rows; an empty slot; and a phone layout as a list grouped by day.
   - **SidePanel:** beside the content on desktop with no scrim, a bottom sheet on phones, with the open state driven by the URL.
   - **Tabs, Select, ComboBox, MultiSelect and Pagination.**
   - **FilterChip and FilterBar:** a pill that opens a popover with single choice, multiple choice or custom content; a clear control; a "More" overflow; and one Filters sheet on phones.
   - **SearchField, DateRangePicker,** and a **NumberField money mode** (dollars and cents, negatives, a decimal keyboard).
4. **The rest of the original roadmap,** `docs/specs/2026-10-10-snapshot-ui-design.md` section 11: phases 2 to 5 minus the parts above, then phase 6 (the charts package) and phase 7 (the HTML version). The app builds its own interim Alert, EmptyState, Skeleton, PageHeader and ThemeSwitch, so those are not urgent.

Rules every part follows, from the consumer:
- `'use client'` only on interactive parts;
- no `Intl` formatting and no `window` at render, and no first-paint measurement;
- no external requests or injected scripts;
- light and dark, all three shapes, right to left (the app has a Persian guide);
- WCAG 2.2 AA including 2.5.8;
- anything that navigates goes through `RouterProvider`;
- everything is exported from the react index, with the CSS in `core/styles.css`.

## How the work is done

Each piece of work has a spec in `docs/specs/` and a plan in `docs/plans/`. Each plan is executed task by task:
- an implementer under TDD;
- a task review (spec compliance and quality);
- fix rounds for Important findings, each with a scoped re-review;
- after the last task: a full visual check, a whole-branch final review, one fix wave, a scoped re-review, then push and a PR.

Merging and releasing are the owner's; the agent cannot merge.

Rules that bind every commit (also in `CLAUDE.md`):
- Conventional messages, no body, no Co-Authored-By line, never mentioning Claude Code;
- no em dashes or emojis anywhere;
- never name the private app this library was extracted from;
- weights 400, 450, 500 and 700 only, tokens only.

## What needs local Docker or local files

| Step | Why it needs the local machine |
| --- | --- |
| Generating or changing visual baselines (`pnpm --filter @snapshot-ui/storybook visual:docker`) | It runs Playwright inside `mcr.microsoft.com/playwright:v1.64.0-noble` for linux/amd64, so baselines match CI byte for byte. Without Docker, new or changed baselines cannot be produced. CI's "Visual regression" job only CHECKS baselines. |

| The `storybook-webkit` Vitest project (the Sheet stories) | It needs Playwright's WebKit build installed. A cloud session may install it with `pnpm exec playwright install webkit`. |
| `pnpm check:public` | It reads `.local/private-names.txt`, which is gitignored and exists only on the owner's Mac. In the cloud, rely on CI's "Public names" job, which reads the `PRIVATE_NAMES` repo secret. |
