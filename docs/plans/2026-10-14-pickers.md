# Pickers: SearchField, Select, ComboBox, MultiSelect, Tabs and Pagination, Batch 3a, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the first consumer's Transactions page its choice and navigation basics, in the spec's build order: `SearchField`; `Select` with the shared option parts `PickerOption` and `PickerSection`; `ComboBox`; `MultiSelect` on ComboBox's multiple mode and a `TagGroup`; `Tabs` with link tabs and a changed dot; and `Pagination` with a server-safe shell. Every part's CSS ships in `@snapshot-ui/core` (`search-field.css`, `select.css`, `combo-box.css`, `multi-select.css`, `tabs.css`, `pagination.css`, all imported by `styles.css`, and one shared class, `.input-button`, in `input.css`), every part has its own docs page, the docs site's own `.search-field`, `.tabs` and `.tab` classes stop colliding with the library's, and the batch ships as one release: `@snapshot-ui/core` and `@snapshot-ui/react` 0.4.0. `@snapshot-ui/charts` is unchanged at 0.1.0.

**Architecture:**

- **One list, three triggers.** Select opens from a button, ComboBox from an input, MultiSelect from an input in a frame of tags, and all three open React Aria's `ListBox` in the library's `Popover`, wearing `menu.css`'s classes, with rows from one part, `PickerOption`. No new row CSS: the Menu's rows already say "the listbox of the choice controls inherits them" (`packages/core/src/components/menu.css:2`).
- **One field look.** Select's trigger, ComboBox's and SearchField's input and MultiSelect's frame all wear `.input`, so every edge and state rule in `input.css` (hover, focus, disabled, changed, invalid) is written once and reached through the `.field` root (`input.css:65-71`). One new shared class, `.input-button`, draws a button inside a field.
- **React Aria 1.22's names only.** The pickers take `value`, `defaultValue` and `onChange`; `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are deprecated in the installed types (react-stately 3.51.0, `dist/types/src/select/useSelectState.d.ts:16-33`, `combobox/useComboBoxState.d.ts:38-55`) and omitted from every wrapper.
- **The URL is the app's state.** Every part works controlled and uncontrolled. Link tabs and page links are anchors routed through `RouterProvider`; no part reads `window.location`, so the server's HTML is already right.
- **Client where it must be.** Every part takes focus and keys, so each is a client module, except the Pagination shell: `pagination/Pagination.tsx` has no hooks, no `'use client'` and no React Aria import, calls the app's functions (`getPageHref`, `pageLabel`, `labels.page`) where it renders, and hands its client leaves only strings, numbers, booleans and server-rendered children.
- Every task is one reviewable deliverable, one per part, in the spec's build order, and a last docs task for the guides.

**Tech Stack:** unchanged from batch 2: pnpm 10.10, Turborepo 2.11, Node 24.5 or later, TypeScript 7 beside the TypeScript 6 API, Lightning CSS 1.33 with the browser floor Chrome 111, Safari 16.4 and Firefox 128, Stylelint 17, Tailwind CSS 4.3, React 19.3, react-aria-components 1.22.1 (on react-aria 3.53.1 and react-stately 3.51.0), lucide-react 1.55, tsdown 0.23, Vitest 5 with jsdom 30, Testing Library, axe-core 4.14, Storybook 10.6 with the a11y and Vitest addons, Playwright 1.64, Next.js 16.4 on Fumadocs 16, Changesets 3.0, publint 0.3, `@arethetypeswrong/cli` 0.18 and size-limit 14.

**Spec:** `docs/specs/2026-10-14-pickers-design.md`, approved, with the owner's seven rulings in its section 10.1 followed exactly: (1) MultiSelect is React Aria's `ComboBox` in `selectionMode="multiple"` with the chosen values as a `TagGroup` drawn by `ComboBoxValue`; (2) the list is a popover at every width, never a sheet; (3) tabs that navigate are React Aria's tabs with `href`, `selectedKey` from the URL and `keyboardActivation="manual"`; (4) Pagination is Previous, numbered pages with gaps and Next, the numbers leaving under a 30rem container, in a server-safe shell that takes `getPageHref`, with `hasPageNumbers={false}` for the short form; (5) one shared `PickerOption` and `PickerSection`; (6) no debounce in SearchField; (7) the filter shows at 9 options or more, `isFilterable` overrides it either way, and on a coarse pointer the filter does not take focus when the list opens. The parent spec is `docs/specs/2026-10-10-snapshot-ui-design.md`; the design authority is `docs/design-system.md`, including Appendix B. Section numbers below are the pickers spec's unless they say otherwise.

**Source app:** the private app this library was extracted from is never named. Its path is in the gitignored `.local/SOURCE.md`; no task opens `.local/`, and nothing it holds is copied into a committed file. The consumer is "the consumer" or "the first consumer".

## Global Constraints

### Runtime and packaging

- Node `>=24.5`, `"packageManager": "pnpm@10.10.0"`, every package `"type": "module"`, ESM only.
- `@snapshot-ui/react` keeps its two dependencies, `react-aria-components` 1.22.1 and `lucide-react`, and gains none. It never imports `@react-types/shared`, `react-aria` or `react-stately` directly: every type it needs (`Key`, `Placement`, `ValidationResult`, the render props) comes from `react-aria-components`, which re-exports them (`dist/types/exports/index.d.ts:93,164,202`), and a type it does not re-export is spelled out (spec correction 6).
- Both packages build with tsdown in `unbundle` mode under `tsconfig.build.json`, which turns on `isolatedDeclarations`: every exported function and constant declares its full type, return types included.
- `tsconfig.base.json` has `types: []`, so `process` is not typed. A development warning is a `console.warn` guarded by a ref, once per mount, in an effect, in every build (`packages/react/src/bottom-tab-bar/BottomTabBar.tsx:50-54`).
- **Versions.** Core and react stay a fixed group (`.changeset/config.json`), and the batch's six minor changesets take them from 0.3.0 to 0.4.0. No changeset names `@snapshot-ui/charts`.

### React components

- Every source file that imports `react-aria-components` starts with `'use client';`, and so does every `.tsx` under `src` that uses state, an effect, a ref callback with state, or a context. `useId` is the one hook a static module may call (the home plan's rule). `packages/react/test/server-components.test.tsx` lists every static module (`STATIC_MODULES`, `:181-192`), and its last describe fails on any `.tsx` that is neither a client module nor listed (`:207-232`).
- The static module of this plan: `pagination/Pagination.tsx`. The client modules: `search-field/SearchField.tsx`, `picker/PickerOption.tsx`, `picker/PickerSection.tsx`, `select/Select.tsx`, `combo-box/ComboBox.tsx`, `multi-select/MultiSelect.tsx`, `tabs/Tabs.tsx`, `tabs/TabList.tsx`, `tabs/Tab.tsx`, `tabs/TabPanel.tsx`, `pagination/PaginationLink.tsx`, `pagination/PaginationButton.tsx`, `pagination/PaginationStatus.tsx`. Pure `.ts` modules (`pagination/pages.ts`, `pagination/useHandOff.ts`, `utils/quiet.ts`) carry no directive; `useHandOff.ts` is imported only by client modules.
- **Lucide only in client modules.** `lucide-react` 1.55's `Icon` is a client module (`node_modules/lucide-react/dist/esm/Icon.mjs:2`), so the static Pagination shell draws its two chevrons inline (spec correction 20). Every other glyph in this batch (`Search`, `X`, `Check`, `ChevronDown`) is a Lucide icon in a client module.
- **Value names.** Every picker exposes `value`, `defaultValue` and `onChange` and omits `selectedKey`, `defaultSelectedKey` and `onSelectionChange` from its props type. Tabs keep React Aria's `selectedKey`, `defaultSelectedKey` and `onSelectionChange`, which are not deprecated on `Tabs` (`react-aria-components` `dist/types/src/Tabs.d.ts:8`).
- `className` and `ref` go on the element each task names; `className` merges after the library's class through `cx` or `composeRenderProps`. Presence checks on rendered slots use `present()`, never `!= null`.
- Server safety (the consumer's rules): no `Intl` formatting, no `toLocaleString`, no `window`, `document` or `matchMedia` at render or import, no measurement for the first paint. Layout is read only in effects and event handlers (the tab row's scroll after mount, the coarse-pointer check when the list opens). React Aria's own collators are the one exception the spec accepts (risk R1, spec correction 5), and the two-locale server test pins that they write nothing.
- Every id the library writes comes from `useId`.
- `jsx-a11y` is in its strict config. Two elements carry a disable, each with its reason, and nowhere else: Select's filter field, `// eslint-disable-next-line jsx-a11y/no-autofocus -- the filter is the list's search, and a list that opens to be searched starts in it (spec ruling 7)`; and MultiSelect's frame, `// eslint-disable-next-line jsx-a11y/no-static-element-interactions -- a press on the frame's empty room is a press on its input, which stays the one tab stop (spec 7.5)`.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` after `charts.css`, in this order: `search-field.css`, `select.css`, `combo-box.css`, `multi-select.css`, `tabs.css`, `pagination.css`. The shared `.input-button` goes in `input.css`. `picker-empty` is drawn in `select.css`, the first file that needs it, and ComboBox and MultiSelect reuse it.
- **Tokens only.** Stylelint's `snapshot-ui/token-only` forbids a literal color, a literal radius and any `box-shadow` that is not `none` or a `var()`. A radius may be `min()`, `max()` or `clamp()` only when every argument is a token, a `var()`, zero or a `calc()` that reads one (`packages/core/stylelint/token-only.js:151-160`), so a halved token is written `calc(var(--size-field) / 2)` (spec correction 11). Class names are kebab-case and never start with a Tailwind namespace (`packages/core/stylelint.config.js`); `search-field-`, `select-`, `combo-box-`, `multi-select-`, `picker-`, `input-button`, `tab-`, `tabs` and `pagination-` are safe.
- **System colors** only inside `@media (forced-colors: active)` (the shared `css.test.js` check, `:195-201`); `canvas` lowercase there.
- **States** are data attributes beside their native twins (`:is(:hover, [data-hovered])`, `:is(:active, [data-pressed])`, `:is(:focus-visible, [data-focus-visible])`, `:is(:disabled, [data-disabled])`). Hover rules sit inside `@media (hover: hover)`, and a press shows the hover look.
- **The focus ring** is `outline: var(--focus-ring-width) solid var(--focus-ring-color); outline-offset: var(--focus-ring-offset);`, outside the part. On an ink fill (a selected tab, the current page) it is the canvas ring inside the pill, SegmentedControl's rule (`segmented.css:178-184`). Rows keep the Menu's inset ring.
- **Specificity against `.input`.** A picker's override of an `.input` property is one class, written after `input.css` (the import order test pins it), so it beats `.input` and still loses to `.input`'s state rules (`:hover`, `:focus-visible`, `:disabled`, all two classes) and to the field's changed and invalid edges (three). A rule that must beat the hover edge but not the changed one is two classes with its extra test in `:where()` (spec correction 12).
- **Motion.** Only Select's chevron moves (140ms); `select.css` carries the reduced-motion block the shared test asks for wherever something moves (`css.test.js:180-184`). Nothing else in this batch transitions.
- **Logical properties** throughout. The two mirrors use the attribute, as the sidebar does (`sidebar.css:505-507`): `[dir='rtl'] .pagination-step svg { scale: -1 1; }`. Nothing else is mirrored: a magnifier, a down chevron and a check have no reading direction.
- **No z-index.** The popovers stack through the overlay layer they already use.

### Design rules

- **Theme axes:** light and dark, the three shapes, compact density. Everything here reads density through `--size-field` and `--size-control` (48 and 40px, 36 and 36px compact, 44 and 44px compact on a coarse pointer, `packages/core/dist/tokens.css:95-97,230-242`).
- **Typography:** weights 400, 450, 500 and 700 only. A tab, a page control and a tag are 500; labels, hints and the range follow the field parts' steps.
- **Reserved colors.** Clay only for the tab's changed dot and the field parts' Changed chips (unsaved); light signal orange only for a changed field's edge, which `input.css` draws; error only for invalid; taupe only for placeholders and disabled text, slate for the placeholder only where no visible label names the field (SearchField's `data-unlabelled`, which Select's filter is too), the exception CommandPalette recorded. Signal orange appears nowhere. State is never color alone: the chosen option has a check, the changed dot is read as a word, the current page is a filled shape and `aria-current`.
- **Surfaces:** the lists are the Menu's float popover; the tab track is canvas with no edge; tags are bone pills in the raised frame.
- **Contrast records.** Every text or graphic color this batch draws on a token surface is already in `CONTRAST_PAIRS` (ink, slate and clay on every surface, canvas on ink, ink and slate on bone), so no task adds to the gate (spec correction 25). Each task's `contrast.test.js` describe cites the gated pairs and recomputes, to two decimals, every value its Appendix B record states; a mix (the 5% wash) or a pair that fails (clay on ink, the reason for the dot's ring) is measured there and recorded, not gated.
- **Strings.** The library writes these of its own, English by default and every one replaceable: SearchField's `clearLabel`; Select's `placeholder` and `labels` (`filter`, `empty`); ComboBox's `labels` (`open`, `empty`, `loading`); MultiSelect's `labels` (those three, `selected`, `remove`); Tab's `changedLabel`; Pagination's `labels` (`navigation`, `previous`, `next`, `page`). React Aria's announcements are its own and follow `I18nProvider`, with no Persian (spec correction 8).

## Review Focus

The input classes the spec implies that a part's ordinary tests would not exercise, most likely first. Each is pinned by a test in the task named.

1. **One row in two places.** React Aria's `SelectValue` renders the chosen option's own children in the trigger (`react-aria-components` 1.22.1, `dist/private/Select.mjs:227`), so a `PickerOption` is drawn twice while the list is open. In the trigger it must draw its icon and label only, write no id, and leave the trigger's name "label, value". Pinned in Task 2 (the trigger test counts one element per id with the list open; the name test).
2. **The filter's threshold and its focus.** Eight options never show the filter and nine always do, counted across sections and not counting headings (`collection.size` counts items only, react-aria 3.53.1 `dist/private/collections/BaseCollection.mjs:109-111,184`); `isFilterable` wins both ways; the text is empty on every open; Escape clears and then closes; and on a coarse pointer focus stays out of the field. Pinned in Task 2 (the unit tests with a mocked `matchMedia`, the touch e2e).
3. **The frame is not a group.** MultiSelect's frame must position the popover (React Aria reads the group ref, `ComboBox.mjs:152-156,283`) without becoming React Aria's `Group`, whose focus-within `data-focus-visible` (`Group.mjs:34-36`) would ring the whole frame while a tag holds focus. Pinned in Task 4 (the frame shows no ring when a tag is focused, and the popover's left edge is the frame's).
4. **Removal and focus.** Backspace in an empty input focuses the last tag and only a second press removes it; Backspace or Delete on a tag removes it; focus goes to the next tag, the previous one, then the input; and the edges of a changed or invalid frame hold through focus. Pinned in Task 4.
5. **Static stays static.** The Pagination shell renders under React's server build with `getPageHref`, `pageLabel` and `labels.page` called there, and its HTML holds no function and no React Aria attribute from the shell itself. Pinned in Task 6 (`server-components.test.tsx`, with the three leaves mocked, as `StatTileLink` is at `:33`).
6. **The server's HTML is right and locale-free.** A Select's chosen value, the selected tab and its panel, MultiSelect's tags and its hidden inputs are in the server's HTML, and a ComboBox and a Select render the same HTML under two locales (risk R1). Pinned in Tasks 2 to 5 (`server-render.test.tsx`).
7. **Right to left in two ways.** React Aria's arrows follow the locale (tabs, tags), the CSS follows the `dir` attribute (Pagination's chevrons and order, the icon and button sides of every field), and nothing that has no direction is mirrored. Pinned in each task's `Mirrored` play and `RightToLeft` story.
8. **The docs never draw two looks.** The docs site's `.search-field` (`apps/docs/components/shell/shell.css:942-968`) and `.tabs` and `.tab` (`:212-246`, `apps/docs/app/site.css:120-125`) would restyle the library's parts on their own pages. Pinned in Task 1 (the search dialog's row keeps its look under a new name) and Task 5 (the preview tabs are the library's Tabs, and the docs CSS has no `.tab` rule left).
9. **The spoken range.** Silent on first render and in Strict Mode's second effect, one announcement 600ms after the last of several quick changes, and spoken again when a later change returns to the first range. Pinned in Task 6 (fake timers).

## Spec corrections

Mismatches found while reading the spec against the repository, the installed packages and the consumer's rules. Each is resolved in the task named; those marked **choice** are design decisions for the controller to see.

1. **The docs collision fix is split: the search row in Task 1, the tabs in Task 5** (spec 10.2 item 11, R4). See "Why the docs collision fix is split" above. **Choice** (Tasks 1 and 5).
2. **In Select's trigger an option draws its icon and label only, by render, not by CSS** (spec 6.3, "The trigger's value"). `SelectValue` renders the chosen item's own `children` (`react-aria-components` `dist/private/Select.mjs:227-241`), which for `PickerOption` is the whole row: the label and hint as `Text` slots, the end value's `span` with its `useId` id, and the check. Hidden by CSS, the end value's id would still be written twice while the list is open, once in the trigger and once in the option, and an option's `aria-describedby` would resolve to whichever comes first. So `PickerOption` renders its row through a small component that reads a private context, `PickerValueContext`, which `Select` provides around its `SelectValue`; inside it the row is `span.menu-item-icon` (when given) and `span.select-value-label`, with no id, no hint, no end value and no check. The spec's `.select-value :is(...) { display: none }` rule is not written. Task 2.
3. **The coarse-pointer check runs in `onOpenChange`; a list opened by `defaultOpen` or by the app's `isOpen` focuses its filter** (spec 6.3, ruling 7). The spec puts the check "in the open handler, an event and not render". React Aria calls `onOpenChange(true)` for an open the user starts and not for one the app sets, so a list that opens from `defaultOpen`, or from `isOpen` the app sets without a user's press, keeps the default, the focused filter. Task 2.
4. **A closed Select also answers Left and Right** (spec 6.3, 11). React Aria's `useSelect` chooses the previous or the next option on Left and Right while closed, without opening, in single mode (react-aria `dist/private/select/useSelect.mjs:58-70`). They are physical keys and do not follow the reading direction. The Keys table gains the row; nothing is added or removed. Task 2.
5. **Risk R1 applies to Select as well as ComboBox** (spec 14). `useSelect` makes a collator at render for the closed type-to-select (`useSelect.mjs:43`), as `ComboBox` does for its filter (`ComboBox.mjs:101`). The two-locale server test therefore renders both, and the release note names both. Task 2 and Task 3.
6. **`PickerOption` omits every link prop, not only `href`** (spec 6.1). `ListBoxItemProps` extends `LinkDOMProps` (`react-aria-components` `dist/types/src/ListBox.d.ts:108`), whose keys are `href`, `hrefLang`, `target`, `rel`, `download`, `ping`, `referrerPolicy` and `routerOptions` (`@react-types/shared` 3.37.0 `src/dom.d.ts:236-243`). `react-aria-components` does not re-export `LinkDOMProps`, and the package never imports `@react-types/shared`, so the eight keys are spelled out in the `Omit`. Task 2.
7. **ComboBox's and MultiSelect's controls take React Aria's group ref; neither is React Aria's `Group`** (spec 7.2, 7.5, 7.6). `ComboBox` positions its popover against the element its `GroupContext` ref holds, else against the input (`ComboBox.mjs:152-156`, the context at `:280-287`). MultiSelect's input is a small part of the frame's last row, so without the ref the list would open under the input at the input's width. React Aria's `Group` would take the ref but also brings `role="group"` and a focus-within `data-focus-visible` (`Group.mjs:34-36,52-56`), which `.input`'s focus rule (`input.css:45-49`) would turn into a ring on the whole frame while a tag holds focus, which spec 7.6 forbids. So each control is a plain `div` that takes `useSlottedContext(GroupContext)?.ref`, and the wrapper writes `data-disabled` itself. ComboBox's control takes the same ref, so both lists align to and match the drawn control. **Choice** (Tasks 3 and 4).
8. **React Aria has no Persian strings** (spec 4, 7.2). react-aria 3.53.1 ships 34 locales for its combo box strings, Arabic and Hebrew among them and no Persian (`dist/private/intl/combobox/`), so on a `fa-IR` page its announcements ("3 options available", "Apple, selected") and the names it writes by default are English. The library's own `labels` are therefore the only way to put Persian on the controls, and the release note says the announcements stay English. An open question for the owner. Task 3.
9. **Multiple mode's `value` is `readonly Key[]`** (spec 7.4). react-stately types the value as `ValueType<'multiple'> = readonly Key[]` and `onChange`'s argument as `Key[]` (`dist/types/src/combobox/useComboBoxState.d.ts:7-8`). The docs and the changeset say so. Task 4.
10. **The frame's block padding is 4.5px, not 6px** (spec 7.6). A 36px tag in a frame with 6px of padding and a 1px edge is 50px tall, not the 48px a field is, and the 1.5px edge a focused, changed or invalid frame draws makes it 51px. `padding-block: calc(0.375rem - 1.5px)` keeps a one-row frame at `--size-field` (48, 36, 44px) with either edge, since `min-height` then holds it. Task 4.
11. **The frame's corner is written with `calc()`** (spec 7.6). `min(var(--radius-pill), var(--size-field) / 2)` fails the token rule, which reads the bare `2` as a literal radius (`token-only.js:153-154`); `min(var(--radius-pill), calc(var(--size-field) / 2))` passes and means the same. Task 4.
12. **The frame's focus rule is two classes with its `:has()` in `:where()`** (spec 7.6). Written plainly, `.multi-select-control:has(.multi-select-input:focus-visible)` weighs three classes, the weight of `.field[data-changed] .input` (`input.css:65`), and coming later it would replace a changed or invalid edge with the focus edge, which `input.css` never does. `.multi-select-control.input:where(:has(...))` weighs two, so it beats the hover edge by order and loses to the changed and invalid edges. Task 4.
13. **Tags show the option's text value, and the last removal focuses the input** (spec 7.5, 7.6). `ComboBoxValue`'s `selectedItems` are the options' object values, `null` for static children (`ComboBox.mjs:324`), so the tags are built from `state.selectedItems`, React Aria's nodes, by `key` and `textValue`; an option whose children are not a string needs a `textValue`, and the docs say so. React Aria's `TagGroup` focuses its grid when the last tag goes (react-aria `dist/private/tag/useTagGroup.mjs:56-59`); the wrapper moves focus on to the input, as the spec asks. Task 4.
14. **The input empties after a choice unless the app controls both `value` and `inputValue`** (spec 7.5). React Aria resets the input to the chosen text, which in multiple mode is empty, only when one of the two is uncontrolled (react-stately `dist/private/combobox/useComboBoxState.mjs:215`). An app that controls both (a server search with the value in the URL) clears `inputValue` in its own `onChange`; the docs show it. Task 4.
15. **A changed tab's words are in a `hidden` span, not a visually hidden one** (spec 8.2). A visually hidden span inside the tab is part of the tab's content, so its name would be "Rules Changed". A `hidden` span leaves the name and still gives the description, since `aria-describedby` reads an element it names directly even when it is hidden (Accessible Name 1.2, step 2A), which the field parts already rely on for their chip. Task 5.
16. **A hovered tab's text turns ink** (spec 8.3). Slate on the 5% ink wash over canvas measures 4.38 in light, under the 4.5 text minimum (6.93 in dark); ink on it is 14.70 and 17.41. SegmentedControl turns its hovered option ink for the same reason (`segmented.css:133-138`). Task 5.

With `shouldForceMount` React Aria renders the panel with `inert` and `data-inert` and nothing that hides it (`Tabs.mjs:316-317`). `tabs.css` adds `.tab-panel[data-inert] { display: none; }`. The harness shoots 1280 and 375 only (`stories.spec.ts:20-48`), and Storybook renders on the client, so a story cannot show the row before its effect. The two glyphs use Lucide's own geometry: left `m15 18-6-6 6-6`, right `m9 18 6-6-6-6`, 24 by 24, stroke 2, round caps and joins, `currentColor`. Task 6.

```tsx
      </div>
    ) : null}
    <div className="search-field-control">

);
```

9. **What the filter keeps.** With text, an option stays when every whitespace-separated word of the text appears in its text value, through `useFilter({ sensitivity: 'base' }).contains`, CommandPalette's rule (`CommandPalette.tsx:139-140,213-219`), so case and accents do not count; React Aria hides a section with nothing left. With no text the filter is `undefined`, so every option shows. `SelectList` mounts each time the list opens (React Aria's popover renders nothing while closed), so the text is empty on every open and the collator is made only in a browser that opened the list.
10. **On a coarse pointer** the filter field does not take focus when the list opens (ruling 7, spec correction 3): `onOpenChange(true)` reads `matchMedia('(pointer: coarse)').matches` and stores whether to focus the filter; a list opened by `defaultOpen` or by the app's `isOpen` focuses it. Where focus then lands is fixed by the spike in Step 3: inside the popover, on the list, with the arrows moving the active option.
11. **Nothing matches.** The `ListBox`'s `renderEmptyState` draws `div.picker-empty` with `labels.empty` (default `'No matches'`).
12. **Phones** (ruling 2). The list is a popover at every width: React Aria flips it above the trigger when there is more room there, caps its height at 320px or the room left, and keeps it 12px inside the viewport; the popover's width caps at the viewport less 2rem (`menu.css:13-17`, `popover.css:9`).
13. **Forms and URL state.** `name` submits the chosen key through React Aria's hidden select (`Select.mjs:216-219`). A Select has no clear action: an app that needs "Any" adds it as an option.
14. **Server.** It renders in Node with the trigger showing the chosen option's label (the probe in "How this plan was made"), the placeholder when nothing is chosen, and the hidden select; the popover renders nothing until it opens. Its HTML is the same under `I18nProvider` `en-US` and `fa-IR` (spec correction 5).

```tsx
// Select.tsx
/** The words of a query, split at whitespace: CommandPalette's rule. */
const wordsOf = (query: string): string[] => query.split(/\s+/).filter(Boolean);

/** Mounted each time the list opens, so the text starts empty and the collator is made only in a browser. */
function SelectList<T extends object>({ items, children, isFilterable, focusFilter, labels }: ListProps<T>): ReactElement {
  const state = useContext(SelectStateContext);
  const { contains } = useFilter({ sensitivity: 'base' });
  const [text, setText] = useState('');
  const filter = useMemo<AutocompleteProps<T>['filter']>(
    () =>
      text.trim() === ''
        ? undefined
        : (textValue, input) => wordsOf(input).every((word) => contains(textValue, word)),
    [text, contains],
  );
  const list = (
    <ListBox<T>
      className="menu select-list"
      items={items}
      renderEmptyState={() => <div className="picker-empty">{labels.empty}</div>}
    >
      {children}
    </ListBox>
  );
  if (!(isFilterable ?? (state?.collection.size ?? 0) > 8)) return list;
  return (
    <Autocomplete<T> inputValue={text} onInputChange={setText} filter={filter}>
      <div className="select-filter">
        <SearchField
          aria-label={labels.filter}
          placeholder={labels.filter}
          // eslint-disable-next-line jsx-a11y/no-autofocus -- the filter is the list's search, and a list that opens to be searched starts in it (spec ruling 7)
          autoFocus={focusFilter}
        />
      </div>
      {list}
    </Autocomplete>
  );
}

// Inside Select: the coarse-pointer check is read when the user opens the list, never at render.
const [focusFilter, setFocusFilter] = useState(true);
const openChange = (isOpen: boolean): void => {
  if (isOpen) setFocusFilter(!window.matchMedia('(pointer: coarse)').matches);
  onOpenChange?.(isOpen);
};
```

```tsx
// ComboBox.tsx: rendered inside RACComboBox, so the context is the combo box's own.
function ComboBoxControl({ placeholder, inputRef, isLoading, labels }: ControlProps): ReactElement {
  // ComboBox.mjs:280-287 hands its group ref here; the list opens against this element and takes its width.
  const group = useSlottedContext(GroupContext);
  return (
    <div ref={group?.ref} className="combo-box-control">
      <Input ref={inputRef} className="combo-box-input" placeholder={placeholder} />
      {isLoading ? (
        <span className="combo-box-spinner">
          <Spinner size="md" aria-label={labels.loading} />
        </span>
      ) : null}
      <Button className="input-button combo-box-button" aria-label={labels.open}>
        <ChevronDown aria-hidden="true" />
      </Button>
    </div>
  );
}
```

1. **Basis** (ruling 1). React Aria's `ComboBox` with `selectionMode="multiple"` and `allowsEmptyCollection`, the chosen values drawn by `ComboBoxValue`'s render function as a `TagGroup`.
2. **Markup, in DOM order.** `RACComboBox.field.multi-select` (`className` merged after `field multi-select`; React Aria writes `data-open`, `data-invalid`, `data-disabled`; the wrapper writes `data-changed` and `data-loading`). Inside: `FieldHead` while labelled; `div.input.multi-select-control`, the drawn frame, which takes React Aria's group ref (spec correction 7) and carries `data-disabled` while `isDisabled`, holding `ComboBoxValue.multi-select-value` (whose render function draws the tags, Code), then `RACInput.multi-select-input` with `placeholder` while nothing is chosen and `inputRef`, then `span.combo-box-spinner` with the `Spinner` while `isLoading`, then `Button.input-button.combo-box-button` with `aria-label={labels.open}`; then `Description` and `FieldError`; then the popover and list exactly as ComboBox's (Task 3, Behavior 1). The tags are `TagGroup.multi-select-tags` with `aria-label={labels.selected}` and `aria-labelledby` the field label's id (read from `LabelContext`), which React Aria joins into "Selected Categories" (`react-aria` `dist/private/utils/useLabels.mjs`), holding `TagList.multi-select-tag-list` of `Tag.multi-select-tag`, each `span.multi-select-tag-text` and, unless disabled, `Button slot="remove"` (`multi-select-tag-remove`, Lucide `X`, `aria-label={labels.remove}`, which React Aria reads with the tag: "Remove Food", `useTag.mjs:85-86`).
3. **Choosing.** A press or Enter toggles an option, the list stays open for the next (React Aria closes on a choice in single mode only, `useComboBoxState.mjs:202-203`), and the input empties so the next search starts clean (spec correction 14). A chosen option shows the check alone, no ink pill: the Menu's multiple rule.
4. **The tags** are built from `state.selectedItems` by `key` and `textValue` (spec correction 13), in the order chosen, one row per option with its text ellipsized past 12rem.
5. **Removing.** A tag's remove button; Backspace or Delete on a focused tag (`useTag.mjs:54-66`); and Backspace in an empty input, which first moves focus to the last tag and removes it only on a second press. After a removal focus goes to the next tag, or the previous one when it was the last (React Aria's list state); when none is left it goes to the input (Code).
6. **Tab order.** The tags are one stop, a grid whose arrows move between them in the drawn direction, then the input; the button is out of the tab order. A press on the frame outside a tag and the input focuses the input.
7. **The frame's edges.** The frame is `.input`, so it takes the hover, disabled, changed and invalid edges through the field's root. While the input has focus the frame draws the focus edge and ring (spec correction 12); while a tag has focus, the tag rings itself and the frame draws nothing.
8. **Many values.** The frame grows a row at a time; nothing collapses into "and 3 more".
9. **Forms and URL state.** `name` submits one value per chosen key through React Aria's hidden inputs (`ComboBox.mjs:185-200`; the probe saw one `<input type="hidden">` per key). For URL state the app passes `value` from a repeated or a comma-joined parameter and writes it in `onChange`; an app that also controls `inputValue` empties it there.
10. **Server.** It renders in Node with the frame, a tag per chosen option and a hidden input per key, and no listbox.

```tsx
// MultiSelect.tsx: rendered inside RACComboBox.
const group = useSlottedContext(GroupContext); // the list opens against the frame (spec correction 7)
const labelId = useSlottedContext(LabelContext)?.id; // the field label's id, for the tags' name
const frameRef = useRef<HTMLDivElement>(null);
const ownInputRef = useRef<HTMLInputElement>(null);
const focusInputNext = useRef(false);
// React Aria does not re-export the state's type, so it is read from its context, as Menu reads its className.
type State = NonNullable<ContextType<typeof ComboBoxStateContext>>;
const count = useContext(ComboBoxStateContext)?.selectedItems.length ?? 0;

/** Removes keys from the value; when none is left, focus goes on to the input once the tags are gone. */
const remove = (state: State, keys: Set<Key>): void => {
  const rest = [...(state.value as readonly Key[])].filter((key) => !keys.has(key));
  if (rest.length === 0) focusInputNext.current = true;
  state.setValue(rest);
};
// An effect keyed on the number of tags runs after React Aria's own (child effects first) and wins.
useEffect(() => {
  if (!focusInputNext.current) return;
  focusInputNext.current = false;
  ownInputRef.current?.focus();
}, [count]);

/** The first Backspace in an empty input focuses the last tag; the tag's own Backspace removes it. */
const onInputKeyDown = (event: KeyboardEvent<HTMLInputElement>): void => {
  if (event.key !== 'Backspace' || event.currentTarget.value !== '') return;
  const tags = frameRef.current?.querySelectorAll<HTMLElement>('.multi-select-tag');
  const last = tags?.[tags.length - 1];
  if (!last) return;
  event.preventDefault();
  last.focus();
};
```

**Behavior:**

1. **Markup.** `RACTabs.tabs` (`className` merged after it, `ref`) holding `RACTabList.tab-list` (`role="tablist"`, `ref` merged with the wrapper's own) of `RACTab.tab` (`role="tab"`, a `div`, or an `a` when it has `href`, which React Aria renders, `Tabs.mjs:190`), each holding `span.tab-label` with `children` and, while `isChanged`, `span.tab-changed[aria-hidden="true"]` and `span[hidden]` with `changedLabel` (default `'Changed'`); then `RACTabPanel.tab-panel` (`role="tabpanel"`). The whole selected state renders on the server (the probe in "How this plan was made").
2. **Keys.** React Aria's: Left and Right move between tabs in the drawn direction of the locale, Home and End jump, and with automatic activation focus selects. Tab moves into the panel.
3. **Tabs that switch a panel.** Automatic activation, React Aria's default; one `TabPanel` per tab, only the selected one mounted unless `shouldForceMount`, and a force-mounted unselected panel hidden by `.tab-panel[data-inert]` (spec correction 17).
4. **Tabs that are links** (ruling 3). Each `Tab` has `href`; the app passes `selectedKey` from the URL and no `onSelectionChange`, and sets `keyboardActivation="manual"`, so the arrows move focus without loading a route per key, and Enter, Space or a press opens the focused tab's link through `RouterProvider` and leaves the selection to the URL (`react-aria` `dist/private/selection/useSelectableItem.mjs:46-52`, `tabs/useTab.mjs:38-39`). The app renders one `TabPanel` whose `id` is the selected key, holding the route's content, so `aria-controls` points at content that is there. A modified or middle click opens the link as the browser would.
5. **The changed dot.** `isChanged` is for a tab whose panel holds unsaved edits, and only that. The dot is drawn and hidden; the tab's `aria-describedby` names the `hidden` span ahead of the caller's ids, so a screen reader hears "Rules, tab, 2 of 4, Changed" and the name stays "Rules" (spec correction 15). A count or a "new" marker goes in `children` (a `Badge` fits), never in clay.
6. **A row that does not fit** scrolls inline inside itself; the page never scrolls sideways. A focused tab scrolls into view as the browser does for focus. After mount, an effect in `TabList` brings the selected tab into the list's view by `list.scrollBy` (Code; spec correction 18), so the server's HTML shows the start of the row and the selected tab arrives on hydration (R6).
7. **Server.** It renders in Node with the tab list, every tab, `aria-selected="true"` on the selected one and its panel.
8. **The docs' preview tabs** become `<Tabs className="preview" defaultSelectedKey="preview">` holding `div.preview-head` (the `Eyebrow` and `<TabList aria-label="Example">` with `<Tab id="preview">Preview</Tab>` and `<Tab id="code">Code</Tab>`) and two `TabPanel`s with `shouldForceMount`, so both panels stay in the page as they are today; the docs' own `.tabs` and `.tab` rules are deleted, and the tabs grow from the docs' 36px to the library's 40px (`--size-control`).

```tsx
const own = useRef<HTMLDivElement>(null);
const listRef = useMemo(() => mergeRefs<HTMLDivElement>(ref, own), [ref]);
// Once, after the first paint: the server's row starts at its first tab, and the selected one arrives here.
useEffect(() => {
  const list = own.current;
  const tab = list?.querySelector<HTMLElement>('[role="tab"][aria-selected="true"]');
  if (!list || !tab) return;
  const room = list.getBoundingClientRect();
  const box = tab.getBoundingClientRect();
  const pad = parseFloat(getComputedStyle(list).paddingInlineStart) || 0;
  if (box.right > room.right - pad) list.scrollBy({ left: box.right - room.right + pad });
  else if (box.left < room.left + pad) list.scrollBy({ left: box.left - room.left - pad });
}, []);
```

```ts
// pages.ts: no directive, no React.
export function clampPage(page: number, pageCount: number): number {
  return Math.min(Math.max(1, Math.trunc(page)), Math.max(1, pageCount));
}

export function pageItems(page: number, pageCount: number, siblingCount: number): PageItem[] {
  const pages = (from: number, to: number): PageItem[] =>
    Array.from({ length: Math.max(0, to - from + 1) }, (_, index) => ({ type: 'page', page: from + index }));
  if (pageCount <= 2 * siblingCount + 5) return pages(1, pageCount);
  // The siblings' window, held clear of the first two and the last two slots.
  const start = Math.max(Math.min(page - siblingCount, pageCount - 2 * siblingCount - 2), 3);
  const end = Math.min(Math.max(page + siblingCount, 2 * siblingCount + 3), pageCount - 2);
  return [
    ...pages(1, 1),
    // A gap that would stand for page 2 alone shows page 2.
    ...(start > 3 ? [{ type: 'gap', side: 'start' } as const] : pages(2, 2)),
    ...pages(start, end),
    ...(end < pageCount - 2 ? [{ type: 'gap', side: 'end' } as const] : pages(pageCount - 1, pageCount - 1)),
    ...pages(pageCount, pageCount),
  ];
}
```

```tsx
'use client';

export function PaginationStatus({ rangeLabel, warning }: PaginationStatusProps): ReactElement {
  const [message, setMessage] = useState('');
  const last = useRef(rangeLabel);
  useEffect(() => {
    // The first render, and Strict Mode's second effect, find the label unchanged: nothing to say.
    if (rangeLabel === last.current) return;
    last.current = rangeLabel;
    const timer = setTimeout(() => {
      setMessage(rangeLabel);
    }, QUIET_MS);
    return () => {
      clearTimeout(timer);
    };
  }, [rangeLabel]);
  const warned = useRef(false);
  useEffect(() => {
    if (warned.current || warning === undefined) return;
    warned.current = true;
    console.warn(warning);
  }, [warning]);
  return (
    <span className="pagination-status" role="status">
      {message}
    </span>
  );
}

// useHandOff.ts: imported only by the two client leaves, for the steps.
export function useHandOff(ref: RefObject<HTMLElement | null>, isDisabled: boolean): HandOff {
  const hadFocus = useRef(false);
  useLayoutEffect(() => {
    if (!isDisabled || !hadFocus.current) return;
    hadFocus.current = false;
    const active = document.activeElement;
    // Focus that went somewhere else went there on purpose.
    if (active !== null && active !== document.body && active !== ref.current) return;
    const nav = ref.current?.closest('.pagination');
    const next =
      nav?.querySelector<HTMLElement>('.pagination-page[aria-current]') ??
      nav?.querySelector<HTMLElement>('.pagination-step:not(:disabled, [aria-disabled="true"])');
    next?.focus();
  }, [isDisabled, ref]);
  return {
    onFocus: () => {
      hadFocus.current = true;
    },
    // Focus lost with its element, or to a disabled button, has no related target; only a move clears the flag.
    onBlur: (event) => {
      if (event.relatedTarget !== null) hadFocus.current = false;
    },
  };
}
```
