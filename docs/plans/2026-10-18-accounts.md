# Accounts: DescriptionList, CardActions, Gauge and MonthGrid, Batch 5, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the first consumer's account pages their parts, in the consumer's order of need, which is the spec's build order: `DescriptionList` and `DescriptionListItem`, a static `dl` whose terms sit beside their values from 30rem of its own width and above them under it, with a row's actions, empty values, long values and numeric values; `CardActions`, buttons in a plain card's header, clear of its corner; `Gauge`, a static meter drawn as a ring or a semicircle on any range, with a centre numeral and a word under it, up to five marks, tones the app chooses and an arc whose length, caps included, is exactly the value; and `MonthGrid`, a static grid of months, one row per year, each month one of three looks for the app's own states, with a sentence and a hidden table. Every part's CSS ships in `@snapshot-ui/core` (`description-list.css`, `gauge.css`, `month-grid.css`, imported by `styles.css` after `breadcrumbs.css`, and a block added to `card.css`), every part has its own docs page or section, the `description-list` page carries the Accounts recipe, the docs site's header moves to PageHeader, and the batch ships as one release: `@snapshot-ui/core` and `@snapshot-ui/react` 0.8.0. `@snapshot-ui/charts` goes to 0.1.5 by a patch changeset, since its `@snapshot-ui/core` peer (`workspace:^`) publishes as `^0.8.0`.

**Architecture:**

- **Static parts, all four.** `DescriptionList`, `DescriptionListItem`, `CardActions`, `Gauge` and `MonthGrid` import nothing from React Aria, hold no state and render in a server component with no client JavaScript; `Gauge` and `MonthGrid` use `useId` and nothing else (spec 4, 12).
- **Layout by the part's own width.** The list and the month grid are size containers; the list switches layout at 30rem of its own box and the month grid shows quarter labels under 28rem of its own, so the server's HTML is right at every width and nothing is measured (spec 5.3, 8.3).
- **A gauge is a meter bent round.** Meter's role, naming chain, track, ink and `--meter-surface`; ProgressBar's prop names and 200ms motion; the geometry is pure arithmetic in `gauge/geometry.ts`, the same on the server and in the browser (spec 7).
- **Words carry the state.** A gauge's tone has `valueLabel` and `figureCaption`; a month's state has a shape, the summary and a hidden table; an empty value has words. Color only repeats (spec 4; owner ruling 2: both low score bands are warning, told apart by word and marks).
- **Calendars and strings are the app's.** No part computes a date or formats a number; every figure, year, month name, state word and sentence is the app's string, the month grid's English summary aside, which the app replaces in any other language (spec 8.3, owner ruling 10).
- Every task is one reviewable deliverable in the spec's build order, and a last task for the docs header, the recipe, the guides, the charts peer and the batch's baseline list.

- No new dependency, in any package, the docs app included: the docs' Persian month grid example holds its data already in Persian months, and the page shows the app's conversion with `@internationalized/date` as code, which the docs app does not import (Task 4).

- **Versions.** Core and react stay a fixed group (`.changeset/config.json:5`); the batch's minor changesets take them from 0.7.x to 0.8.0. ### React components

- Every source file that imports `react-aria-components` starts with `'use client';` (`packages/react/scripts/check-use-client.js`), and so does every `.tsx` under `src` that uses state, an effect, a ref callback with state, or a context. **This batch adds no client module.** The static modules, added to `STATIC_MODULES` in `packages/react/test/server-components.test.tsx` (`:344`) and to its `STATIC` rows: `description-list/DescriptionList.tsx`, `gauge/Gauge.tsx`, `month-grid/MonthGrid.tsx`; `card/Card.tsx` is listed already and gains `CardActions`. Pure `.ts` modules carry no directive: `gauge/geometry.ts`, `month-grid/summary.ts`. The last describe of that file fails on any `.tsx` that is neither a client module nor listed.
- **No Lucide in these parts.** lucide-react's `Icon` is a client module, so a static part draws its few marks by hand (StatTile's rule) or draws none. None of the four draws an icon; the recipe's icons are in client example files.
- **Names are the library's only where the library writes them:** "Not set" (`emptyValue`), MonthGrid's `labels.year` ("Year") and `labels.outside` ("Not in range") and its English summary. Every other word is the app's.
- `className` and `ref` go on the element each task names; `className` merges after the library's class through `cx`. Presence checks on rendered slots use `present()` (`utils/present.ts`), which also defines an empty value (null, undefined, a boolean, an empty string).
- **Server safety** (the consumer's rules): no `Intl` formatting and no `toLocaleString`, no `window`, `document` or `matchMedia` at render or import, no measurement for the first paint. Every number a part writes into its HTML is written with at most three decimals by one shared rounding (`Math.round(n * 1000) / 1000`, Meter's), so the server and the browser write the same string.
- Every id the library writes comes from `useId`.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` **after `breadcrumbs.css`**, in this order: `description-list.css`, `gauge.css`, `month-grid.css`. Each batch appends its files after the last; the spec's "after `card.css`" and "after `meter.css`" (spec 15) name what each file reads from, not where it is imported, and the existing import-order tests in `css.test.js` keep their blocks. CardActions is a block appended to `card.css`.
- **Tokens only.** Stylelint's `snapshot-ui/token-only` (`packages/core/stylelint/token-only.js`) forbids a literal color, a literal radius (a radius is `0`, a `var(--radius-*)` or a `calc()` whose every `var()` falls back to a token, `:142-150`) and any `box-shadow` that is not `none` or a `var()`. The month cell's corner is `calc(var(--radius-micro) * 2 / 3)`: 4px in Rounded and Soft, 0 in Square, the value spec 8.5 gives as `min(var(--radius-micro), 0.25rem)`, written as a calc on the token so the rule reads it. Class names are kebab-case; `description-list`, `card-actions` (already CollapsibleCard's), `gauge` and `month-grid` are used by nothing else in `apps/docs` or `packages` (spec 14.1 item 25; Task 1's Step 0 searches again).
- **System colors** only inside `@media (forced-colors: active)` (`css.test.js`), and every file has a forced-colors block. This plan writes them in lowercase (`canvas`, `canvastext`, `graytext`, `highlight`).
- **States** are data attributes: the list's `[data-layout]`, `[data-dividers]`, `[data-empty]` and `[data-numeric]`; the gauge's `[data-size]`, `[data-form]`, `[data-tone]` and `[data-over]`; a month's `[data-look]` and a header label's `[data-quarter]`. No part here has hover, focus or press of its own.
- **Motion.** Only the gauge moves: its arc over 200ms when its value changes, and `gauge.css` carries the reduced-motion block the shared test asks for (`css.test.js`).
- **Logical properties** throughout. What mirrors: the list's columns, the gauge's svg (by `--gauge-flip` from `:where([dir='ltr' i])` and `:where([dir='rtl' i])`, the charts' pattern, since `:dir()` is above the floor), the month grid's columns. What does not: a numeric value (`direction: ltr`, `unicode-bidi: isolate`, `text-align: match-parent` written also as `-webkit-match-parent`, `copy.css`'s rule), the gauge's figure and text, the month hatch's angle.
- **Container queries**, widths and not tokens: the list at `30rem` (`container: description-list / inline-size`), the month grid at `28rem` (`container: month-grid / inline-size`), the plain card's header at `24rem` (`container: card-header / inline-size`, Task 2). Both size containers declare `contain-intrinsic-inline-size: 20rem` (spec 11, risk R1), StatTile's 0.6.1 fix.

### Design rules

- **Theme axes:** light and dark, the three shapes, compact density. The list's row follows density through `--size-field`; nothing else here changes with density, so only stories that hold a card or a table take the `density` tag.
- **Typography:** weights 400, 450, 500 and 700 only. A term 500 and a value 450; a gauge's figure 500 and its caption, label and value text 500, 450 and 450; a month label 450 and a year label 500; the summary 450.
- **Reserved colors.** Signal orange, clay, success and gain appear nowhere. Warning is a gauge's `warning` tone and its over-limit arc, and in the recipe the Fair and Poor score bands, a utilization above 30% and a duplicate Badge. Error is a gauge's `error` tone only where a limit stopped something, and in the recipe a bank feed that failed (an error Badge); never a score band (owner ruling 2). Taupe appears nowhere: an empty value is slate. Slate is the terms, empty values, a gauge's caption and value text, month labels and the summary. State is never color alone: a tone has words and, on a score, marks; a month look is a shape.
- **The concentric rule** (design record, "Nested radii, derived"): a surface in a holder's corner takes the holder's radius less the gap; a control keeps its shape and moves out, down where a column stands above it. Here: the list's first and last rows with actions in a card (Task 1), CardActions in a card's header (Task 2), the month cells as text-sized parts sharper than the formula (Task 4). The gauge is a circle, which the rule leaves alone. The audit runs on every new story in three shapes.
- **Contrast records**, light then dark. Gated already: ink and slate as text on canvas, lifted, float and raised; the boundary against canvas and lifted (3.06 and 6.20, 3.36 and 5.59). Measured and recorded, not gated (Task 3): the gauge's arc against its track, on lifted ink 13.85 and 12.27, warning 4.76 and 6.28, error 5.61 and 4.04; on the canvas ink 12.72 and 14.17, warning 4.37 and 7.26, error 5.15 and 4.67; on float, measured in Task 3; the track against its surface 1.29 and 1.42 on lifted and 1.28 and 1.36 on the canvas, a cue. Each task's `contrast.test.js` describe cites the gated pairs and recomputes, to two decimals, every value its Appendix B record states.

### Standing lessons from batch 4

Each was learned the hard way in batch 4 and holds for every task here.

1. **The concentric corner rule** (design record, "Nested radii, derived"; batch 4's commits 3080858, d48f170 and d57b1fc). A surface in a holder's corner takes `calc(var(--holder-radius) - var(--holder-border) - var(--holder-pad))` on every corner; a control keeps its shape and stops at `--holder-corner-inset`, moving down where a column stands above or below it. Story code places an app's controls with `CLEAR_OF_FOOT` and surfaces with `HOLDER_CORNER` (`src/stories/corner.ts`), and so do the docs examples. The audit (`apps/storybook/tests/concentric`) runs every story in three shapes and fails a control left in a curve; the docs audit (`apps/docs/tests/concentric.spec.ts`) does the same for every docs page, the docs header included after Task 5.
2. **Focus never falls to the body** (batch 4's corrections 54, 102, 103, 111 and 113). When the focused element leaves, focus goes to a named place: the next control, the trigger, a heading with `tabIndex={-1}`, or `<main>`. These parts hold no focus of their own, but the recipe does: a Dialog's close returns focus to Edit, a removed account returns the reader to the list with focus on its heading, and a tab switch keeps focus on the tab. Task 5's end-to-end tests read `document.activeElement` after each and fail on `body`.
3. **Plays that hold on CI.** CI runs four story projects side by side: `storybook`, `storybook-dark`, `storybook-webkit` and `storybook-firefox` (`apps/storybook/vitest.config.ts`). WebKit and Firefox do not run on the implementer's machine; each task pushes and reads the draft pull request's results before it is done (owner action 1). A story test gets 60 seconds on CI and 15 locally (`apps/storybook/vitest.config.ts:12`, batch 4's correction 123). A play draws the least that proves its point; a play whose story is about what follows focus focuses with `focusOn(element)` (`src/stories/focus.ts`), which polls until focus holds, since Firefox can let an early focus go unheard; every check that follows a resize, a key or a transition waits with `waitFor` (five seconds where a busy runner is slow); every pixel comparison allows 1px for an engine's rounding (`expectSameEdge` and `expectInside` in `rtl/RightToLeft.stories.tsx:107-117`, correction 126); a play that resizes or scrolls puts it back in `finally`.
4. **`'use client'` boundaries.** A part with no state imports no React Aria and no Lucide and carries no directive, so a server component renders it with no client code; `server-components.test.tsx` proves it per module. An example file that passes a handler is a client file.
5. **The server's HTML is what hydration finds.** Each part joins `server-render.test.tsx` (its markup), `server-face.test.tsx` where it has a face before scripts, and `hydration.test.tsx` (`:465`): rendered on the server and hydrated under `en-US`, `de-DE` and `fa-IR` in UTC and Asia/Tehran, with React's `onRecoverableError` failing the test. No part here reads the locale, so the three must write the same HTML.
6. **Sizes, both ways** (batch 4's corrections 108, 112 and 127). Each entry is measured without React Aria, Lucide and `@internationalized/date`, which sets its limit by the rule (the measured size rounded up to the next 0.5 kB, plus 0.5 kB), and once with React Aria not ignored; the commit's verification records both. For these four parts the two must be equal, since none imports React Aria; a difference is a stray import and is fixed, not recorded.
7. **No em or en dashes**, and the public-names rule, as above; both are checked by every task's `pnpm verify` (`check:public`) and Task 5's dash search.

## Review Focus

The input classes the spec implies that a part's ordinary tests would not exercise, most likely first. Each is pinned by a test in the task named.

1. **The list's layout by its own width.** Side by side from 30rem of the list's box and stacked under it, whatever the viewport: a list in a 24rem frame on a 1280px screen stacks, and every list on a 375px phone stacks, since no box there reaches 30rem; `layout` holds either at every width; the term column lines up on every row with and without actions. Pinned in Task 1 (`SwitchesAtItsWidth`, three engines).
2. **Empty means empty, and only that.** `undefined`, `null`, `false`, `true` and `''` show "Not set" in slate; `0` and `'0'` are values. Pinned in Task 1.
3. **Controls out of a card's corner, and nothing else moved.** The list's last row with actions at a card's foot, its first row at a card's head with no header, and CardActions in a card's header stand at least the corner inset from the card's edge in Rounded, comfortable and compact; Soft and Square do not move; CollapsibleCard's header and its baselines do not change. Pinned in Tasks 1 and 2 by measuring plays and the concentric audit.
4. **The arc is exactly the value, on any range.** A share of 0 draws nothing; a share under the stroke's width draws a dot; 0.5 draws half the track, caps included; 1 closes a ring at the top and covers a semicircle's track; a value below `minValue` or above `maxValue` clamps; 742 on 300 to 850 draws 80.4%; in three engines. Pinned in Task 3 (`geometry.test.ts`, `ArcLength`).
5. **Tones are the app's, except over the limit.** `neutral` above `maxValue` draws warning; `error` stays error over the limit; nothing turns success; the recipe's Fair and Poor are both warning and differ by their caption and their place between the marks (owner ruling 2). Pinned in Tasks 3 and 5.
6. **Right to left.** The list's term column on the right with numeric values still left to right and starting at the line's start; the gauge's ring counter-clockwise and semicircle from the right, its figure and text unmirrored; the month grid's first month on the right. Pinned in each task's `RightToLeft` story and `Mirrored` play.
7. **The month grid says the same three ways.** The visible looks, the summary and the hidden table agree for runs, gaps, several years, outside months and a grid with nothing missing; the table has a caption and row and column headers; the visible grid and legend are hidden from assistive technology; the three looks stay three shapes in forced colors. Pinned in Task 4.
8. **Server faces with no hydration warning, and no client code.** All four parts in the server-components suite with no client module, and in the hydration suite under three locales and two time zones. Pinned in each task.
9. **Focus in the recipe.** Edit's Dialog returns focus to Edit; Remove returns to the list with focus on its heading; never the body. Pinned in Task 5's end-to-end run.
10. **The docs header as PageHeader.** One `h1` per page, the color mode and corner switches working, the sticky offset kept, no sideways scroll at 320px, the docs corner audit passing on every page. Pinned in Task 5.

**Behavior:**

1. **Markup, in DOM order.** `dl.description-list` (the rest props, `className` merged after, `ref`) with `data-layout` (`auto`, `horizontal` or `stacked`) and `data-dividers` while `hasDividers` (default true), holding the app's children as given. `DescriptionListItem` is `div.description-list-item` (rest props, `className`, `ref`) holding `dt.description-list-term` with `term`, then `dd.description-list-value`, then, when `present(actions)`, `dd.description-list-actions` with `actions`.
2. **Empty.** When `!present(children)`, the value `dd` carries `data-empty` and holds `emptyValue` (default `'Not set'`). `0` and `'0'` are values. An empty value with `isNumeric` drops `data-numeric`, since "Not set" is words.
3. **Numeric.** `isNumeric` writes `data-numeric` on the value `dd`; the stylesheet does the rest.
4. **No role, no hooks.** No ARIA role is written on any element; neither part uses a hook, a context or an id. `DescriptionListItem` outside a `DescriptionList` renders the same markup; axe's `dlitem` rule then fails, which the docs say.
5. **Static.** No directive, no state; both render under React's server build.

**The geometry**, `gauge/geometry.ts`, written as here, since the cap compensation and the mark angles are where two builds would differ and one would be wrong:

```ts
export type GaugeSize = 'sm' | 'md' | 'lg';
export type GaugeForm = 'ring' | 'semicircle';

/** The box and the stroke of each size, in pixels: one user unit is one pixel at the gauge's own size. */
export const GAUGE_SIZES: Readonly<Record<GaugeSize, { readonly box: number; readonly stroke: number }>> = {
  sm: { box: 32, stroke: 4 },
  md: { box: 96, stroke: 8 },
  lg: { box: 160, stroke: 12 },
};

/** At most three decimals, Meter's rounding, so the server and the browser write the same string. */
const num = (n: number): string => String(Math.round(n * 1000) / 1000);

export interface GaugeTrack {
  viewBox: string;
  d: string;
  /** The path's length in user units. */
  length: number;
  stroke: number;
}

/** The track's path: a ring from the top, clockwise, in two half arcs; a semicircle from the inline start over the top. */
export function gaugeTrack(size: GaugeSize, form: GaugeForm): GaugeTrack {
  const { box, stroke } = GAUGE_SIZES[size];
  const r = (box - stroke) / 2;
  const c = box / 2;
  if (form === 'ring') {
    const top = `${num(c)} ${num(stroke / 2)}`;
    const bottom = `${num(c)} ${num(box - stroke / 2)}`;
    return {
      viewBox: `0 0 ${num(box)} ${num(box)}`,
      d: `M${top}A${num(r)} ${num(r)} 0 1 1 ${bottom}A${num(r)} ${num(r)} 0 1 1 ${top}`,
      length: 2 * Math.PI * r,
      stroke,
    };
  }
  return {
    viewBox: `0 0 ${num(box)} ${num(box / 2 + stroke / 2)}`,
    d: `M${num(stroke / 2)} ${num(c)}A${num(r)} ${num(r)} 0 0 1 ${num(box - stroke / 2)} ${num(c)}`,
    length: Math.PI * r,
    stroke,
  };
}

/** The value's share of the range, clamped to 0 and 1; 0 for a range with no width or a value that is not a number. */
export function gaugeShare(value: number, min: number, max: number): number {
  if (!(max > min) || !Number.isFinite(value)) return 0;
  return Math.min(1, Math.max(0, (value - min) / (max - min)));
}

/**
 * The dash that draws a share with round caps, caps included: a dash of the share's length less one stroke,
 * starting half a stroke in, so each cap adds back half a stroke. Under one stroke's length it is a zero-length
 * dash, a dot; a share of 0 is null and draws nothing.
 */
export function gaugeDash(share: number, track: GaugeTrack): { dasharray: string; dashoffset: string } | null {
  if (share <= 0) return null;
  const dash = Math.max(0, share * track.length - track.stroke);
  return { dasharray: `${num(dash)} ${num(track.length)}`, dashoffset: num(-track.stroke / 2) };
}

/** A mark's radial line across the track, 2px past it on both sides, at its share of the arc. */
export function gaugeMark(share: number, size: GaugeSize, form: GaugeForm): { x1: string; y1: string; x2: string; y2: string } {
  const { box, stroke } = GAUGE_SIZES[size];
  const r = (box - stroke) / 2;
  const c = box / 2;
  const inner = r - stroke / 2 - 2;
  const outer = r + stroke / 2 + 2;
  // A ring turns clockwise from the top; a semicircle from the inline start (180 degrees) over the top (90) to the end (0).
  const angle = form === 'ring' ? share * 2 * Math.PI : Math.PI * (1 - share);
  const point = (radius: number): [number, number] =>
    form === 'ring'
      ? [c + radius * Math.sin(angle), c - radius * Math.cos(angle)]
      : [c + radius * Math.cos(angle), c - radius * Math.sin(angle)];
  const [x1, y1] = point(inner);
  const [x2, y2] = point(outer);
  return { x1: num(x1), y1: num(y1), x2: num(x2), y2: num(y2) };
}
```

**The summary**, `month-grid/summary.ts`, written as here, since its grouping and its empty cases are where builds would differ:

```ts
import type { MonthGridState, MonthGridYear } from './MonthGrid';

/**
 * The English default (spec 8.3): for each state whose look is not filled, in the order of `states`, its label,
 * a colon, and its months grouped by year in the order the years are drawn, each year's months joined by commas
 * with the year once at the end, years joined by semicolons; each state a sentence. With nothing but filled or
 * outside months, the first filled state's label and "every month"; with no filled state either, nothing.
 */
export function monthGridSummary(
  states: readonly MonthGridState[],
  years: readonly MonthGridYear[],
  monthNames: readonly string[],
): string {
  const sentences: string[] = [];
  for (const state of states) {
    if (state.look === 'filled') continue;
    const parts: string[] = [];
    for (const year of years) {
      const names = year.months.flatMap((id, index) =>
        id === state.id && monthNames[index] !== undefined ? [monthNames[index]] : [],
      );
      if (names.length > 0) parts.push(`${names.join(', ')} ${year.label}`);
    }
    if (parts.length > 0) sentences.push(`${state.label}: ${parts.join('; ')}.`);
  }
  if (sentences.length > 0) return sentences.join(' ');
  const filledIds = new Set(states.filter((state) => state.look === 'filled').map((state) => state.id));
  const filled = states.find((state) => state.look === 'filled');
  const anyFilled = years.some((year) => year.months.some((id) => id !== null && filledIds.has(id)));
  return filled !== undefined && anyFilled ? `${filled.label}: every month.` : '';
}
```
