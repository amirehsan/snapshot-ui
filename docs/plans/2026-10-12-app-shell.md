# App Shell, Sidebar, BottomTabBar and Compact Density, Batch 1, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the library's first consumer the frame its app runs in, in build order: the compact density axis (`data-density="compact"`, four size tokens, a generator refinement for touch screens, and the controls and the card reading them), the shell tokens (`--spacing-inset`, `--container-sidebar` with a generated `sidebar` axis, `--z-header`, `--z-chrome`); then `AppShell` with `useAppShell()`, the `Sidebar` and its parts (`SidebarGroup`, `SidebarItem`, `SidebarBrand`, `SidebarSearch`, `SidebarTrigger`, `useSidebar()`), `BottomTabBar` with `BottomTabBarItem`, and a docs page on routing. Each part is a client component on react-aria-components 1.22.1, exported from `@snapshot-ui/react`, drawn by CSS in `@snapshot-ui/core`, documented on its own page, and released by its own changeset in the batch 1 minor.

**Architecture:**
- **One density axis, not sizes.** `data-density="compact"` on any element remaps `--size-control`, `--size-field` and `--spacing-card` for its subtree, generated exactly as `data-shape` remaps the radii, with a `compact-coarse` refinement that writes the compact values again under `@media (pointer: coarse)`. `--size-target` is the 40px floor every hit area is extended to and never changes. Components never know which density is active: Button, IconButton, SegmentedControl, the input and Card read the tokens where they had literals, and comfortable renders byte for byte as 0.1.0 does, which the existing baselines prove.
- **AppShell owns layout state.** The collapsed state and the drawer state live on `AppShell` (controlled or uncontrolled through a private `useControllableState`), because the workspace offset depends on the first and the header's menu button on the second. The root carries `data-sidebar="collapsed"` while collapsed and never `"expanded"`, so a server can paint the right width from a prop or a pre-paint script can set the attribute on `<html>`, and the generated `sidebar` axis turns the attribute into a width. `Sidebar` reads the state through context and renders the permanent rail at every width, and, when the drawer is open, a second copy of its slots inside the overlays plan's `Drawer`, which supplies every modal behavior.
- **Links go through `RouterProvider`.** Every link-bearing part is React Aria's `Link`: `href` is a real attribute that works with scripts off, one `RouterProvider` at the app's root routes every press, and the inherited `render` prop is the per-item escape hatch. There is no `linkComponent` prop.
- **A docked tab bar.** `BottomTabBar` is flush with the bottom edge with the safe area padded inside it, hidden from 1024px up by CSS alone, and `AppShell` reserves room under the page for it through one custom property a future save bar will add to.
- Every task is one reviewable deliverable. The tokens and the generator are one task, the density change to the shipped components and the Storybook mode another, then one task per component, then the routing page.

## Global Constraints

### Runtime and packaging

- Node `>=24.5`, `"packageManager": "pnpm@10.10.0"`, every package `"type": "module"`, ESM only.
- React and React DOM are peers at `^19.0.0`. `react-aria-components` and `lucide-react` are dependencies of `@snapshot-ui/react`, and `@snapshot-ui/core` is an optional peer of it. No task adds a dependency. `react-aria` and `react-stately` are never imported directly: everything comes from `react-aria-components`, which re-exports `Link`, `Button`, `RouterProvider`, `VisuallyHidden`, `I18nProvider`, `useLocale`, `composeRenderProps`, `DialogTrigger`, `SheetTrigger`, `TooltipTrigger` and the types `LinkProps`, `LinkRenderProps`, `ButtonProps`, `ButtonRenderProps`.
- `packages/react` builds with tsdown in `unbundle` mode under `tsconfig.build.json`, which turns on `isolatedDeclarations`: every exported function, constant and hook declares its full type explicitly.
- `tsconfig.base.json` has `types: []`, so `process` is not typed in `packages/react/src`. A development warning never reads `process.env`; it is a `console.warn` guarded by a ref, once per mount.

### React components

- Every source file that imports `react-aria-components` starts with `'use client';`. A `.tsx` under `src` that uses a hook or a context carries it too. Static modules import no React Aria and carry no directive; `packages/react/test/server-components.test.tsx` lists every static module, so a new `.tsx` in `src` is either a client module or listed there. Nothing in this plan is static.
- Use React Aria 1.22's current compositions, named in each task. Never `NavigationTree` (spec 4): a sidebar of links is `nav > ul > li > a` in tab order.
- `className` and `ref` go on the element each task names. `className` takes a string, or React Aria's render function where the element is a React Aria one, and merges after the library's classes through `composeRenderProps` and `cx` from `packages/react/src/utils/cx.ts`.
- Presence checks on rendered slots use `present()` from `packages/react/src/utils/present.ts`, never `!= null`. A slot given `false`, `null`, `undefined`, `true` or `''` renders nothing and sets no `data-has-*` attribute.
- Server safety (spec 6.2, 7.2, 8.2 and the consumer's rules): no `Intl` formatting during render, no `window`, `document`, `matchMedia` or measurement at render or at import, no first-paint measurement, preformatted strings accepted wherever a value is shown (a count, a shortcut). `matchMedia`, `popstate` and the current item's reveal are effects. Every client part joins `packages/react/test/server-render.test.tsx`, where it renders in Node with no window.
- `jsx-a11y/no-autofocus` is on in the strict config and flags `autoFocus` on components as well as elements. The one place this plan needs it (the current `SidebarItem` inside the drawer copy, Task 4) carries `// eslint-disable-next-line jsx-a11y/no-autofocus -- initial focus inside a modal is the dialog pattern: the drawer opens on the page shown`. Nowhere else.
- Every id the library writes comes from `useId`, because the Sidebar's slots render twice while the drawer is open. The drawer copy receives the rail's `className` and nothing else of its attributes, so an `id` an app puts on `Sidebar` is never duplicated.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` in this order after the overlays' files (the last of which is `tooltip.css`; on the overlays branch today it is `menu.css`, and Toast, CommandPalette and Tooltip add theirs after it): `app-shell.css`, `sidebar.css`, `tab-bar.css`. It uses only tokens: Stylelint's `snapshot-ui/token-only` rule forbids a literal color, radius or shadow, and `light-dark()`. Lengths such as `40px`, `0.75rem`, `4rem` and `calc(100vw - 2rem)` are allowed. Class names are kebab-case and never start with a Tailwind namespace (the list in `packages/core/stylelint.config.js`: `text-`, `bg-`, `p-`, `w-`, `h-`, `size-`, `inset-`, `z-`, `gap-`, `grid-`, `flex-` and the rest). `app-shell-`, `sidebar-` and `tab-bar-` are safe prefixes.
- **Non-token colors:** CSS system colors are the only ones allowed, and only inside `@media (forced-colors: active)`. A core test fails any other use; it matches whole words in any case, so `canvas` is written lowercase only inside a forced-colors block, and `var(--color-canvas)` is fine anywhere.
- **State selectors.** States are data attributes with React Aria's names, and each also matches its native twin where one exists (`:focus-visible`, `:hover`, `:active`). `aria-current="page"` is matched beside React Aria's `[data-current]`. Hover rules sit inside `@media (hover: hover)`, and never on the current item. A press shows the hover look, because touch has no hover.
- **The focus ring** is `outline: var(--focus-ring-width) solid var(--focus-ring-color); outline-offset: var(--focus-ring-offset);`, outside the part. On an ink fill it inverts to `var(--color-canvas)` and goes inside: `outline-offset: calc(-1 * (var(--focus-ring-width) + var(--focus-ring-offset)))`, the segmented control's rule. The rail's items keep the outset ring on the current item too (spec 7.3, "Focus"): nothing in a static group clips it.
- **Cursor:** `pointer` on every interactive control.
- **Motion:** every `transition` is turned off under `@media (prefers-reduced-motion: reduce)`, in a block that comes after the rules it overrides. Nothing animates its shape.
- **Text a person writes** wraps (`overflow-wrap: anywhere`, `min-width: 0` on flex and grid children): a rail label wraps onto a second line rather than truncate (spec 3). A tab bar label is the one exception, one line with an ellipsis as a last resort, because its accessible name always holds the full label.
- **The z ladder (spec 6.3):** `--z-header` 20 for a sticky page header, `--z-chrome` 30 for fixed chrome (the rail, its collapse button, the tab bar), both under `--z-modal` 1000 and `--z-toast` 1100, with React Aria's positioned overlays at the inline 100000. A core test fails any `z-index` in `src/components` that is not `var(--z-*)`, a `calc()` on one, or the keyword `auto`, which the overlays' `.overlay-scrim.sheet-scrim` variant writes to reset its scrim's layer ("Needs a ruling", 1); nothing in core writes a bare number.
- **Breakpoints:** `1024px` is `--breakpoint-md`, written out in `app-shell.css`, `sidebar.css` and `tab-bar.css` because a media query cannot read a custom property, and tied to the token by a test as `heading.css` is. The tab bar's `4rem` is written in `tab-bar.css` and in `app-shell.css`'s bottom reserve, and tied by a test.
- **Forced colors and right to left:** ink-filled current items become `Highlight` with `HighlightText`; dots become `CanvasText` (and `Highlight` when current); outlines and edges survive on their own. Logical properties throughout, except the tab bar's two inline paddings, which are physical because `env(safe-area-inset-left)` and `-right` are. `:dir()` is above the browser floor and is never used; where a physical side is needed the component resolves direction from `useLocale()`, and the chevron is mirrored under `[dir='rtl']`.

### Design rules

- **Theme axes:** `data-theme="light" | "dark"`, `data-shape="rounded" | "soft" | "square"`, `data-density="compact" | "comfortable"` and `data-sidebar="collapsed" | "expanded"`, on any element, matched case-insensitively except theme. An overlay copies theme, shape and density from the nearest scoped ancestor of its origin (the overlays plan's `useOverlayScope`): the trigger for a positioned overlay such as a tooltip, and what held focus when a modal opened, which `ModalFrame` records before the content's `autoFocus` runs; `data-sidebar` is read by CSS on any ancestor of the rail. `AppShell` writes `collapsed` only, never `expanded`.
- **Typography:** weights 400, 450, 500 and 700 only. 14px is the minimum for sentences, and 12px for short uppercase labels and key chips. Group labels are `--text-overline` (14px uppercase), items and the brand `--text-action`, tab labels and counts `--text-small`.
- **Touch targets:** every one is at least `--size-target` (40px): rail items, the brand, the search pill, the collapse button (drawn at 32px, hit at 40 through a pseudo-element), tab items (56px). Compact controls are 36px with a mouse and extend their hit area to 40 through a pseudo-element; on a coarse pointer they are 44px. Comfortable controls do not change on touch.
- **Reserved colors:** signal orange is for consent only; light signal orange is the attention cue (the current group's dot); clay is for the Changed chip only; error means invalid or failed; success means success; taupe is for placeholders and disabled text only; warning and gain mean what the overlays plan says. The current item is ink with canvas text; the hover is the 5% ink wash. State is never color alone: the current item also carries `aria-current="page"`.
- **Surfaces:** the rail is `--color-float` with `--color-hairline`, `--radius-stadium` and `--shadow-lift`; the tab bar is `--color-float` with a hairline top edge, no radius and no shadow; the search pill is `--color-canvas` with a hairline; the collapse button is float with `--color-frame` and `--shadow-lift`.
- **Contrast records.** A new text-on-ground or edge-on-ground pair goes into `CONTRAST_PAIRS` in `packages/core/scripts/contrast.js` with a test in `packages/core/test/contrast.test.js`; pairs the gate already holds are cited in the component's Appendix B section, not added. **Code** (the generator, because the refinement must be validated in the preprocessor, where the token's path is known, and emitted in the format in a fixed place; everything not shown is unchanged):

```js
// build-tokens.js: AXES gains two axes and the refinements feature.
export const AXES = {
  theme: {
    attr: 'data-theme',
    base: 'light',
    caseInsensitive: false,
    colorScheme: true,
    media: { dark: '(prefers-color-scheme: dark)' },
    variants: ['dark'],
  },
  shape: { attr: 'data-shape', base: 'rounded', caseInsensitive: true, variants: ['soft', 'square'] },
  density: {
    attr: 'data-density',
    base: 'comfortable',
    caseInsensitive: true,
    variants: ['compact'],
    // A refinement writes one variant's values again under a media query: compact on a touch screen.
    // A token gives it a value only beside a value for the variant it refines.
    refinements: { 'compact-coarse': { of: 'compact', media: '(pointer: coarse)' } },
  },
  sidebar: { attr: 'data-sidebar', base: 'expanded', caseInsensitive: true, variants: ['collapsed'] },
};

// In the preprocessor, where `variants` is the token's $extensions["snapshot-ui"][axis] object:
const def = AXES[axis];
for (const [variant, value] of Object.entries(variants)) {
  const refinement = def.refinements?.[variant];
  if (!def.variants.includes(variant) && !refinement) {
    throw new Error(`Unknown ${axis} variant "${variant}" on ${path.join('.')}`);
  }
  if (refinement && !Object.hasOwn(variants, refinement.of)) {
    throw new Error(
      `Token ${path.join('.')} has a ${axis} ${variant} value but no ${refinement.of} value. ` +
        'A refinement changes a value under a media query, so the variant it refines must set one.',
    );
  }
  // ... the existing reference check and the copy into the mode tree, unchanged
}

// In the snapshot-ui/css-layered format, replacing the `for (const [axis, variants] of Object.entries(modes))` loop:
for (const [axis, def] of Object.entries(AXES)) {
  const variants = modes[axis];
  if (!variants) continue;
  const changed = new Set(Object.values(variants).flatMap((v) => v.map((d) => d.name)));
  const followLines = followers(base, changed, byPath).map((t) => decl(t.name, cssValue(t, byPath)));
  const scope = (variant, decls) => {
    const lines = [...decls.map((d) => decl(d.name, d.value)), ...followLines];
    if (def.colorScheme) lines.unshift(`color-scheme: ${variant};`, 'color: var(--color-ink);');
    return lines;
  };
  for (const variant of def.variants) {
    const decls = variants[variant];
    if (!decls) continue;
    out.push(block(attrSelector(def, variant), scope(variant, decls), 1));
    if (def.media?.[variant]) {
      out.push(
        [`  @media ${def.media[variant]} {`, block(`:root:not(${attrSelector(def, def.base)})`, scope(variant, decls), 2), '  }'].join('\n'),
      );
    }
  }
  for (const [name, refinement] of Object.entries(def.refinements ?? {})) {
    const decls = variants[name];
    if (!decls) continue;
    out.push([`  @media ${refinement.media} {`, block(attrSelector(def, refinement.of), scope(name, decls), 2), '  }'].join('\n'));
  }
  const baseLines = [
    ...base.filter((t) => changed.has(t.name)).map((t) => decl(t.name, cssValue(t, byPath))),
    ...followLines,
  ];
  if (def.colorScheme) baseLines.unshift(`color-scheme: ${def.base};`, 'color: var(--color-ink);');
  out.push(block(attrSelector(def, def.base), baseLines, 1));
}
```

```ts
const THEME_SHAPES = [
  { theme: 'light', shape: 'rounded' },
  { theme: 'dark', shape: 'rounded' },
  { theme: 'light', shape: 'soft' },
  { theme: 'light', shape: 'square' },
] as const;

interface Mode {
  theme: 'light' | 'dark';
  shape: 'rounded' | 'soft' | 'square';
  density: 'comfortable' | 'compact';
  width: 1280 | 375;
}

/**
 * The modes a story is shot in, from its tags. Untagged: the four theme and shape modes at 1280 and light
 * Rounded at 375. `viewport-phone`: the four at 375 and nothing at 1280; `viewport-desktop`: the four at 1280
 * and nothing at 375. `density` adds light Rounded compact at the story's width, with the `-compact` suffix.
 */
function modesOf(id: string, tags: readonly string[] = []): Mode[] {
  const phone = tags.includes('viewport-phone');
  const desktop = tags.includes('viewport-desktop');
  if (phone && desktop) throw new Error(`${id} is tagged viewport-phone and viewport-desktop; pick one`);
  const width = phone ? 375 : 1280;
  const modes: Mode[] = THEME_SHAPES.map((mode) => ({ ...mode, density: 'comfortable', width }));
  if (!phone && !desktop) modes.push({ theme: 'light', shape: 'rounded', density: 'comfortable', width: 375 });
  if (tags.includes('density')) modes.push({ theme: 'light', shape: 'rounded', density: 'compact', width });
  return modes;
}

const suffixOf = ({ width, density }: Mode): string =>
  `${width === 1280 ? '' : `-${width}`}${density === 'compact' ? '-compact' : ''}`;

for (const story of stories) {
  for (const mode of modesOf(story.id, story.tags)) {
    const { theme, shape, density, width } = mode;
    test(`${story.id} [${theme}/${shape}${suffixOf(mode)}]`, async ({ page }) => {
      await page.setViewportSize({ width, height: 720 });
      await page.goto(
        `/iframe.html?id=${story.id}&viewMode=story&globals=theme:${theme};shape:${shape};density:${density}`,
      );
      await ready(page);
      await page.evaluate(() => document.fonts.ready);
      await expect(page.locator('html')).toHaveAttribute('data-theme', theme);
      await expect(page.locator('html')).toHaveAttribute('data-shape', shape);
      await expect(page.locator('html')).toHaveAttribute('data-density', density);
      await expect(page).toHaveScreenshot(`${story.id}--${theme}-${shape}${suffixOf(mode)}.png`, { fullPage: true });
    });
  }
}
```

**Code** (`useControllableState` and the shell's close effects, because the setter must not move a controlled value, must not call `onChange` for no change, and must not write a ref during render, and the listeners must be effects):

```ts
// useControllableState.ts
import { useCallback, useState } from 'react';

export function useControllableState<T>(
  value: T | undefined,
  defaultValue: T,
  onChange?: (value: T) => void,
): [value: T, setValue: (next: T) => void] {
  const [own, setOwn] = useState(defaultValue);
  const isControlled = value !== undefined;
  const current = isControlled ? value : own;
  // Rebuilt when the value or the callback changes, so it never reads a ref written during render.
  const setValue = useCallback(
    (next: T) => {
      if (Object.is(next, current)) return;
      if (!isControlled) setOwn(next);
      onChange?.(next);
    },
    [current, isControlled, onChange],
  );
  return [current, setValue];
}
```

1. **Markup.** The rail root is `div.sidebar` with no landmark role, `className` merged after `sidebar`, `ref` and the other `HTMLAttributes` on it, and an `id` from `useId` for `aria-controls`. The label is a paragraph and not a heading (spec 7.2).
2. **Items.** A `SidebarItem` is React Aria's `Link` with its `href`, press, hover and focus states, `aria-current="page"` only when `isCurrent` (React Aria would treat `"false"` as current), and `data-current` from React Aria while it is set. Inside: `span.sidebar-item-icon[aria-hidden="true"]` with the icon, `span.sidebar-item-label` with the label, and, with a count, `span.sidebar-item-count` holding a visually hidden `, `, `span.sidebar-item-count-number` with the number, and a visually hidden ` ` plus `countLabel`, so the name is exactly "Transactions, 12 to review" and the words are not visible. Enter follows the link; Space does nothing. Tab walks the brand, the collapse button, the search action, every item in DOM order, then the footer. No roving focus, no arrow keys. Pressing an item in the drawer copy calls the caller's `onPress` and then `closeDrawer()`, which also covers pressing the page already open.
3. **Groups** are static; `isCurrent` on the group lights its dot light signal orange and turns its label ink. The library does not inspect children.
4. **Collapse.** The collapse button is React Aria's `Button` with `aria-expanded={!isCollapsed}`, `aria-controls` pointing at the rail root's id, a visually hidden label that is `collapseLabel` while expanded and `expandLabel` while collapsed, and Lucide's `ChevronLeft` at 16px, `rotate: 180deg` when collapsed. Enter and Space toggle it through `setSidebarCollapsed`. It is inside the rail copy only, so below 1024px it leaves with the rail, and the drawer has none.
5. **Collapsed**, from 1024px up, under `data-sidebar="collapsed"` on any ancestor of the rail: every label (brand name, search label, group text, item labels, the count's number) is clipped and stays in the accessibility tree, so no name changes; items become 40px squares holding the icon, centered in the 72px rail, every one still a tab stop; each item's count becomes an 8px dot at the icon's top-end corner, ink, and canvas on the current item, its number clipped inside it; `SidebarBrand`, `SidebarSearch`, every `SidebarItem` and the collapse button are wrapped in a `TooltipTrigger` whose `isDisabled` is `!isCollapsed`, so no tooltip exists while expanded or in the drawer; the tooltip (`placement="end"`) holds the label and, with a count, `span.sidebar-tooltip-count` on a second line with the count and its words; the search tooltip passes `shortcut`. The footer is centered and the app draws its account row icon-only through `useSidebar().isCollapsed`. A tooltip opened from a rail inside `data-density="compact"` carries `data-density="compact"` (the overlays plan's scope copy).
6. **The drawer.** Below 1024px the rail copy is `display: none`. `Sidebar` always renders `<Drawer placement="start" title={drawerLabel} isTitleHidden hasCloseButton={false} isOpen={isDrawerOpen} onOpenChange={(open) => { if (!open) closeDrawer(); }} className="sidebar-drawer-panel">` holding the second copy, `div.sidebar.sidebar-drawer` with the same slots and children under a context of `{ isCollapsed: false, inDrawer: true }`, so it ignores collapse whatever the attribute above says, including one on `<html>`. The Drawer renders nothing while closed (and on the server), supplies the scrim, focus containment, `aria-hidden` outside, the scroll lock, Escape, the scrim press, focus restore to the trigger (in the next animation frame), the slide and its reduced-motion rule, and copies the scope of what held focus when it opened, the trigger: `ModalFrame` records it in a layout effect before React Aria applies the current item's `autoFocus` in a passive effect, so focus landing inside never changes the scope. With these props it draws no header, only the visually hidden title, then `div.drawer-body`, whose keyboard-scroll ref never marks it a tab stop here, since the rail copy holds links and a button and the rail's own nav is the scroller. The current `SidebarItem` in the drawer copy carries `autoFocus`, so focus lands on it; with no current item the Drawer focuses its dialog. The head gets the close button at its end. `AppShell` closes the drawer on widening and `popstate` (Task 3).
7. **`SidebarTrigger`** is an outline `IconButton` with Lucide's `Menu`, `aria-label={label}`, `aria-haspopup="dialog"`, `aria-expanded={isDrawerOpen}`, calling the caller's `onPress` then `openDrawer()`, with the class `sidebar-trigger` merged before `className`. No `aria-controls`: the drawer is not in the DOM while closed. CSS hides it from 1024px up.
8. **Reveal on mount.** Each copy's rail runs an effect on mount: it finds `[aria-current="page"]` inside its nav; if the nav has a height (`clientHeight > 0`, which the hidden rail does not) and the item's bottom (`offsetTop + offsetHeight`) is below the nav's visible bottom (`scrollTop + clientHeight`), it sets `nav.scrollTop = Math.max(0, item.offsetTop - 40)`. `scrollTop` only, never `scrollIntoView`. Once per mount.
9. **Server.** The rail renders at every width; the Drawer renders nothing; no `window`, `matchMedia` or measurement runs during render.
10. **Right to left.** Every inset, margin and padding is logical. The chevron is mirrored with `scale: -1 1` under `[dir='rtl']`, after its rotation, so it points at the rail in both states. Tooltips take `placement="end"`. The Drawer resolves `start` from `useLocale()`, so an `I18nProvider` with a right-to-left locale puts it on the right, and a `dir="rtl"` wrapper alone does not.
11. **Density.** Items and the search pill are `max(var(--size-target), var(--size-control))` tall: 40px in comfortable and compact, 44 in compact on touch. Nothing in the rail shrinks.

```tsx
// Sidebar.tsx, the shape. Props not shown are destructured and defaulted as the types say.
const SidebarContext = createContext<SidebarState | null>(null);

function SidebarRail({ inDrawer, railId, ...slots }: RailProps): ReactElement {
  const { isSidebarCollapsed, setSidebarCollapsed, closeDrawer } = useAppShell();
  const nav = useRef<HTMLElement>(null);
  useEffect(() => {
    // Once, on mount: after that the reader chose the item and can see it. The hidden rail has no height.
    const list = nav.current;
    const current = list?.querySelector<HTMLElement>('[aria-current="page"]');
    if (!list || !current || list.clientHeight === 0) return;
    if (current.offsetTop + current.offsetHeight > list.scrollTop + list.clientHeight) {
      list.scrollTop = Math.max(0, current.offsetTop - 40);
    }
  }, []);
  const state: SidebarState = { isCollapsed: !inDrawer && isSidebarCollapsed, inDrawer };
  return (
    <SidebarContext value={state}>
      <div
        {...(inDrawer ? {} : slots.rest)}
        id={inDrawer ? undefined : railId}
        ref={inDrawer ? undefined : slots.ref}
        className={cx('sidebar', inDrawer && 'sidebar-drawer', slots.className)}
      >
        {/* head, collapse button (rail only), search, nav, footer as Behavior 1 says */}
      </div>
    </SidebarContext>
  );
}

export function Sidebar(props: SidebarProps): ReactElement {
  const { isDrawerOpen, closeDrawer } = useAppShell();
  const railId = useId();
  return (
    <>

        placement="start"
        title={drawerLabel}
        isTitleHidden
        hasCloseButton={false}
```

**Behavior:**
1. **Markup.** `nav.tab-bar[aria-label | aria-labelledby]` (`className` merged after `tab-bar`, `ref`, the other `HTMLAttributes` spread) > `ul.tab-bar-list` > one `li` per item > `a.tab-bar-item[href]` (React Aria's `Link`) or `button.tab-bar-item` (React Aria's `Button`) holding `span.tab-bar-item-icon[aria-hidden="true"]` with the icon and, with a count, `span.tab-bar-count` with the number; then `span.tab-bar-item-label` with the label; then, with a count, visually hidden words `, {count} {countLabel}` (`VisuallyHidden elementType="span"`), so the name is "Transactions, 12 to review" and the chip is decoration. No tab roles.
2. **Current.** A link item with `isCurrent` carries `aria-current="page"` (and React Aria's `data-current`); a button item with `isCurrent` carries `data-current-action=""` and never `aria-current`. Neither is set for `isCurrent={false}`.
3. **Links** follow `RouterProvider` and honour `render`. **A button item** inside a `SheetTrigger` (or `DialogTrigger`) opens it and carries `aria-haspopup` and `aria-expanded` from React Aria; given `onPress` it does what the app says. Enter follows a link or presses the button; Space presses a button only.
4. **Hidden at 1024px and up** by `display: none`, with no script, so it also leaves the accessibility tree there.
5. **Three to five items.** In an effect on mount and whenever the count changes, the bar warns once per mount through `console.warn` when `Children.count(children)` is outside 3 to 5 (`BottomTabBar holds N items; give it three to five.`); a ref keeps Strict Mode's double effect to one warning. It still renders. Effects do not run on the server, so the server logs nothing.
6. **Labels fit or ellipsize:** one line at `--text-small` with an ellipsis as a last resort; the accessible name always holds the full label.
7. **Safe areas** are padded inside the bar (`env(safe-area-inset-bottom)`, `-left`, `-right`), and the docs say `viewportFit: 'cover'` is needed for them to be non-zero on iOS.
8. **Server.** Pure CSS and links; nothing is measured. The bar renders in Node.

```tsx
// BottomTabBar.tsx
export function BottomTabBar({ children, className, ref, ...rest }: BottomTabBarProps): ReactElement {
  const count = Children.count(children);
  const warned = useRef(false);
  useEffect(() => {
    if (warned.current || (count >= 3 && count <= 5)) return;
    warned.current = true;
    console.warn(`BottomTabBar holds ${String(count)} items; give it three to five.`);
  }, [count]);
  return (
    <nav {...rest} ref={ref} className={cx('tab-bar', className)}>
      <ul className="tab-bar-list">{children}</ul>
    </nav>
  );
}

// BottomTabBarItem.tsx
export function BottomTabBarItem(props: BottomTabBarItemProps): ReactElement {
  const { icon, children, isCurrent, count, countLabel } = props;
  const content = (
    <>
      <span className="tab-bar-item-icon" aria-hidden="true">
        {icon}
        {count !== undefined ? <span className="tab-bar-count">{count}</span> : null}
      </span>
      <span className="tab-bar-item-label">{children}</span>
      {count !== undefined ? <VisuallyHidden elementType="span">, {count} {countLabel}</VisuallyHidden> : null}
    </>
  );
  if (props.href !== undefined) {
    const { icon: _i, children: _c, isCurrent: _cur, count: _n, countLabel: _l, className, href, ...link } = props;
    return (
      <li>
        <RACLink
          {...link}
          href={href}
          aria-current={isCurrent ? 'page' : undefined}
          className={composeRenderProps(className, (user) => cx('tab-bar-item', user))}
        >
          {content}
        </RACLink>
      </li>
    );
  }
  const { icon: _i, children: _c, isCurrent: _cur, count: _n, countLabel: _l, className, href: _h, ...button } = props;
  return (
    <li>
      <RACButton
        {...button}
        data-current-action={isCurrent ? '' : undefined}
        className={composeRenderProps(className, (user) => cx('tab-bar-item', user))}
      >
        {content}
      </RACButton>
    </li>
  );
}
```
