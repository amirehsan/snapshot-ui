# Home: Avatar, StatTile, Meter, Sparkline and LineChart, Batch 2, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the first consumer's Home page its figures, in the spec's build order: `Avatar`, `StatTile` and `Meter` in `@snapshot-ui/react`; then a new package, `@snapshot-ui/charts`, added end to end (build, tests, checks, size limits, Storybook, docs, changesets, the release workflow) with the chart foundations (`scale.ts`, `path.ts`) and `Sparkline`; then `LineChart` with its keyboard and pointer readout and its table view; then the guides that name the new package. Every part's CSS ships in `@snapshot-ui/core` (`avatar.css`, `stat-tile.css`, `meter.css`, `charts.css`, all imported by `styles.css`), every part has its own docs page, and the batch ships as one release: `@snapshot-ui/core` and `@snapshot-ui/react` 0.3.0, `@snapshot-ui/charts` 0.1.0.

**Architecture:**

- **Figures are strings.** Nothing in this batch formats a number or a date. A part that draws takes the number to place the mark and a string to say it (`value` and `valueLabel`), so the server's HTML is final in any locale, and there is no `Intl` anywhere.
- **Static where it can be.** `Meter`, `Sparkline` and a `StatTile` without `href` carry no `'use client'` and import no React Aria, so a server component renders them with no client JavaScript. A `StatTile` with `href` hands its content to a private client module, `StatTileLink`, which is React Aria's `Link`. `Avatar` is a client module for one piece of state, the failed image. `LineChart` is a client module, and its SVG, axis labels, legend and table still render on the server.
- **Draw without measuring.** Every chart SVG has `viewBox="0 0 100 100"` and `preserveAspectRatio="none"`, every stroke carries `vector-effect: non-scaling-stroke`, and anything that must keep its shape (a dot, a label, the readout) is HTML placed over the SVG by percentage with logical insets. The geometry is pure functions of the props. The only reads of layout are in event handlers (the plot's box on a pointer event) and never at render.
- **Direction from the `dir` attribute.** A static part cannot read React Aria's locale, so the drawing follows the nearest `dir` attribute, as the card's chevron does: `charts.css` sets `--chart-flip` to `1` under `[dir='ltr' i]` and `-1` under `[dir='rtl' i]` and mirrors each SVG by it, the HTML overlays mirror by their logical insets, and `LineChart`'s keys and pointer read the same attribute at event time. In a right-to-left page time flows right to left (ruling 3).
- **A new package for charts (ruling 1).** `@snapshot-ui/charts` depends on nothing at run time but React. It copies `cx` and the `AriaName` type rather than importing `@snapshot-ui/react`, so neither package depends on the other, and its CSS lives in core.
- Every task is one reviewable deliverable: one per part, with the new package's scaffold in the Sparkline task, before any chart is built on it, and a last docs task for the guides.

**Tech Stack:** unchanged from batch 1: pnpm 10.10, Turborepo 2.11, Node 24.5 or later, TypeScript 7 beside the TypeScript 6 API, Lightning CSS 1.33 with the browser floor Chrome 111, Safari 16.4 and Firefox 128, Stylelint 17, Tailwind CSS 4.3, React 19.3, react-aria-components 1.22.1, lucide-react 1.55, tsdown 0.23, Vitest 5 with jsdom 30, Testing Library, axe-core 4.14, Storybook 10.6 with the a11y and Vitest addons, Playwright 1.64, Next.js 16.4 on Fumadocs 16, Changesets 3.0 (`@changesets/assemble-release-plan` 7.0), publint 0.3, `@arethetypeswrong/cli` 0.18 and size-limit 14.

## Global Constraints

### Runtime and packaging

- Node `>=24.5`, `"packageManager": "pnpm@10.10.0"`, every package `"type": "module"`, ESM only.
- React and React DOM are peers at `^19.0.0` of both libraries. `@snapshot-ui/react` keeps its two dependencies, `react-aria-components` 1.22.1 and `lucide-react`, and gains none. `@snapshot-ui/charts` has no `dependencies` at all: React and React DOM are peers, `@snapshot-ui/core` an optional peer (`workspace:^`, as `@snapshot-ui/react` declares it, `packages/react/package.json`). It never imports `react-aria-components`, `lucide-react` or `@snapshot-ui/react`; `cx` and `AriaName` are copied into `packages/charts/src/utils/` (spec 8.1).
- Both packages build with tsdown in `unbundle` mode under `tsconfig.build.json`, which turns on `isolatedDeclarations`: every exported function and constant declares its full type, return types included.
- `tsconfig.base.json` has `types: []`, so `process` is not typed. A development warning is a `console.warn` guarded by a ref, once per mount, in an effect, in every build (the BottomTabBar's rule).
- **Versions.** Core and react stay a fixed group (`.changeset/config.json`), and the batch's minor takes them from 0.2.0 to 0.3.0. `@snapshot-ui/charts` is not in the fixed group: its `package.json` says `0.0.0`, and its minor changesets take it to `0.1.0` (spec 13). See spec correction 1.

### React components

- Every source file that imports `react-aria-components` starts with `'use client';`, and so does every `.tsx` under `src` that uses state, an effect, a ref callback with state, or a context. **`useId` is the one hook a static module may call**: React's server build exports it (`react.react-server.js` exports `use`, `useCallback`, `useDebugValue`, `useId` and `useMemo` and no other hook, read in `node_modules` at 19.3.0), so `Meter` takes its ids from `useId` and stays static. `packages/react/test/server-components.test.tsx`, and the new `packages/charts/test/server-components.test.tsx`, list every static module, so a new `.tsx` in `src` is either a client module or listed there.
- The static modules of this plan: `stat-tile/StatTile.tsx` and `meter/Meter.tsx` in the react package, and `sparkline/Sparkline.tsx` in the charts package. The client modules: `avatar/Avatar.tsx`, `stat-tile/StatTileLink.tsx`, `line-chart/LineChart.tsx`. Pure `.ts` modules (`scale.ts`, `path.ts`, `geometry.ts`) carry no directive and import no React.
- `className` and `ref` go on the element each task names; `className` merges after the library's class through `cx`. Presence checks on rendered slots use `present()` (`packages/react/src/utils/present.ts`), never `!= null`; a slot given `false`, `null`, `undefined`, `true` or `''` renders nothing.
- Server safety (the consumer's rules): no `Intl`, no `toLocaleString`, no `window`, `document` or `matchMedia` at render or import, no measurement for the first paint. Every figure on screen is a string from the app. Layout is read only inside event handlers (`getBoundingClientRect` on a pointer event) and direction only from the nearest `dir` attribute at event time.
- Every id the library writes comes from `useId`.
- `jsx-a11y` is in its strict config. The LineChart plot is a focusable `role="group"` with key and pointer handlers, which `jsx-a11y/no-noninteractive-tabindex` and `jsx-a11y/no-noninteractive-element-interactions` flag; that one element carries `// eslint-disable-next-line jsx-a11y/no-noninteractive-tabindex, jsx-a11y/no-noninteractive-element-interactions -- the chart is one tab stop that arrow keys move through (spec 9.2), the WAI-ARIA pattern for a composite with a roledescription`. Nowhere else.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` after `tab-bar.css`, in this order: `avatar.css`, `stat-tile.css`, `meter.css`, `charts.css`. One file draws both charts (spec 8.1).
- **Tokens only.** Stylelint's `snapshot-ui/token-only` forbids a literal color, a literal radius and any `box-shadow` that is not `none` or a `var()` (`packages/core/stylelint/token-only.js`, `isTokenShadow`). So every ring, spacer and edge in this batch is a `border` (on the element or on a pseudo-element), never an inset or spread shadow, as the BottomTabBar's chip already is (Appendix B, "BottomTabBar", "The chip"). Lengths such as `2px`, `0.5rem` and `6rem` are allowed. Class names are kebab-case and never start with a Tailwind namespace; `avatar-`, `stat-tile-`, `meter-`, `sparkline-` and `line-chart-` are safe.
- **System colors** only inside `@media (forced-colors: active)` (the shared `css.test.js` check); `canvas` lowercase there, as the other files write it.
- **States** are data attributes beside their native twins (`:is(:hover, [data-hovered])`, `:is(:active, [data-pressed])`, `:is(:focus-visible, [data-focus-visible])`). Hover rules sit inside `@media (hover: hover)`, and a press shows the hover look.
- **The focus ring** is `outline: var(--focus-ring-width) solid var(--focus-ring-color); outline-offset: var(--focus-ring-offset);`, outside the part.
- **No motion.** Nothing in this batch transitions or animates (spec 9.3, "Reduced motion"), so no file needs a reduced-motion block; the shared test asks for one only where something moves.
- **No z-index.** The chart's dots, crosshair and readout stack by DOM order inside the plot; the four files write no `z-index`.
- **Logical properties** throughout. `:dir()` is above the browser floor and is never used. Two rules in `charts.css` set the flip from the attribute, the card chevron's pattern (`card.css`, `--card-chevron-turn`): `:where([dir='ltr' i]) { --chart-flip: 1; }` and `:where([dir='rtl' i]) { --chart-flip: -1; }`, read as `var(--chart-flip, 1)`.
- **Surface custom properties.** `--meter-surface` and `--chart-surface` name the surface a part sits on, for the spacers and rings drawn in it. Each is read with a fallback, `var(--meter-surface, var(--color-lifted))`, and never declared by the part, so an app sets it once on any ancestor (a canvas section) and every part inside follows (spec correction 9).
- **A hidden view stays hidden.** An element that the `hidden` attribute toggles (the chart view and the table) never gets a `display` from component CSS without a `[hidden]` rule after it, because author CSS beats the user agent's `[hidden] { display: none }`.

### Design rules

- **Theme axes:** light and dark, the three shapes, compact density. Only the StatTile reads density (its padding is `--spacing-card`, 32px and 20px compact); nothing else in this batch has a density-dependent size.
- **Typography:** weights 400, 450, 500 and 700 only. 14px is the floor for sentences and 12px for short uppercase labels and initials (the Avatar's `sm`, at 700).
- **Reserved colors:** `gain` only for money that arrived and `warning` only for a state that needs a look (the change line's tones, the meter's over state); `error` and `success` never stand for up and down (ruling 4); signal orange, light signal orange and clay appear nowhere in this batch; taupe nowhere (no part here has a placeholder or a disabled state). State is never color alone: the change line carries the app's sentence, the meter's over state requires words in `valueLabel`, two series carry a legend and a readout that names each.
- **Surfaces:** the StatTile is the Card's surface (Lifted, the hairline, `--radius-stadium`, `--spacing-card`); the readout is a float panel (Float, the frame edge, `--radius-surface`, `--shadow-float`); the Avatar's fallback is Bone.
- **Contrast records.** Every text or graphic color this batch draws is ink, slate, gain or warning on a surface the gate already holds them on, so no task adds to `CONTRAST_PAIRS`. Each task's `contrast.test.js` describe cites the gated pairs and recomputes, to two decimals, every value Appendix B records; a mix (the 5% hover wash, the meter's track) is measured there and recorded, not gated, as the Tooltip's key chip is.
- **Strings:** the library writes three strings of its own, the LineChart's `labels` (`showTable`, `showChart`, `noScript`, spec correction 10), English by default and all replaceable. Everything else a reader sees is the app's.

## Review Focus

The input classes the spec implies that a part's ordinary tests would not exercise, most likely first. Each is pinned by a test in the task named.

1. **Right to left in three different ways.** The meter fills from the right because its track is a flex row and every offset is logical; a sparkline and a line chart mirror their SVG through `--chart-flip` from the nearest `dir` attribute, their HTML overlays mirror through logical insets, and the chart's Left and Right keys follow the drawn direction. The direction comes from a `dir` attribute, never from an `I18nProvider` alone, and the nearest one decides, so a `dir="ltr"` region inside a right-to-left page draws left to right. Pinned in Task 3 (the pace marker's `inset-inline-start` under `dir="rtl"`, the `RightToLeft` story), Task 4 (the end point at the inline end, the `RightToLeft` story) and Task 5 (the keys under a `dir="rtl"` ancestor and under a nested `dir="ltr"`, the `RightToLeft` story and its newest point at the left).
2. **Gaps.** A `null` point breaks the line into subpaths, an isolated point between two gaps is still drawn, the keys and the pointer skip positions where no series has a value, Page Up and Page Down land on data, the readout and the announcement omit a series with no value, and the table's cell is empty. Pinned in Task 4 (`linePath`, `areaPath`) and Task 5 (the geometry and component tests, the `Gaps` story).
3. **Scripts off.** The chart is a correct picture with no JavaScript, the table is shown under it, and with scripts on there is exactly one table in the DOM. Pinned in Task 5 (the server row counts two `<table` in the HTML, one in `<noscript>`; the jsdom test counts one; the docs test with JavaScript disabled).
4. **A linked tile's name is everything it shows.** The label, the value, the change and the caption, in that order and with spaces between them, so axe's `label-content-name-mismatch` passes; nothing focusable inside it. Pinned in Task 2 (the name test, the warning test, the docs axe loop).
5. **Over the limit.** The value is capped at `max`, both looks turn warning, segments past `max` are clipped, a zero-width segment draws no spacer, and the words are the app's. Pinned in Task 3.
6. **Static stays static.** `Meter`, `Sparkline` and an unlinked `StatTile` render under React's server build with no client directive, and an unlinked tile's HTML holds no React Aria attribute. Pinned in Tasks 2, 3 and 4 (`server-components.test.tsx` in each package).
7. **A new package's release.** The tarball has no `workspace:` range left, `changeset status` plans core and react at 0.3.0 and charts at 0.1.0, publint and attw pass, and the release workflow publishes it with no change. Pinned in Task 4 (the CI pack step, the status check) and the owner actions.

## Spec corrections

Mismatches found while reading the spec against the repository, the installed packages and the consumer's rules. Each is resolved in the task named; those marked **choice** are design decisions for the controller to see.

1. **Charts starts at 0.1.0 outside the fixed group** (spec 13; parent spec section 10). The parent spec says `charts` joins the fixed group of core and react when it ships, but the fixed group would release it at the group's version, 0.3.0, against spec 13's 0.1.0. The home spec is the newer and approved document, so charts stays out of `fixed` in `.changeset/config.json`, its `package.json` says `0.0.0`, and its minor changesets take it to `0.1.0` (`@changesets/assemble-release-plan` 7.0 increments `0.0.0` by `minor` to `0.1.0`). Its `@snapshot-ui/core` peer is `workspace:^`, which pnpm writes as `^0.3.0` in the tarball (verified with `pnpm pack` on the react package, which writes `^0.2.0` today), and assemble-release-plan 7.0 adds no bump to a dependent that is already releasing (`determineDependents`, `dist/index.mjs:78-118`). **Choice** (Task 4), and an open question for the owner.
2. **`MeterProps` uses `AccessibleName<'label'>`, not `AriaName`** (spec 7.1). `AriaName` requires an `aria-label` or an `aria-labelledby` even when a visible `label` names the meter, which spec 7.2 says it does. The repo's type for "a visible label, or an ARIA name" is `AccessibleName<'label'>` (`packages/react/src/utils/accessible-name.ts:28-29`), and the base omits `'aria-label' | 'aria-labelledby'` as every named part does (`bottom-tab-bar/BottomTabBar.tsx:17-20`). Task 3.
3. **The meter role sits on the bar, not on the root** (spec 7.2). `meter` has presentational children in WAI-ARIA 1.2, so a legend inside a `role="meter"` element would be lost to assistive technology. The root is a plain `div.meter`; `div.meter-bar` is the meter, named by the label or the `aria-label` and described by the pace. **Choice** (Task 3).
4. **A linked tile is named by all of its content, and its lines are blocks** (spec 6.2, 11). The spec names a linked tile by its label, value and change and puts the caption in `aria-describedby`. The docs run axe's `label-content-name-mismatch` (`apps/docs/tests/support.ts:46-62`, on by default in axe 4.14, which the packages' tests run), which fails a link whose name leaves out text it shows. So the link is named by its content, label, value, change and caption in order, with no `aria-describedby`; and each line is a block element (`p`, or the heading), never a `span`, because name computation puts a space between blocks and none between inline elements (Appendix B, "BottomTabBar", "The count and the name"), so the change line is `p.stat-tile-change`. Task 2.
5. **The StatTile's arrows are inline SVG, not lucide-react** (spec 6.2). `lucide-react` 1.55's `Icon` is a client module (`node_modules/lucide-react/dist/esm/Icon.mjs:2` is `"use client"`, `:14` imports `useLucideContext`), so a Lucide arrow would turn the unlinked tile into a client tree and throw under React's server build in `server-components.test.tsx`. The three glyphs are drawn inline with Lucide's own geometry: up `M12 19V5` and `m5 12 7-7 7 7`, down `M12 5v14` and `m19 12-7 7-7-7`, flat `M5 12h14`, 24 by 24, stroke 2, round caps and joins, `currentColor`. Task 2.
6. **A static tile and a linked tile are two modules** (spec 6.2). **Code** (the image state, because a ref callback that sets state on every render loops, and a state that is not keyed to `src` shows the last image's verdict for the next one):

```tsx
// Avatar.tsx
type ImageState = { src: string; status: 'loaded' | 'failed' } | null;

function initialsOf(name: string): string {
  return name
    .trim()
    .split(/\s+/)
    .filter(Boolean)
    .slice(0, 2)
    .map((word) => (Array.from(word)[0] ?? '').toUpperCase())
    .join('');
}

// Inside Avatar:
const [image, setImage] = useState<ImageState>(null);
const status = src !== undefined && image?.src === src ? image.status : 'loading';
// One function per src, and an update that returns the same object when nothing changed, so React bails out
// and a ref callback that runs again never renders again.
const settle = useCallback(
  (next: 'loaded' | 'failed') => {
    if (src === undefined) return;
    setImage((current) =>
      current?.src === src && current.status === next ? current : { src, status: next },
    );
  },
  [src],
);
const catchEarly = useCallback(
  (img: HTMLImageElement | null) => {
    if (img?.complete) settle(img.naturalWidth > 0 ? 'loaded' : 'failed');
  },
  [settle],
);
// <img className="avatar-image" src={src} alt="" ref={catchEarly} data-loaded={status === 'loaded' ? '' : undefined}
//   onLoad={() => settle('loaded')} onError={() => settle('failed')} />
```

**Behavior:**

1. **Markup, in DOM order.** The root is `div.stat-tile` without `href` and `a.stat-tile[href]` with it (`className` merged after `stat-tile`, `ref`, the other attributes spread on either), holding `div.stat-tile-body` > the label (`p.stat-tile-label`, or `h{level}.stat-tile-label` with `level`), then `p.copy.copy-numeral-sm.stat-tile-value` with `value`, then `div.stat-tile-trend` with `trend` while `present(trend)`, then `p.stat-tile-change[data-direction][data-tone]` while `change` is given, then `p.stat-tile-caption` while `present(caption)`. The grid places the trend at the inline end of the value's row; the DOM keeps it before the change, so a named trend is read after the value.
2. **The change line** holds `span.stat-tile-arrow[aria-hidden="true"]` with an inline 16px SVG (spec correction 5: up, down, or a dash for flat, never mirrored in right to left) and `span.stat-tile-change-label` with `change.label`. `data-tone` is `change.tone ?? 'neutral'`; `data-direction` is `change.direction`.
3. **Static without `href`.** `StatTile.tsx` carries no directive and imports nothing from React Aria; its HTML holds no `data-rac`, `data-hovered` or `data-focus-visible`.
4. **The tile as a link.** With `href`, `StatTile` renders `<StatTileLink {...rest} href={href} className={...} ref={ref}>{body}</StatTileLink>`, and `StatTileLink` renders React Aria's `Link` with those props, so a press routes through `RouterProvider` and a modified press falls through to the browser. Its accessible name is its content, the label, the value, the change and the caption in that order, with spaces between them; there is no `aria-describedby` (spec correction 4). React Aria drops `onClick` from a link's DOM props (`react-aria-components` 1.22.1, `dist/private/Link.mjs`, `delete DOMProps.onClick`).
5. **Nothing focusable inside a linked tile.** In an effect on mount, `StatTileLink` queries its own element for `a[href], button, input, select, textarea, [tabindex]:not([tabindex="-1"])` and, when it finds one, calls `console.warn('StatTile with href holds a focusable element; a link cannot hold a link or a button. Move it out of the tile.')` once per mount (a ref guards Strict Mode's second effect).
6. **The trend moves on a narrow tile.** The tile is a size container (`container: stat-tile / inline-size`), and under 18rem of content width the body is one column with the trend after the caption (spec correction 7). The tile therefore takes its width from its container and never from its content.
7. **A tile in a card steps down** to `--radius-surface` with the frame edge, by the Card's own rule (directly in a `.card`, or anywhere in a `.card-body`).
8. **Server.** Without `href` the tile renders under React's server build; with it, `StatTileLink` renders in Node with the link and no warning (effects do not run there).
9. **Forced colors and right to left** as the CSS says: the value stays left to right (the numeral's own rule), the trend sits at the inline end, the arrow is not mirrored.

```tsx
// StatTile.tsx: no directive.
import { StatTileLink } from './StatTileLink';

export function StatTile({
  label,
  value,
  change,
  caption,
  trend,
  href,
  level,
  className,
  ref,
  ...rest
}: StatTileProps): ReactElement {
  const Label = level === undefined ? 'p' : (`h${level}` as const);
  const body = (
    <div className="stat-tile-body">
      <Label className="stat-tile-label">{label}</Label>
      <p className="copy copy-numeral-sm stat-tile-value">{value}</p>
      {present(trend) ? <div className="stat-tile-trend">{trend}</div> : null}
      {change ? (
        <p
          className="stat-tile-change"
          data-direction={change.direction}
          data-tone={change.tone ?? 'neutral'}
        >
          <span className="stat-tile-arrow" aria-hidden="true">
            {ARROWS[change.direction]}
          </span>
          <span className="stat-tile-change-label">{change.label}</span>
        </p>
      ) : null}
      {present(caption) ? <p className="stat-tile-caption">{caption}</p> : null}
    </div>
  );
  if (href !== undefined)
    return (
      <StatTileLink {...rest} href={href} ref={ref} className={cx('stat-tile', className)}>
        {body}
      </StatTileLink>
    );
  // createElement, as Card does (card/Card.tsx:17-19): the root's ref is an HTMLElement ref, which a JSX div
  // does not take.
  return createElement('div', { ...rest, ref, className: cx('stat-tile', className) }, body);
}

// server-components.test.tsx, beside the react-server mock: a server bundler replaces a client module with a
// reference, and React Aria cannot be imported under React's server build.
vi.mock('../src/stat-tile/StatTileLink', () => ({ StatTileLink: () => null }));
```

`ARROWS` is a module constant of three `<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2" strokeLinecap="round" strokeLinejoin="round" focusable="false">` elements with the paths of spec correction 5. `StatTileLink` merges its own ref with the caller's through `useMemo(() => mergeRefs(own, ref), [ref])`, passes the result to `RACLink` (a callback ref, so the `HTMLElement` ref type the tile declares fits the anchor), and runs the warning of Behavior 5 in a `useEffect(() => ..., [])`.

```ts
export interface MeterSegment {
  /** In the meter's units, such as dollars. Segments stack in order from the start. */
  value: number;
  /** `fill` is solid ink, `hatched` is ink stripes: spent and held. */
  look: 'fill' | 'hatched';
  /** For the legend and the accessible value: "Spent", "Held". */
  label: string;
  /** Formatted: "$820.00". */
  valueLabel: string;
}

export type MeterBaseProps = Omit<
  HTMLAttributes<HTMLDivElement>,
  'children' | 'aria-label' | 'aria-labelledby'
> & {
  /** The visible label, such as "Groceries". When absent, `aria-label` or `aria-labelledby` names the meter. */
  label?: ReactNode;
  /** The limit, in the same units. */
  max: number;
  segments: MeterSegment[];
  /** The visible value text and the accessible value: "$1,020 of $1,200". Over the limit it must say so in words. */
  valueLabel: string;
  /** Where spending would be today if it kept pace, in the same units. */
  pace?: { value: number; label: string };
  /** Draws a legend under the bar for the segments and the pace. @default false */
  hasLegend?: boolean;
  ref?: Ref<HTMLDivElement>;
};

export type MeterProps = MeterBaseProps & AccessibleName<'label'>;

/** Static: no client directive. */
export function Meter(props: MeterProps): ReactElement;
```

**Behavior:**

1. **Markup, in DOM order.** `div.meter` (the root: `className` after `meter`, `ref`, the other attributes; `data-over=""` while the sum is over `max`) > `div.meter-head` > (`span.meter-label[id]` with `label` while `present(label)`) + `span.meter-value[aria-hidden="true"]` with `valueLabel`; then `div.meter-bar[role="meter"]` > `div.meter-track` > one `span.meter-segment[data-look]` per segment whose drawn width is over 0, then `span.meter-pace` while `pace` is given; then `span.meter-pace-label[id][hidden]` with `pace.label` while `pace` is given; then, with `hasLegend`, `ul.meter-legend` > one `li.meter-legend-item` per segment (`span.meter-swatch[data-look][aria-hidden="true"]`, `span.meter-legend-label`, `span.meter-legend-value`) and, with `pace`, one more (`span.meter-swatch[data-look="pace"][aria-hidden="true"]`, `span.meter-legend-label` with `pace.label`).
2. **Semantics on the bar** (spec correction 3): `aria-valuemin="0"`, `aria-valuemax={max}`, `aria-valuenow` the sum of the segments' values, each floored at 0, capped at `max` (and 0 when `max` is not over 0), `aria-valuetext={valueLabel}`. Named by `aria-labelledby` when it is given, else by `aria-label` when it is given, else by the label's `useId` id through `aria-labelledby`. With `pace`, `aria-describedby` is the hidden pace label's id, so a screen reader reads the app's sentence and never a percentage.
3. **Geometry** (Code below): each segment's width is its share of `max`, stacked from the inline start, as a percentage with at most three decimals in `style={{ inlineSize }}`; what passes `max` is clipped, and a segment left with no width is not drawn, so it draws no spacer. The pace marker is `style={{ insetInlineStart }}` at `pace.value / max` clamped to 0 to 100%. No measurement.
4. **Over the limit.** The sum over `max` sets `data-over`, which turns both looks warning; exactly `max` is not over. The words are the app's: the docs and the changeset say `valueLabel` must say "over".
5. **Static.** No state, no effects, no handlers; `useId` only.
6. **Right to left.** The track is a flex row and every offset is logical, so the bar fills from the inline start, the right; the pace marker mirrors with it; the hatch keeps its 45 degrees (a texture, not an arrow).
7. **Print and forced colors** as the CSS says (spec correction 17).

**Code** (the widths, because a clip that does not account for what came before draws past the track, and a zero width with a spacer draws a stray 2px line):

```ts
/** Each segment's drawn width, in percent of the track, stacked from the start and clipped at max. */
function widths(segments: readonly MeterSegment[], max: number): number[] {
  let used = 0;
  return segments.map(({ value }) => {
    const amount = Math.max(0, value);
    const drawn = max > 0 ? (Math.min(amount, Math.max(0, max - used)) / max) * 100 : 0;
    used += amount;
    return Math.round(drawn * 1000) / 1000;
  });
}
// The track draws a segment only where its width is over 0; the legend lists every segment.
```

```ts
// foundations/path.ts
const num = (n: number): string => String(Math.round(n * 1000) / 1000);

export function linePath(points: readonly (PlotPoint | null)[]): string {
  let d = '';
  points.forEach((point, i) => {
    if (!point) return;
    const before = points[i - 1];
    const after = points[i + 1];
    const xy = `${num(point.x)} ${num(point.y)}`;
    if (!before) d += after ? `M${xy}` : `M${xy}L${xy}`;
    else d += `L${xy}`;
  });
  return d;
}
```

```ts
'use client';

export interface LinePoint {
  /** The y value, to draw. */
  value: number;
  /** The y value, formatted, for the readout and the table: "$84.20". */
  valueLabel: string;
}

export interface LineSeries {
  /** "This month", "Last month". Required: it names the series in the legend, the readout and the table. */
  label: string;
  /** One point per x position, aligned with `xLabels`. `null` is a gap, such as a future day. */
  points: (LinePoint | null)[];
}

/** The strings the chart writes itself. Give all three, so no default in English is left on the page. */
export interface LineChartLabels {
  showTable: string;
  showChart: string;
  /** Shown with scripts off, above the table: "Scripts are off, so the chart's data is in the table below." */
  noScript: string;
}

export type LineChartProps = Omit<
  HTMLAttributes<HTMLElement>,
  'children' | 'aria-label' | 'aria-labelledby'
> &
  AriaName & {
    /** One or two series. The first is the story, drawn in ink; the second is context, drawn in slate. */
    series: [LineSeries] | [LineSeries, LineSeries];
    /** The x positions' labels, formatted: "Oct 1", "Oct 2". */
    xLabels: string[];
    /** Which x labels the axis shows, by index. @default first, middle and last */
    xTicks?: number[];
    /** The y gridlines and their labels, formatted. When absent the chart draws no y labels and relies on the readout and the table. */
    yTicks?: { value: number; label: string }[];
    /** The y domain. @default from zero to the nice ceiling of the data */
    yDomain?: [number, number];
    /** Fills under the first series. @default false */
    hasArea?: boolean;
    /** @default { showTable: 'Show as table', showChart: 'Show as chart', noScript: "Scripts are off, so the chart's data is in the table below." } */
    labels?: LineChartLabels;
    /** Height of the plot in px. @default 240 */
    height?: number;
    ref?: Ref<HTMLElement>;
```

**Behavior:**

1. **Markup, in DOM order.** `figure.line-chart` (`className` after `line-chart`, `ref`, the other attributes; `aria-label` or `aria-labelledby` as given; `data-view="chart"` or `"table"`) > `div.line-chart-chart` (`hidden` in the table view) holding: `ul.line-chart-legend` with two series only (`li.line-chart-legend-item[data-series="1"|"2"]` > `span.line-chart-key[aria-hidden="true"]` + `span.line-chart-legend-label`); `div.line-chart-plot` (Behavior 4; `data-has-y-labels` with `yTicks`; `data-active` while a position is active; `style={{ blockSize: height }}`) > `svg[viewBox="0 0 100 100"][preserveAspectRatio="none"][aria-hidden="true"][focusable="false"]` (`line.line-chart-grid` per `yTicks` value inside the domain, `line.line-chart-baseline` at the domain's minimum, `path.line-chart-area` with `hasArea`, then the second series' `path.line-chart-line[data-series="2"]` and the first's `[data-series="1"]` last, so ink draws on top) + `div.line-chart-overlay[aria-hidden="true"]` (`span.line-chart-y-label` per tick at `style={{ top }}`; while active, `span.line-chart-crosshair`, one `span.line-chart-dot[data-series]` per series with a point there, and, unless Escape hid it, `div.line-chart-readout[data-align]`) + `span.line-chart-live[aria-live="polite"][aria-atomic="true"]`; then `div.line-chart-x[aria-hidden="true"]` with one `span.line-chart-x-label` per tick (`data-edge="start"` on index 0, `"end"` on the last index). Then `table.line-chart-table` (`hidden` in the chart view), then `div.line-chart-toolbar` > `button.button.button-tertiary.line-chart-toggle[type="button"]`, then `noscript` (Behavior 10).
2. **Geometry.** x is `xPosition(i, xLabels.length)`; y is `linearScale(chartDomain(series, yDomain), [100, 0])`; a series' points past `xLabels.length` are ignored and missing ones are gaps; each line is `linePath` and the area is `areaPath` down to 100. The HTML marks sit at `style={{ insetInlineStart: 'x%', top: 'y%' }}` (three decimals at most). Nothing is measured to draw.
3. **Axis labels.** y labels at the inline start, above their gridline, only with `yTicks`; x labels at `xTicks ?? defaultTicks(n)`, under the plot, centred on their position and kept inside the plot at either end by `data-edge`. Both are the app's strings, in tabular figures, hidden from assistive technology (the readout and the table carry them).
4. **One tab stop.** The plot is `tabIndex={0}`, `role="group"`, `aria-roledescription="chart"`, named as the figure is. Focus activates the last position with data (unless the pointer already holds one). Keys, handled with `preventDefault`: Left and Right move to the previous or next position with data in the drawn direction (in right to left, Left is the next, newer, position and Right the previous); Home and End go to the first and the last; Page Up and Page Down move seven positions back or forward and land on the nearest position with data in that direction, or the end; Escape hides the readout until the next move. The direction is read at the key press from the nearest `dir` attribute, `event.currentTarget.closest('[dir]')`, as the CSS reads it. Blur ends the active position.
5. **The readout** is `div.line-chart-readout` placed over the active x at the plot's top, `data-align="start"` in the oldest quarter, `"end"` in the newest and `"center"` between, so it stays inside the plot with no measurement; it holds `p.line-chart-readout-x` (the x label) and `ul.line-chart-readout-list` with one `li` per series with a point there: `strong.line-chart-readout-value` (the value label) then `span.line-chart-readout-series` (the series' label).
6. **The announcement** (risk R2): after a key move or focus, once the active position has rested 150ms, the live region's text becomes `announcement(xLabels[i], series, i)`; a move inside the 150ms restarts the wait, so a held key announces only where it stops. A pointer move announces nothing. The timer is cleared on unmount and blur.
7. **Pointer.** A mouse or pen moving over the plot activates `nearestWithData` at the pointer's fraction of the plot's width from the oldest side (`(clientX - left) / width`, and one less that under right to left), read from `getBoundingClientRect` in the handler; leaving clears it unless the plot has focus. The hit area is therefore the whole column of each position (spec correction 18).
8. **Touch.** A touch press does the same and holds the position; a `pointerdown` anywhere outside the plot, listened for on `document` in an effect only while a touch holds, clears it.
9. **The table** (ruling 2): a caption with the chart's `aria-label` when it is named that way, or the figure's `aria-labelledby` on the table and no caption (spec correction 11); `thead` > `tr` > an empty `td`, then one `th[scope="col"]` per series label; `tbody` > one `tr` per x label > `th[scope="row"]` with the label, then one `td` per series with its value label, or empty for a gap. The toggle's text is `labels.showTable` in the chart view and `labels.showChart` in the table view; pressing it swaps the two `hidden` attributes and keeps focus on the toggle. Both views are in the server's HTML.
10. **Scripts off.** `noscript` holds `p.line-chart-noscript` with `labels.noScript` and a second copy of the table without `hidden`. With scripts on, a browser does not parse `noscript`'s content and React renders none of it on the client (checked in jsdom: a client render of `<noscript>` with children leaves it empty), so there is one table in the DOM; with scripts off the plot, the inert toggle and the shown table are what a reader gets, as spec 9.2 says.
11. **Server.** The SVG, the gridlines, the labels, the legend, the toggle, both tables and the empty live region render in Node from the props; no readout, crosshair or dot, since nothing is active.
12. **Right to left** (ruling 3): the x axis runs from the inline start, so the newest position is at the left under `dir="rtl"`; the SVG is mirrored by `--chart-flip`, the marks and labels by their logical insets, the x labels' and the readout's centring translations by `--chart-flip`; the figures inside the app's strings are the app's.
13. **No motion**: the readout appears and moves with no transition, so reduced motion needs nothing.

**Code** (the keys, because the drawn direction must come from the same attribute the CSS reads, and the announcement, because a timer per move must be cancelled by the next one):

```tsx
// LineChart.tsx, inside the component. `withData` is positionsWithData(series, xLabels.length).
const KEYS: Record<string, Move | ((rtl: boolean) => Move)> = {
  ArrowRight: (rtl) => (rtl ? 'previous' : 'next'),
  ArrowLeft: (rtl) => (rtl ? 'next' : 'previous'),
  Home: 'first',
  End: 'last',
  PageUp: 'page-back',
  PageDown: 'page-forward',
};

const onKeyDown = (event: KeyboardEvent<HTMLDivElement>): void => {
  if (event.key === 'Escape') {
    if (active !== null && !isReadoutHidden) {
      event.preventDefault();
      setReadoutHidden(true);
    }
    return;
  }
  const key = KEYS[event.key];
  if (key === undefined || active === null) return;
  event.preventDefault();
  const rtl = event.currentTarget.closest('[dir]')?.getAttribute('dir')?.toLowerCase() === 'rtl';
  const move = typeof key === 'function' ? key(rtl) : key;
  activate(moveFrom(withData, active, move), 'key');
};

// The rest of 150ms before a key or a focus is announced; a new move restarts it.
useEffect(() => {
  if (active === null || source !== 'key') return;
  const timer = window.setTimeout(() => {
    setAnnounced(announcement(xLabels[active] ?? '', series, active));
  }, 150);
  return () => {
    window.clearTimeout(timer);
  };
}, [active, source, series, xLabels]);
```

`activate(index, source)` sets the active position and its source (`'key'`, `'pointer'` or `'touch'`) and clears `isReadoutHidden`. The plot element carries the one lint exception of Global Constraints.
