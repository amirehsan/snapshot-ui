# Time: TimeField, TimeRangeField and DateTimePicker, Batch 9a, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start phase 3's last rows with the time family, one task each. First `TimeField`: React Aria's time field in the library's pill, ISO 'HH:mm' in and out, the minute step (1, 5, 10, 15, 20 or 30) on the arrow keys over React Aria's minute segment, a typed minute off the step kept and marked invalid, and a clock button opening a list of times at `listStep`. Then `TimeRangeField`: opening hours for one day as two TimeFields in a named group, closed as null and said in words, half a range held and never sent, an overnight range by `allowsOvernight`, two hidden inputs under `startName` and `endName`. Then a refactor with no visible change: DatePicker's body moves into an internal `PickerField`, so DatePicker draws byte-identical baselines and its tests pass unchanged. Then `DateTimePicker` on `PickerField` with minute granularity: a wall time 'YYYY-MM-DDTHH:mm' by default and a UTC instant with `timeZone`, DatePicker's year hold, the calendar and a TimeField in one popover that stays open after a day, `defaultTime`, and presets of moments. Every part's CSS ships in `@snapshot-ui/core` (`time-field.css`, `time-range-field.css`, `date-time-picker.css`, and `date-picker.css`'s focus rule widened by selector), every part has its own docs page, the `time-range-field` page carries the Opening hours recipe, and the batch ships as one release: `@snapshot-ui/core` and `@snapshot-ui/react` at the minor after batch 8's 0.11.0, which is 0.12.0 if nothing else releases between, with a patch to `@snapshot-ui/charts` whose core peer (`workspace:^`) publishes as a caret on the new core.

**Architecture:**

- **Client parts on React Aria, all three.** Each imports React Aria and starts with `'use client'`; each draws its server face from the same tree (spec 5's table): on the server and through hydration no segment is drawn and the app's `valueLabel` stands where the segments go, DatePicker's face (design record, "The server face"). Each joins `CLIENT`, `FACES` and `HYDRATED`.
- **Strings in and out.** `calendar/iso.ts` gains pure `parseIsoTime`, `toIsoTime`, `parseIsoDateTime` and `toIsoDateTime` beside `parseIso` and `toIso`; React Aria's `Time`, `CalendarDateTime` and `ZonedDateTime` never cross an API (spec 18 item 2).
- **The library writes the hidden inputs.** React Aria's time field writes `state.timeValue?.toString()`, 'HH:mm:ss' (`react-aria/dist/private/datepicker/useDateField.mjs:165`, read while writing this plan), so React Aria is given no `name`; the library writes `input[type="hidden"]` with 'HH:mm' and a `reset` listener on its form, TagInput's pattern (spec 7.3, spec 18 item 5).
- **The step over React Aria, not a fork.** A capture-phase `keydown` handler on the time field's frame acts only on the minute segment (`[data-type="minute"]`, `react-aria-components/dist/private/DateField.mjs:348`) and sets it through `TimeFieldStateContext`'s `setSegment('minute', n)` (`react-stately/dist/types/src/datepicker/useDateFieldState.d.ts:87`); every other key is React Aria's (spec 7.4, spec 18 item 3, risk R1).
- **Share, do not copy.** TimeRangeField is two TimeFields; DateTimePicker is DatePicker's body through `PickerField`; the time field's ring reuses `date-picker.css`'s rule by selector; the segments are `date-range-picker.css`'s `.date-segment`. DatePicker's and DateRangePicker's baselines must not move.
- **No size container.** TimeRangeField wraps with flex (spec 16, spec 18 item 7).
- Every task is one reviewable deliverable, in the order TimeField, TimeRangeField, PickerField, DateTimePicker, and a last task for the recipe, the guides, the changesets and the batch's baseline list (plan open question 1).

## Global Constraints

### Runtime and packaging

- Node `>=24.5`, `"packageManager": "pnpm@10.10.0"`, every package `"type": "module"`, ESM only.
- No new dependency, in any package, the docs app included. `@internationalized/date` is already a dependency of `@snapshot-ui/react` and does every date and zone conversion here.
- Both packages build with tsdown in `unbundle` mode under `tsconfig.build.json`, which turns on `isolatedDeclarations`: every exported function and constant declares its full type, return types included.
- `tsconfig.base.json` has `types: []`, so `process` is not typed. Development warnings go through `useWarnOnce` (`utils/useWarnOnce.ts`): a `value`, `defaultValue`, `minValue`, `maxValue`, `placeholderValue` or `defaultTime` that is not 'HH:mm' or 'HH:mm:ss'; a date-time that is not 'YYYY-MM-DDTHH:mm' (with ':ss', and with 'Z' under `timeZone`); a `step` not in 1, 5, 10, 15, 20 and 30; a `timeZone` `Intl` does not know (checked in an effect, never at render).
- **Versions.** Core and react stay a fixed group (`.changeset/config.json:5`); the batch's three minor changesets take them from 0.11.x to 0.12.0. A patch changeset (`charts-core-peer.md`, Task 5) moves `@snapshot-ui/charts`, whose core peer publishes as a caret on core's version, which a 0.x caret limits to one minor (spec 25). ### React components

- Every source file that imports `react-aria-components` starts with `'use client';` (`packages/react/scripts/check-use-client.js`), and so does every `.tsx` under `src` that uses state, an effect, a ref callback with state, or a context. **Client modules added:** `time-field/TimeField.tsx`, `time-field/TimeList.tsx`, `time-field/MinuteStep.tsx`, `time-range-field/TimeRangeField.tsx`, `calendar/PickerField.tsx`, `date-time-picker/DateTimePicker.tsx`. **Pure `.ts` modules, no directive:** `time-field/step.ts`, `time-field/times.ts`, `time-range-field/range.ts`, `date-time-picker/zone.ts`, and the additions to `calendar/iso.ts`. - **Names are the library's only where the library writes them:** `TimeFieldLabels` (two), `TimeRangeFieldLabels` (eight), `DateTimePickerLabels` (the calendar's and two), `changedLabel` ("Changed"). Every other word is the app's; a Persian page passes all of them. The list's times and the segments are written by `Intl` in the locale after hydration, never on the server.
- `className` and `ref` go on the element each task names; `className` merges after the library's class through `cx` or `composeRenderProps`; `style`, where a root takes one, goes on the same root as `className` (lesson 18). Presence checks on rendered slots use `present()` (`utils/present.ts`).
- **Server safety** (the consumer's rules): no `Intl` formatting and no `toLocaleString`, no `window`, `document` or `matchMedia` at render or import, no measurement for the first paint. - Every id the library writes comes from `useId`.
- **Focus moves outside React's commit** (batch 7's spec, its section 4): every focus move a part makes itself runs in a frame after the commit through `utils/focus-after-commit.ts`, never in a layout effect. Here React Aria moves focus back to the clock button and the calendar button when a popover closes, and the library moves none itself except Task 1 behavior 10's fallback.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` **after the last file batch 8 appends** (`position-pad.css`), in task order: `time-field.css`, `time-range-field.css`, `date-time-picker.css`. Each reads from `date-picker.css` and `date-range-picker.css`, which come earlier; each task's import-order test asserts both.
- **Tokens only.** Stylelint's `snapshot-ui/token-only` (`packages/core/stylelint/token-only.js`) forbids a literal color, a literal radius (a radius is `0`, a `var()`, a `calc()` whose every `var()` falls back to a token, or a `min()`, `max()` or `clamp()` of those) and any `box-shadow` that is not `none` or a `var()`. Write `max(0px, ...)`, never `max(1px, ...)`, in a radius. Lengths 9rem, 10rem, 14rem, 16rem and 18rem are literals in their files, as SidePanel's 24rem is (spec 18 item 36). Class names are kebab-case; `time-field`, `time-range-field` and `date-time-picker` are used by nothing else in `apps/docs` or `packages` (each task's Step 0 searches with `git grep`).
- **System colors** only inside `@media (forced-colors: active)` (`css.test.js`), and every file has a forced-colors block. Written in lowercase (`canvas`, `canvastext`, `graytext`, `highlight`, `highlighttext`).
- **States** are data attributes that also match the native pseudo-class: a segment's `:is(:focus-visible, [data-focus-visible])` (shared), a button's `:is(:hover, [data-hovered])`, `:is(:active, [data-pressed])` and `:is(:disabled, [data-disabled])`, a list row's `[data-selected]` and `[data-focus-visible]`; a field root's `[data-changed]`, `[data-unlabelled]`, `[data-invalid]`, `[data-disabled]` and `[data-readonly]`; TimeRangeField's `[data-closed]` and `[data-overnight]`.
- **Hover** only inside `@media (hover: hover)`, with its pressed twin outside it.
- **Motion.** None. The popovers' own entry is Popover's.
- **Logical properties** throughout. What mirrors: the button at the frame's inline end, the range's row, the "to" word's side. What does not: the segments' order, which React Aria takes from the locale and isolates; the arrow keys between segments follow the drawn order.
- **No size container** in this batch (spec 16). Should one ever be added, its intrinsic inline size is 0 (lesson 8).

```ts
// step.ts. Up: the next multiple strictly after the minute; down: the previous strictly before it; within the hour.
export function stepMinute(minute: number | null, step: MinuteStep, direction: 1 | -1, fromMinute: number): number {
  if (minute === null) return (Math.ceil(fromMinute / step) * step) % 60; // empty: the first on-step minute at or after the placeholder's
  if (direction === 1) return (Math.floor(minute / step) + 1) * step % 60;
  return minute % step === 0 ? (minute - step + 60) % 60 : Math.floor(minute / step) * step;
}
```

   Page Up, Page Down, Home, End and every key on another segment are React Aria's. A step of 1 attaches nothing.
4. **Off the step** (ruling 2). The part's `validate` (passed to React Aria, composed with the app's) returns `labels.offStep(String(step))` when the committed minute is not on the step, so the error shows when React Aria shows its own: on blur with `validationBehavior="aria"`, at submit with `"native"` (React Aria's default). Seconds are never checked against the step.

8. **The hidden input and reset** (spec 18 item 5; plan open question 4). React Aria gets no `name`; the part writes the hidden input and, in an effect, listens for its form's `reset` event and puts back the value of its first render (`defaultValue`, or the controlled value then), as TagInput does; the listener is removed on unmount and when `form` changes.
9. **Changed, invalid, required, disabled, read only** are the field contract's and React Aria's (spec 7.8): the chip or the unlabelled dot a part step before the button; invalid outranks changed; a disabled field takes its segments and button out of the tab order; read only keeps the segments focusable and disables the button.
10. **Focus never on the body.** React Aria returns focus to the clock button after the list. If the field becomes disabled while a segment holds focus (an app's pending save), the focus watch (`utils/focus-after-commit.ts`) sends focus in a frame after the commit to `<main>`, else the body's first focusable, the batch 7 fallback; a play checks it (lesson 16 says why nothing in the part disables itself).
