# Filters: NumberField, Calendar, RangeCalendar, DateRangePicker, FilterChip and FilterBar, Batch 3b, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the first consumer's Transactions page its filters, in the spec's build order: the server face that keeps `Intl`, the clock and the platform out of the server's HTML and the hydration pass, proved on `NumberField` with its money mode; `Calendar` and `RangeCalendar`, with presets, the Persian calendar and the app's `today`; `DateRangePicker` on React Aria's date segments and the range calendar; `FilterChip`, a pill that opens Select's shared list or a panel of free content; and `FilterBar`, the row, "More", the active count and the one Filters sheet on a phone. Every part's CSS ships in `@snapshot-ui/core` (`number-field.css`, `calendar.css`, `date-range-picker.css`, `filter-chip.css`, `filter-bar.css`, all imported by `styles.css` after `pagination.css`), every part has its own docs page, Select's list moves into a shared internal module with Select's behavior unchanged, and the batch ships as one release: `@snapshot-ui/core` and `@snapshot-ui/react` 0.5.0. `@snapshot-ui/charts` goes to 0.1.2 by a patch changeset, since its `@snapshot-ui/core` peer (`workspace:^`) publishes as `^0.5.0`.

**Architecture:**

- **The server face.** Every date and number part renders React Aria's component on the server and in the browser, so the label, the hint, the error line, the hidden form inputs and every id are in the server's HTML. While `useHydrated()` is false (on the server and through the hydration pass) each part leaves out, or replaces with an `Intl`-free string, whatever React Aria derives from `Intl`, the clock or the platform; from the first render after hydration React Aria's own text shows. The face is the same element tree, never a second component, so nothing remounts except an inline calendar, which holds no focus then (spec 4, ruling 1, 10.2 item 1).
- **Values a URL can hold.** A date is an ISO string, a range `{ start, end }` of two, an amount an integer count of minor units, a chip's value a `Key` or a `Key[]`. The wrappers convert at the edge with `@internationalized/date` and integer arithmetic; the app formats every string it shows (rulings 2, 4, 6).
- **One list, now four triggers.** Select's `SelectList` and `SelectPopover` move to `picker/SelectList.tsx`, internal, and FilterChip's list mode opens the same list, filter and hidden-pass guard. No new row CSS (`menu.css:2`).
- **One filter, two faces.** A `FilterChip` is a pill in the row and a labelled section in the "More" panel and the Filters sheet; `FilterBar` renders its children under a context that says which, and the app's value keeps the copies in step (spec 4).
- **Client where it must be.** Every part takes focus and keys, so each is a client module. FilterBar's active count is read from its children's props, so the server's HTML already holds it.
- Every task is one reviewable deliverable, one per part, in the spec's build order, and a last task for the guides and charts' core requirement.

**Tech Stack:** unchanged from batch 3a: pnpm 10.10, Turborepo 2.11, Node 24.5 or later, TypeScript 7 beside the TypeScript 6 API, Lightning CSS 1.33 with the browser floor Chrome 111, Safari 16.4 and Firefox 128, Stylelint 17, Tailwind CSS 4.3, React 19.3, react-aria-components 1.22.1 (on react-aria 3.53.1 and react-stately 3.51.0, with `@internationalized/date` 3.12.4 and `@internationalized/number` 3.6.9 under them), lucide-react 1.55, tsdown 0.23, Vitest 5 with jsdom 30, Testing Library, axe-core 4.14, Storybook 10.6 with the a11y and Vitest addons, Playwright 1.64, Next.js 16.4 on Fumadocs 16, Changesets 3.0, publint 0.3, `@arethetypeswrong/cli` 0.18 and size-limit 14. ## Global Constraints

- `@snapshot-ui/react` gains one dependency, `"@internationalized/date": "^3.12.4"`, React Aria's own range (react-aria-components 1.22.1 `package.json` `dependencies`), so pnpm keeps one copy and it adds no bytes (ruling 2); Task 2 adds it with `pnpm --filter @snapshot-ui/react add @internationalized/date@^3.12.4` and commits `pnpm-lock.yaml`. It never imports `@react-types/shared`, `react-aria`, `react-stately` or `@internationalized/number` directly: every React Aria type it needs comes from `react-aria-components`, which re-exports them (`dist/types/exports/index.d.ts:5,17,18,41,64,98-182`), and the date types (`CalendarDate`, `DateValue`'s Gregorian base, `CalendarIdentifier`, `Calendar` as `ICalendar`) come from `@internationalized/date`.
- Both packages build with tsdown in `unbundle` mode under `tsconfig.build.json`, which turns on `isolatedDeclarations`: every exported function and constant declares its full type, return types included.
- `tsconfig.base.json` has `types: []`, so `process` is not typed. A development warning is a `console.warn` guarded by a ref, once per mount, in an effect, in every build (`packages/react/src/bottom-tab-bar/BottomTabBar.tsx:50-54`). Task 1 lifts the pattern into `utils/useWarnOnce.ts` (`useWarnOnce(message: string | null): void`), which every part of this batch uses.
- **Versions.** Core and react stay a fixed group (`.changeset/config.json`), and the batch's five minor changesets take them from 0.4.0 to 0.5.0. A patch changeset (`charts-core-peer.md`, Task 6) takes `@snapshot-ui/charts` to 0.1.2, whose core peer publishes as `^0.5.0`; 0.1.1's `^0.4.0` does not admit 0.5.

### React components

- Every source file that imports `react-aria-components` starts with `'use client';`, and so does every `.tsx` under `src` that uses state, an effect, a ref callback with state, or a context. `packages/react/test/server-components.test.tsx` lists every static module (`STATIC_MODULES`), and its last describe fails on any `.tsx` that is neither a client module nor listed.
- No static module in this batch. The client modules: `number-field/NumberField.tsx`, `calendar/CalendarParts.tsx`, `calendar/Calendar.tsx`, `calendar/RangeCalendar.tsx`, `date-range-picker/DateRangePicker.tsx`, `picker/SelectList.tsx`, `filter-chip/FilterChip.tsx`, `filter-bar/FilterBar.tsx`. Pure `.ts` modules carry no directive and are imported only by client modules: `utils/useHydrated.ts`, `utils/useWarnOnce.ts`, `number-field/money.ts`, `calendar/iso.ts`, `filter-bar/walk.ts`.
- **Lucide only in client modules**, as 3a: `Minus`, `Plus`, `ChevronLeft`, `ChevronRight`, `ChevronDown`, `ArrowRight`, `CalendarDays`, `X` and `ListFilter`.
- **Value names.** Every part exposes `value`, `defaultValue` and `onChange` in the app's terms (a number of minor units, an ISO string, a range of two, a `Key` or a `Key[]`) and never React Aria's `CalendarDate` or `NaN`.
- **Names are the library's.** Every name React Aria would write in its own localized strings, and which a part shows or renders in the server pass, comes from the part's `labels`, English by default and every one replaceable (10.2 item 2): the sign button, the steppers, the month buttons, the presets' group, the calendar button, the two date fields, a chip's clear button, the filter, the empty line, "More", "Clear all", "Done", the section heads' clear word.
- `className` and `ref` go on the element each task names; `className` merges after the library's class through `cx` or `composeRenderProps`. Presence checks on rendered slots use `present()`, never `!= null`.
- **Server safety** (the consumer's rules): no `Intl` formatting and no `toLocaleString` in the library's own code, no `window`, `document` or `matchMedia` at render or import, no measurement for the first paint. React Aria may build a formatter, a collator or a list formatter inside a render, as 3a's risk R1 accepted, as long as nothing it formats reaches the server's HTML or the hydration pass (ruling 1); the server-face test pins that across three locales and two zones, and the hydration test across a mocked iPhone. `matchMedia` is read only in an event handler and always guarded (`typeof window.matchMedia === 'function'`), as `Select.tsx:233-238` does.
- **The face** is read from `useHydrated()` in `utils/useHydrated.ts`, moved out of `collapsible-card/useFolding.ts:9-14` in Task 1. It is `useSyncExternalStore(subscribeNothing, () => true, () => false)`: false on the server and through the hydration pass, true from the render after, and true from the first render of a part first rendered in the browser, such as one inside a popover or a sheet, which therefore never shows a face.
- Every id the library writes comes from `useId`.
- `jsx-a11y` is in its strict config. One element in this batch carries a disable, with its reason: FilterChip's pill, `// eslint-disable-next-line jsx-a11y/no-static-element-interactions -- the capture guard keeps a closed chip's letters and Left and Right from choosing silently; the trigger inside stays the tab stop (spec 8.2, R3)`. NumberField's guard sits on React Aria's `Group`, a component, which the rule does not read.

### CSS

- Component CSS lives in `packages/core/src/components/<name>.css`, inside `@layer components`, imported from `src/styles.css` after `pagination.css`, in this order: `number-field.css`, `calendar.css`, `date-range-picker.css`, `filter-chip.css`, `filter-bar.css`.
- **Tokens only.** Stylelint's `snapshot-ui/token-only` forbids a literal color, a literal radius and any `box-shadow` that is not `none` or a `var()` (`packages/core/stylelint/token-only.js`), so today's ring is a `border`, never an inset shadow. Class names are kebab-case and never start with a Tailwind namespace; `number-field-`, `calendar`, `range-calendar`, `date-range-`, `date-segment`, `filter-chip`, `filter-bar` and `filter-section` are safe, and none of them is used by the docs site (spec 10.2 item 13, checked with a search of `apps/docs` at 092d0f9).
- **System colors** only inside `@media (forced-colors: active)` (the shared `css.test.js` check).
- **States** are data attributes beside their native or ARIA twins: `:is(:hover, [data-hovered])`, `:is(:active, [data-pressed])`, `:is(:focus-visible, [data-focus-visible])`, `:is(:disabled, [data-disabled])`, `:is([data-selected], [aria-pressed='true'])` on a toggle, `:is(.calendar-day[data-selected], [aria-selected='true'] > .calendar-day)` on a day, whose ARIA twin is on its cell. Hover rules sit inside `@media (hover: hover)`, and a press shows the hover look.
- **The focus ring** is `outline: var(--focus-ring-width) solid var(--focus-ring-color); outline-offset: var(--focus-ring-offset);`, outside the part. On an ink fill (a pressed sign button, a chosen day, a pressed preset, an active chip's clear button) it is the canvas ring inside, SegmentedControl's rule (`segmented.css:178-184`). Days, whose cells touch, ring inside the cell (`outline-offset: calc(-1 * var(--focus-ring-width))`).
- **Specificity against `.input`**, as 3a: a part's override of an `.input` property is one class after `input.css`; a rule that must beat the hover edge but not the changed one is two classes with its extra test in `:where()`.
- **The unlabelled placeholder** is slate under `data-unlabelled` and never while disabled (`.x[data-unlabelled]:not([data-disabled])`, `search-field.css`, `combo-box.css`); disabled text is taupe.
- **Motion.** Only the chip's chevron moves (140ms), and `filter-chip.css` carries the reduced-motion block the shared test asks for (`css.test.js:193-197`).
- **Logical properties** throughout. The mirrors use the attribute, as the sidebar does (`sidebar.css:505-507`): the calendar's month chevrons and the range field's arrow. The number input is a figure, `direction: ltr`, so its logical paddings resolve left to right on every page and `number-field.css` swaps them under `[dir='rtl']` (spec correction 9).
- **The phone switch** is `@media (width < 768px)`, the `--breakpoint-sm` token written out as `copy.css:73` writes it, and the test compares it with the token (`css.test.js:413-416`).
- **No z-index.** The range band and the day's number stack by tree order; the popovers stack through the overlay layer they already use.

### Design rules

- **Theme axes:** light and dark, the three shapes, compact density. Everything here reads density through `--size-field` and `--size-control` (48 and 40px, 36 and 36px compact, 44 and 44px compact on a coarse pointer, `packages/core/dist/tokens.css:95-97,230-242`). `--radius-pill` is the shape's pill (999px Rounded, 12px Soft, 0 Square, `tokens.css:212,219,226`), so days, chips and presets keep the shape's pill.
- **Typography:** weights 400, 450, 500 and 700 only. The month heading, a chip's label at rest, a preset and the "More" button are 500; an active chip's label is 450 and its value 700; today's number is 700 and a day inside a range 500; labels, hints and errors follow the field parts' steps.
- **Reserved colors.** Clay only for the field parts' Changed chips (unsaved); light signal orange only for a changed field's edge, which `input.css` draws; error only for invalid, never for a negative amount, which is ink with its sign; success and gain nowhere; taupe only for placeholders and disabled text (an unavailable or out-of-bounds day is disabled text); slate for the placeholder only where no visible label names the field. Signal orange appears nowhere: neither a filter nor the Filters button is consent. State is never color alone: an active chip is filled and shows its value, today is a ring and a weight, chosen days are filled and `aria-selected`, unavailable days are struck through, a negative amount has its sign.
- **Surfaces:** the calendar sits on whatever holds it (canvas, a card, the float popover, the sheet's float); the lists are the Menu's float popover; a chip is transparent with the boundary edge, and active it is the ink fill.
- **Contrast records.** Every text or graphic color this batch draws on a token surface is already in `CONTRAST_PAIRS` (`packages/core/scripts/contrast.js:17-140`: ink and slate on every surface, canvas on ink, the boundary as a control edge and as a track on every surface), so no task adds to the gate (spec correction 31). Each task's `contrast.test.js` describe cites the gated pairs and recomputes, to two decimals, every value its Appendix B record states; a mix (a 5% or 10% wash, the 15% canvas wash on ink) or a pair under 3:1 that is a cue (the range band) is measured there and recorded, not gated.
- **Strings.** The library writes no date, no amount, no count in a locale and no list: the app passes `valueLabel`, `labels.summary`, `formatCount` and every preset's words. React Aria's announcements and its cell and segment descriptions are its own and follow `I18nProvider`, with no Persian (risk R5).

### The consumer's rules (its batch 3 request and "Rules every part must follow")

1. **Markup, in DOM order.** `RACNumberField.field.number-field` (`className` merged after `field number-field`; React Aria writes `data-disabled`, `data-readonly`, `data-required` and `data-invalid`, `NumberField.mjs:119-127`; the wrapper writes `data-changed` while `isChanged`, `data-unlabelled=""` without a visible label, `data-money` in money mode, `data-signed` with `allowsNegative`, `data-stepper` with `hasStepper`, `data-symbol="start"` or `"end"` with `money`, and the inline style `--number-field-symbol: calc(<length>ch + 0.5rem)` from `money.symbol.length`, a property of the string and not a measurement), with `aria-describedby` from `useChangedDescription` as TextField does. Inside: `FieldHead` while labelled; `Group.number-field-control` holding, in order, `ToggleButton.input-button.number-field-sign` with Lucide `Minus` while `allowsNegative`, `span.number-field-symbol[id]` while `money.symbolPosition` is `start`, the input (`input.input.number-field-input`, through `NumberFieldInput`, Code), the symbol while it is `end`, and `Button slot="decrement"` and `Button slot="increment"` as `.input-button.number-field-step` with Lucide `Minus` and `Plus` while `hasStepper`; then `Description` while `present(description)`, `FieldError`, and the money mode's own hidden input (Behavior 10). The symbol's id joins the input's `aria-describedby` after React Aria's, so "Amount, 1,234.50, $" is heard.
2. **The face** (ruling 1). While `useHydrated()` is false, `NumberFieldInput` sets the input's `value` to the face: in money mode `faceOfMinor(value, digits)` ("-1234.50", ASCII digits, no grouping, the hyphen-minus), for a plain number `String(value)`, and `''` for null. From the next render React Aria's formatted text shows. `inputMode` is set in both passes (Behavior 4), and React Aria's `aria-roledescription` is left out in both (spec correction 5). The sign button's pressed state, the steppers' disabled states and every id depend on the value only, so they are the same in every locale and zone.
3. **Money mode** (ruling 4). The wrapper sets React Aria's `formatOptions` to `{ style: 'decimal', minimumFractionDigits: d, maximumFractionDigits: d }` with `d = money.fractionDigits ?? 2`, a stable object per `d` (a module constant per digit count, so React Aria's `isEqualFormatOptions` never sees a new one), leaves `step` unset so a typed 12.50 is never snapped (React Aria snaps only to a given step, `useNumberFieldState.mjs:23-33`), passes React Aria `toUnits(value, d)` and `toUnits(minValue, d)` and `toUnits(maxValue, d)`, and calls `onChange(toMinor(n, d))`, `null` for React Aria's `NaN`. React Aria rounds the committed text to `d` places before it calls `onChange` (`numberParser.parse(format(clampedValue))`, `:97-98`), so `n * 10 ** d` is an integer up to float error and `Math.round` makes it exact. A `value` that is not a safe integer is rounded, with `useWarnOnce`.
4. **The decimal keyboard** (ruling 5). `inputMode` is `decimal` in money mode, and for a plain number `decimal` when its `formatOptions.maximumFractionDigits` (ECMA-402's default, 3 for decimal and unit and 0 for percent, read from props and never from `Intl`) is above 0, else `numeric`; set through the input context in both passes, so React Aria's platform choice (`useNumberField.mjs:131-145`) never reaches the DOM.
5. **Negatives** (ruling 5). Off unless `allowsNegative`, which leaves the lower bound to `minValue`; without it the lower bound is 0 when `minValue` is not given, and a `minValue` under 0 warns once. With it on, `ToggleButton.number-field-sign` (spec correction 7), named `labels.negative`, is pressed while React Aria's committed `numberValue` is under zero (from `NumberFieldStateContext`); a press negates it with `state.setNumberValue(-numberValue)`, or on an empty field puts a minus in the input with `state.setInputValue('-')` and focuses the input. A minus typed on a hardware keyboard works too, and the button follows it once the value commits. The input shows the sign as the locale writes it after hydration and the hyphen-minus in the face. A negative amount is ink: never error, never gain.
6. **Keys** (spec correction 6). React Aria's: Arrow Up and Arrow Down, and Page Up and Page Down with them, step by `step` (1 by default) and a money amount by one whole unit, snapping first (12.50 then Arrow Up is 13.00), and from an empty field start at the lower bound; Enter commits and formats. Home and End are the library's: `Group`'s `onKeyDownCapture` stops their propagation when the input is the target, before React Aria's spin button (`useSpinButton.mjs:85-98`) sets the minimum or the maximum, and the browser's default moves the caret (R3, Code). The spike in Step 1 proves it in three engines.
7. **The wheel** is off in money mode (`isWheelDisabled`), and React Aria's default for a plain number: on while the group has focus within (`useNumberField.mjs:104-126`), which needs the `Group`.
8. **Paste** (spec correction 8). `Group`'s `onPasteCapture`, in money mode, when the clipboard text contains `money.symbol` and the input's selection covers its whole text: `preventDefault`, `stopPropagation`, and `state.commit(text.replaceAll(symbol, '').trim())`. React Aria parses that ("1,234.50"), so a copied figure pastes. Any other paste is React Aria's.
9. **Steppers.** For a plain number with `hasStepper`: React Aria's slotted buttons, named `labels.decrement` and `labels.increment` as `aria-label`, keeping React Aria's `aria-labelledby` of themselves and the field's label (spec correction 10), out of the tab order, disabled at a bound (`useNumberField.mjs:255-281`). A money field has none: `hasStepper` is `never` there.
10. **Forms** (spec correction 4). A plain number keeps React Aria's hidden input under `name`. In money mode the wrapper passes no `name` and no `form` to React Aria and renders `<input type="hidden" name={name} form={form} disabled={isDisabled} value={minor === null ? '' : String(minor)} />` after the field's root, from React Aria's `numberValue` through `toMinor`, so it follows a native form reset, which React Aria applies to its state (`useNumberField.mjs:214`).
11. **URL state.** Controlled from a search parameter as an integer, `?min=2000`, read with `Number()` (an absent or non-numeric parameter reads as null), written in `onChange`, which fires when the value commits, never on a keystroke. **Code** (the money arithmetic and its face, because a float of whole units drifts and the face must be the same bytes everywhere; the input's context, because a prop cannot remove a key React Aria merges first; and the two capture guards):

```ts
// money.ts: pure, no Intl.
/** Minor units as whole units for React Aria, NaN for an empty field (React Aria's empty value). */
export const toUnits = (minor: number | null | undefined, digits: number): number =>
  minor == null ? Number.NaN : minor / 10 ** digits;

/** React Aria's committed number as minor units, null for its NaN. React Aria has rounded it to `digits`. */
export const toMinor = (units: number, digits: number): number | null =>
  Number.isNaN(units) ? null : Math.round(units * 10 ** digits);

/** The face: ASCII digits, no grouping, the hyphen-minus. faceOfMinor(-123450, 2) is "-1234.50". */
export function faceOfMinor(minor: number | null, digits: number): string {
  if (minor === null) return '';
  const sign = minor < 0 ? '-' : '';
  const units = Math.abs(minor);
  if (digits === 0) return `${sign}${String(units)}`;
  const scale = 10 ** digits;
  return `${sign}${String(Math.floor(units / scale))}.${String(units % scale).padStart(digits, '0')}`;
}
```

```tsx
// NumberField.tsx: rendered inside RACNumberField's Group, so the input context is the field's own.
function NumberFieldInput({ inputMode, face, placeholder, describedBy, inputRef }: InputPartProps): ReactElement {
  const context = useContext(InputContext) as (InputProps & { ref?: Ref<HTMLInputElement> }) | null;
  // React Aria's input props (useNumberField.mjs:216-227) less its localized role description, which differs by
  // locale and would break the face; the keyboard and, before hydration, the value are set here in both passes.
  const own = useMemo(() => {
    const { 'aria-roledescription': _localized, ...rest } = context ?? {};
    return {
      ...rest,
      inputMode,
      'aria-describedby': cx(rest['aria-describedby'], describedBy) || undefined,
      ...(face === undefined ? {} : { value: face }),
    };
  }, [context, inputMode, face, describedBy]);
  return (
    <InputContext value={own}>
      <Input ref={inputRef} className="number-field-input" placeholder={placeholder} />
    </InputContext>
  );
}

// On the Group: React Aria's spin button takes Home and End for the bounds (useSpinButton.mjs:85-98) and prevents
// the caret's move. Stopped here, before it, the browser's default still moves the caret (R3).
const guardKeys = (event: KeyboardEvent<HTMLElement>): void => {
  if ((event.key === 'Home' || event.key === 'End') && event.target instanceof HTMLInputElement) {
    event.stopPropagation();
  }
};
```

```ts
/** A range of days as ISO dates, 'YYYY-MM-DD', in the Gregorian calendar whatever the calendar shown. */
export interface DateRange {
  start: string;
  end: string;
}

export interface DateRangePreset {
  id: Key;
  /** The preset's words, the app's: "This month". */
  label: string;
  /** Its range, computed by the app from its own today. */
  range: DateRange;
}

export interface CalendarLabels {
  /** @default 'Previous month' */
  previous: string;
  /** @default 'Next month' */
  next: string;
  /** The name of the row of presets. @default 'Presets' */
  presets: string;
}

interface CalendarShared {
  /** The earliest and latest day that can be chosen, as ISO dates. */
  minValue?: string;
  maxValue?: string;
  /** Days that cannot be chosen, such as a closed day. Receives an ISO date. */
  isDateUnavailable?: (date: string) => boolean;
  /** Today in the app's time zone, as an ISO date (ruling 3). Without it, the device's today after hydration. */
  today?: string;
  /** @default from the locale */
  firstDayOfWeek?: 'sun' | 'mon' | 'tue' | 'wed' | 'thu' | 'fri' | 'sat';
  /** React Aria's, to ship only the calendar systems the app uses. */
  createCalendar?: (identifier: CalendarIdentifier) => ICalendar;
  isDisabled?: boolean;
  isReadOnly?: boolean;
  labels?: Partial<CalendarLabels>;
  className?: string;
  ref?: Ref<HTMLDivElement>;
}

export type CalendarProps = CalendarShared &
  AriaName & { value?: string | null; defaultValue?: string | null; onChange?: (value: string) => void };

export type RangeCalendarProps = CalendarShared &
  AriaName & {
    value?: DateRange | null;
    defaultValue?: DateRange | null;
    onChange?: (value: DateRange) => void;
    /** A row of preset ranges above the grid. */
    presets?: readonly DateRangePreset[];
  };

export function Calendar(props: CalendarProps): ReactElement;
export function RangeCalendar(props: RangeCalendarProps): ReactElement;
```

1. **Markup, in DOM order.** `RACCalendar.calendar` (or `RACRangeCalendar.calendar.range-calendar`), `className` merged after, `ref` on the root, the app's `aria-label` or `aria-labelledby` passed through (`AriaName` is required: a calendar shows no label of its own), holding `header.calendar-header` with `IconButton slot="previous"` (Lucide `ChevronLeft`, `aria-label={labels.previous}`), `Heading.calendar-heading` (React Aria's month title through its heading context, `aria-hidden`, `Calendar.mjs:86-93`) and `IconButton slot="next"` (Lucide `ChevronRight`, `labels.next`); for a range with `presets`, `div.calendar-presets[role="group"]` with `aria-label={labels.presets}`, holding one `ToggleButton.calendar-preset` per preset (spec correction 7); then `CalendarGrid.calendar-grid` (a `table` with `role="grid"`) holding `CalendarGridHeader` of `CalendarHeaderCell.calendar-weekday` and `CalendarGridBody` of `CalendarCell.calendar-day`, each drawing `span.calendar-day-number` (Behavior 5). React Aria adds its own visually hidden `h2` and a hidden next button (`Calendar.mjs:111-116`).
2. **The face** (spec 6.2). While `useHydrated()` is false, the part renders `div.calendar[data-face]` (and `.range-calendar` for a range) with `className` and `ref`, empty: React Aria's root name joins the visible month with `Intl`, and its weekdays, days and today come from `Intl` and the device's zone, so nothing of it renders earlier. React Aria's calendar mounts on the next render; the root changes element, which is the one remount the server face allows, and an inline calendar holds no focus then (10.2 item 1). A calendar in a popover or a sheet is first rendered in the browser and never shows the face.
3. **Values** (ruling 2). The wrapper reads `value`, `defaultValue`, `minValue` and `maxValue` with `parseIso`, which wraps `@internationalized/date`'s `parseDate` (its pattern and range checks throw, `dist/private/string.mjs:21,43-52,98-101`) and returns `'invalid'` for a string that does not parse; a range whose end is before its start is `'invalid'` too. An invalid value reads as no value and warns once (`useWarnOnce`), so a hand-edited URL never throws. `onChange` receives `toIso(date)`, `toCalendarDate(date).toString()`, which writes the Gregorian ISO date whatever calendar the date is in (`string.mjs:106-111`); React Aria emits a chosen date in the value's calendar, else Gregorian (`useCalendarState.mjs:119-125`), so `fa-IR` reads and writes Gregorian. `isDateUnavailable` receives the ISO date. Controlled and uncontrolled, as the props say.
4. **Which month shows** (spec correction 13). The value's month (a range's start); else `today`'s, passed as React Aria's `defaultFocusedValue` only while there is no value; else React Aria's `today(timeZone)` with the device's zone (`useCalendarState.mjs:55-58`), which runs only in the browser.
5. **Today** (ruling 3, spec correction 14). `CalendarCell`'s render function draws `span.calendar-day-number` with the cell's `formattedDate` and `data-today=""` when `isSameDay(date, todayDate)` with the parsed `today`, or when React Aria's `isToday` holds and no `today` is given. `calendar.css` keys the ring and the weight on the number's `data-today` and never on the cell's own. React Aria's spoken "Today" still follows the device (R7).
6. **A range.** The first choice anchors, the second completes; until then moving or hovering shows the range that would be chosen (React Aria's `highlightedRange`). A range of one day is allowed. `commitBehavior="reset"` drops a half-chosen range on a blur out of the calendar and on a press released outside it or on anything in it that is not a button, the month heading included (spec correction 16), so no range the person did not finish is written. `allowsNonContiguousRanges` is never passed.
7. **Presets** (10.2 item 7). A press sets the range through `RangeCalendarStateContext`'s `setValue` with the preset's parsed range and moves the view to its start with `setFocusedDate`; a preset is pressed (`isSelected`) while the state's value, written as ISO, equals its range. The library computes no range. Presets are disabled with the calendar.
8. **The Persian calendar.** With `fa-IR`, React Aria draws the Persian calendar, its month names and Persian digits, with the week from Saturday, all from `Intl` in the browser; `fa-IR-u-ca-gregory` draws the Gregorian calendar in Persian digits and `fa-IR-u-nu-latn` Latin digits. `createCalendar` is passed through; an app that uses Gregorian and Persian only passes one that returns `GregorianCalendar` or `PersianCalendar`, which narrows a calendar's bundle and not a date field's (spec correction 18).
9. **Keys.** React Aria's, as the table says (spec correction 32): the arrows by day and week, in the drawn direction under a right-to-left locale (`useCalendarGrid.mjs:66-80`); Home and End to the month's ends; Page Up and Page Down by a month, with Shift by a year; Enter and Space choose; Escape drops an anchor and goes on to whatever holds the calendar; the grid is one tab stop.
10. **Unavailable and out of bounds.** React Aria writes `data-unavailable` and `data-disabled` on the day (`Calendar.mjs:327-341`); both draw taupe, the first struck through, with `cursor: not-allowed`. Days outside the month take `data-outside-month` and are hidden but keep their place.
11. **Server.** An inline calendar renders its face in Node, one HTML in every locale and zone; a range calendar with presets renders the same empty frame (the presets need React Aria's state).

```tsx
/** The presets of whichever range calendar holds them: the app's RangeCalendar, or the picker's. */
export function CalendarPresets({ presets, label }: PresetsProps): ReactElement | null {
  const state = useContext(RangeCalendarStateContext);
  if (state === null || presets.length === 0) return null;
  const chosen = state.value === null ? null : `${toIso(state.value.start)}/${toIso(state.value.end)}`;
  return (
    <div className="calendar-presets" role="group" aria-label={label}>
      {presets.map((preset) => (
        <ToggleButton
          key={preset.id}
          className="calendar-preset"
          isSelected={chosen === `${preset.range.start}/${preset.range.end}`}
          isDisabled={state.isDisabled || state.isReadOnly}
          onChange={() => {
            const start = parseDate(preset.range.start);
            state.setValue({ start, end: parseDate(preset.range.end) });
            state.setFocusedDate(start);
          }}
        >
          {preset.label}
        </ToggleButton>
      ))}
    </div>
  );
}
```

**Code** (the names, because `DateInput` takes nothing but its slot from its context; and the frame, because the picker's keys live on its group props and React Aria's `Group` would ring the frame for the button):

```tsx
/**
 * React Aria's two date field slots with the library's names: DateInput reads only its slot from this context
 * (DateField.mjs:253-258), and the name reaches each segment with the field's label (useDateSegment.mjs:321-325).
 */
function DateFieldNames({ start, end, children }: NamesProps): ReactElement {
  const context = useContext(DateFieldContext) as SlottedDateFields | null;
  const named = useMemo(
    () =>
      context === null
        ? null
        : {
            slots: {
              start: { ...context.slots.start, 'aria-label': start },
              end: { ...context.slots.end, 'aria-label': end },
            },
          },
    [context, start, end],
  );
  return <DateFieldContext value={named}>{children}</DateFieldContext>;
}

/**
 * The drawn frame: the picker's whole group (its role, its labelling, Alt+Arrow Down and its focus within,
 * useDateRangePicker.mjs:126-139) on a plain div, which React Aria positions the popover against. Not React Aria's
 * Group, whose focus-within data-focus-visible (Group.mjs:54-56) would ring the frame while the button has focus.
 */
function DateRangeFrame({ isDisabled, children }: FrameProps): ReactElement {
  const { ref, isInvalid: _invalid, isDisabled: _disabled, isReadOnly: _readOnly, ...group } =
    (useSlottedContext(GroupContext) ?? {}) as PickerGroup;
  return (
    <div {...group} ref={ref} className="input date-range-control" data-disabled={isDisabled ? '' : undefined}>
      {children}
    </div>
  );
}
```

10. **The section face.** Under `FilterChipPlaceContext` with `place` `panel` or `sheet`, the chip draws `section.filter-section[aria-labelledby]` holding `div.filter-section-head` with `h3.filter-section-title` (the label, its id the section's name) and, while active and clearable, `Button variant="tertiary"` (`filter-section-clear`) showing `clearWord` and named `labels.clear(label)` (spec correction 26), which clears and puts focus on the section's trigger; then, for a list chip, `RACSelect.field.select.filter-section-select` with `Button.input.select-trigger` (Select's look) `aria-labelledby` its `span.select-value` and the title, showing the summary, or `labels.any` as `data-placeholder` in slate (`select.css`), with `span.select-chevron`, and the same `SelectPopover`; for a custom chip, its `children`, called with the context's `close`. A chip in a section never draws the pill or the guard.
11. **Where a chip shows in a bar** (spec correction 29). In the row, an inactive secondary chip renders nothing when `hasMore` is true; in the panel, a chip renders only when its label is in `panelLabels`; in the sheet, every chip renders. On its own, a chip is a pill.
12. **Server.** A list chip renders in Node with its label, its summary from the hidden pass, its chevron and its clear button, no listbox and no filter (the shared `SelectPopover`'s guard), one HTML in every locale and zone.

**Code** (the trigger and its summary, because React Aria's own value and name would put `Intl` in the render and the name out of the visible order; and the guard):

```tsx
/** "Food", "Food, Rent", "Food, Rent and 2 more", with concatenation and String() only (ruling 7). */
const defaultSummary = (texts: readonly string[]): string =>
  texts.length <= 2
    ? texts.join(', ')
    : `${texts[0] ?? ''}, ${texts[1] ?? ''} and ${String(texts.length - 2)} more`;

/** The chosen options' text values in the list's order: React Aria keeps selectedItems in the value's order. */
function chosenTexts(state: ChipSelectState): string[] {
  const order = [...state.collection.getKeys()];
  return [...state.selectedItems]
    .sort((a, b) => order.indexOf(a.key) - order.indexOf(b.key))
    .map((item) => item.textValue);
}

/** The pill's trigger for a list chip. React Aria's state is null in its hidden collection pass. */
function ChipTrigger({ label, valueLabel, summary, triggerRef }: TriggerProps): ReactElement {
  const state = useContext(SelectStateContext);
  const labelId = useId();
  const valueId = useId();
  const text =
    valueLabel ?? (state !== null && state.selectedItems.length > 0 ? summary(chosenTexts(state)) : undefined);
  return (
    <Button
      ref={triggerRef}
      className="filter-chip-trigger"
      aria-labelledby={text === undefined ? labelId : `${labelId} ${valueId}`}
    >
      <span id={labelId} className="filter-chip-label">{label}</span>
      {text === undefined ? null : <span id={valueId} className="filter-chip-value">{text}</span>}
      <span className="filter-chip-chevron" aria-hidden="true">
        <ChevronDown />
      </span>
    </Button>
  );
}

// On div.filter-chip: a closed chip keeps letters and Left and Right from React Aria's Select, which would choose
// an option unseen (useSelect.mjs:54-61, useTypeSelect.mjs:49-60). Stopped here, before the trigger's handlers.
const guardClosedKeys = (event: KeyboardEvent<HTMLDivElement>): void => {
  if (isOpen || !(event.target as Element).classList.contains('filter-chip-trigger')) return;
  const isLetter =
    event.key.length === 1 && event.key !== ' ' && !event.ctrlKey && !event.metaKey && !event.altKey;
  if (isLetter || event.key === 'ArrowLeft' || event.key === 'ArrowRight') event.stopPropagation();
};
```

**Code** (the walk, because it decides the count on the server and whether a secondary chip may leave the row):

```ts
// walk.ts
/** Whether a FilterChip's props say it has a value: a list chip by its value, a custom chip by its valueLabel. */
const isActive = (props: FilterChipProps): boolean =>
  props.selectionMode === undefined
    ? present(props.valueLabel)
    : Array.isArray(props.value)
      ? props.value.length > 0
      : props.value !== null;

/**
 * The bar's census, read from its children's props through fragments as BottomTabBar counts its items: how many
 * chips are active, and the labels of the inactive secondary ones. A chip wrapped in the app's own component is
 * not read; `activeCount` covers its count, and it stays in the row (plan, spec correction 29).
 */
export function censusOf(children: ReactNode): { active: number; inactiveSecondary: string[] } {
  const census = { active: 0, inactiveSecondary: [] as string[] };
  const visit = (nodes: ReactNode): void => {
    for (const child of Children.toArray(nodes)) {
      if (!isValidElement(child)) continue;
      if (child.type === Fragment) visit((child.props as { children?: ReactNode }).children);
      else if (child.type === FilterChip) {
        const props = child.props as FilterChipProps;
        if (isActive(props)) census.active += 1;
        else if (props.isSecondary === true) census.inactiveSecondary.push(props.label);
      }
    }
  };
  visit(children);
  return census;
}
```
