## One series

A line chart shows a value across a run of days as a 2px ink line. Gridlines sit at the `yTicks`, with their labels above them, and the first, middle and last day are labeled underneath. Focus or point at the plot to see a readout of the day and its value.

## Gaps

Pass `null` for a day with no value, such as one still to come. The line breaks there, the keys and pointer skip it, the readout leaves out that series, and the table cell is empty. `hasArea` fills under the first series with a 10% ink wash, which breaks with the line.

<Section>

## The table

The Show as table toggle under every chart swaps the plot for a table of the same strings, with a row per day and a column per series. It is visible to everyone who would rather read the numbers, not only screen reader users. With scripts off, the table is shown under the plot with a note saying so.

The table is named like the chart. With `aria-label`, a caption repeats it. With `aria-labelledby`, the table points at the same heading and has no caption.

</Section>

<Section>

## Right to left

Time follows the page's direction. Under `dir="rtl"` the newest day is at the left, and Left moves to newer days. The svg, its marks and the keys all read the nearest `dir="ltr"` or `dir="rtl"` attribute, so they always agree; `dir="auto"` is skipped. The figures inside the labels are your strings.

## Usage

```bash
pnpm add @snapshot-ui/charts @snapshot-ui/core
```

It needs the same 0.x minor of `@snapshot-ui/core` (0.7 for charts 0.1.4), whose `styles.css` styles it. The svg, axis labels, legend and table render on the server, and the client adds the keys, pointer and readout. A server component can render it with plain data.

- Formatting: every label and value is your formatted string. `valueLabel` is what the reader sees, and `value` only places the point. Currency, compact figures and Persian digits are yours, and the server's HTML is final.
- `yTicks`: gridlines with labels. Without them, the chart draws only its baseline and relies on the readout and the table.
- `yDomain`: pass the same one to charts read side by side, so their scales match.
- `labels`: in another language, pass all four strings the chart writes itself: the toggle's two, the note shown with scripts off, and the role description a screen reader says in place of "chart".

```tsx
import { LineChart } from '@snapshot-ui/charts';

<LineChart
  aria-label="هزینه‌های مهر"
  series={[
    { label: 'این ماه', points: [{ value: 42.1, valueLabel: '۴۲٫۱۰ دلار' }, null] },
    { label: 'ماه گذشته', points: [{ value: 35, valueLabel: '۳۵ دلار' }, { value: 41.2, valueLabel: '۴۱٫۲۰ دلار' }] },
  ]}
  xLabels={['۱ مهر', '۲ مهر']}
  yTicks={[
    { value: 0, label: '۰ دلار' },
    { value: 50, label: '۵۰ دلار' },
  ]}
  labels={{
    showTable: 'نمایش جدول',
    showChart: 'نمایش نمودار',
    noScript: 'اسکریپت‌ها خاموش‌اند، پس داده‌های نمودار در جدول زیر است.',
    roleDescription: 'نمودار',
  }}
/>;
```

## Accessibility

The chart is a `figure` named by `aria-label` or `aria-labelledby`, which the types require. The plot is a single tab stop, so thirty-one days are never thirty-one stops. It is a group named like the figure, with the role description "chart" (`labels.roleDescription`), and becomes focusable once scripts run. The table is the full alternative.

- Keys: the arrows move a readout and a crosshair through the days with data. Keys with Alt, Control or Meta are left to the browser.
- Readout: it sits above the day's dots, or below them near the top, so it never covers its point.
- Announcements: once the keys rest for 150ms, a screen reader hears the day and each series with its value, so a held key is heard only where it stops. Each part is announced on its own, with no punctuation added between your words.
- Pointer: snaps to the nearest day anywhere in its column, not only on the line.
- Forced colors: the first line uses the reader's text color, the second line and gridlines GrayText, and the crosshair and dots Highlight.
