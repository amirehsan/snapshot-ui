## Basic

A field for a range of two days. Type each date into its segments, in the locale's order, or choose the range on the calendar. The button at the field's end, or Alt+Arrow Down, opens the calendar on the start month, or on `today`'s month when there is no value.

- Value: `{ start, end }`, two ISO dates, in and out. Days only, never times.
- `onChange`: receives the range once both dates are complete and the end is on or after the start. It receives `null` once every segment of a date is cleared, or while the end is before the start.
- Clearing one segment keeps the range until the rest of that date is cleared.
- Forms: `startName` and `endName` submit the two ISO dates.

## Presets

`presets` adds a row of your own ranges above the calendar. The library computes no ranges: compute "Last 7 days" from the app's today, ideally on the server. A press sets the range, closes the calendar and returns focus. A preset is disabled when it falls outside `minValue` or `maxValue`, or holds a day `isDateUnavailable` rejects.

## Before hydration

Pass `valueLabel` wherever the server's HTML should show the range, written like any other string in the app: "1 to 30 Sep 2026". The segments' text, order and names come from `Intl`, which the server must not write. Until hydration, the field draws the label, the frame at its final size, the calendar button, the hint, the two hidden inputs and your `valueLabel` in place of the segments. The segments replace it in the next render without moving anything.

</Section>

## Usage

Keep the range in two search parameters, `?from=2026-09-01&to=2026-09-30`. With the Next App Router, a server page reads them and writes `valueLabel`:

```tsx
// app/transactions/page.tsx, a server component
import { Period } from './period';
import { periodLabel } from './words'; // the app's own: "1 to 30 Sep 2026"

export default async function Transactions({ searchParams }: { searchParams: Promise<Record<string, string>> }) {
  const { from, to } = await searchParams;
  return <Period valueLabel={from && to ? periodLabel({ start: from, end: to }) : ''} />;
}
```

The client component keeps the range in its own state, so each change shows at once. Driven by the server's props instead, it would show the old range until the new page arrived.

- It rereads the URL only when the URL changes under it, by Back, Forward or a link.
- On change it sets both parameters, or deletes both for `null`, and keeps the other parameters.
- It never writes a bare `?`, and passes `{ scroll: false }` so the page does not jump.

```tsx
'use client';

import { useState } from 'react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { DateRangePicker, type DateRange } from '@snapshot-ui/react';

const rangeOf = (from: string | null, to: string | null): DateRange | null =>
  from && to ? { start: from, end: to } : null;

export function Period({ valueLabel }: { valueLabel: string }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const from = searchParams.get('from');
  const to = searchParams.get('to');
  const key = `${from ?? ''}/${to ?? ''}`;
  const [range, setRange] = useState(() => rangeOf(from, to));
  const [seen, setSeen] = useState(key);

  // The URL changed under the field, by Back, Forward or a link: show its range.
  if (key !== seen) {
    setSeen(key);
    setRange(rangeOf(from, to));
  }

  return (
    <DateRangePicker
      label="Statement period"
      value={range}
      valueLabel={valueLabel}
      onChange={(next) => {
        setRange(next);
        setSeen(next ? `${next.start}/${next.end}` : '/');
        const params = new URLSearchParams(searchParams);
        if (next === null) {
          params.delete('from');
          params.delete('to');
        } else {
          params.set('from', next.start);
          params.set('to', next.end);
        }
        const query = params.toString();
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    />
  );
}
```

- A pair that does not parse, or ends before it starts, reads as no range and warns in the console. A hand-edited URL never throws.
- While someone types an end before its start, the field sends `null` but keeps what is typed, so your `null` coming back does not clear it. Setting any other value, or focus leaving the field, ends this, so a "Clear all" that sets `null` still clears it.
- On a statically rendered route, like this page, call `useSearchParams()` inside `<Suspense>` with an empty field as the fallback. The example below does this, and writes its `valueLabel` from twelve month names, with no `Intl`.

## Accessibility

The field is a `group` named by the label. Each segment is a `spinbutton` named by its type, its date and the label: "month, Start date, Statement period". On iOS, each segment is a text box. The button, named "Choose dates" plus the label, opens a `dialog` with the range calendar.

"Choose dates", "Start date" and "End date" come from `labels`. Segment type names come from the browser. React Aria's announcements, such as the chosen range, have no Persian.
