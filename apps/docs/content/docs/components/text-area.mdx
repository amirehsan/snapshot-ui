## Basic

Pass a label, and a hint if the label cannot say it all. The box is three lines tall and never shorter than 6rem. Enter adds a line, and the reader can drag the corner to make it taller. The placeholder shows an example and never replaces the label.

## States

The states match Text field, on the taller box.

- Changed: a light signal orange edge and a clay chip beside the label.
- Invalid: the error edge and an error line. Invalid outranks changed, so the chip steps aside.
- Disabled: recessed.
- Read-only: looks enabled and still submits.

## Length and height

Pass `budget` to count the value's length against a rough target. The count appears from 70% of the budget and never blocks typing. Pass `rows` for a taller box: the height is the rows times the line height, plus padding and edge, and never less than 6rem.

<Preview name="text-area-counter" />

- Units: the count is in UTF-16 code units, as JavaScript and `maxLength` measure it. A line break counts as one, as in the value `onChange` receives. An emoji, or an accented letter built from two code points, can count as two.
- Forms: a browser sends each line break as two characters, so a server measuring the request sees one more per line.
- Limits: the budget is a soft target the count can pass. `maxLength` is a hard stop the counter does not read, so set `budget` at or below `maxLength`.

To word the count another way, such as in another language, pass `counter` with a `label` function. It receives the count, the budget and whether the count is past it, and returns the text. `counter.showFrom` sets the share of the budget where the count first appears.

```tsx
<TextArea
  label="Kurzbeschreibung"
  budget={60}
  counter={{ label: ({ count, budget }) => `${count} von etwa ${budget}` }}
/>
```

The count is announced each time it changes. If that is too often, build the field from its parts and pass FieldCounter a count that settles after a pause, as [Field parts](/docs/components/field) describes.

## Usage

Every value works controlled and uncontrolled, and a field with a `name` submits in a plain form. `onChange` receives the string, with each line break as `\n`.

```tsx
import { useState } from 'react';
import { TextArea } from '@snapshot-ui/react';

export function ShortDescription({ saved }: { saved: string }) {
  const [value, setValue] = useState(saved);
  return (
    <TextArea
      label="Short description"
      description="One or two sentences, for search results."
      name="description"
      value={value}
      onChange={setValue}
      isChanged={value !== saved}
      budget={120}
      rows={4}
    />
  );
}
```

The types require an accessible name: a `label`, an `aria-label` when no label is shown, or an `aria-labelledby` that points at a label elsewhere.

For a custom layout, use Snapshot UI's Label, Description and FieldError inside React Aria's TextField, with React Aria's TextArea and the classes `input textarea`. There is no bare textarea part, since those classes are all it would add. [Field parts](/docs/components/field) has the layout.

## Accessibility

A native textarea, labelled by the label and described by the hint and error line, with React Aria handling the wiring. While the field is changed and valid, a screen reader reads the Changed chip after the hint. An invalid field reads its hint, then its error line.

<Keys rows={[['Tab', 'Moves focus into the field. The edge firms to 1.5px ink and the 2px ring sits outside it.'], ['Shift Tab', 'Moves focus back out.'], ['Enter', 'Adds a new line. It never submits the form.']]} />

- Resizing: the corner handle works with a pointer, in browsers that draw one. The keyboard cannot resize, so set `rows` to the height the content needs.
- Placeholder: taupe and quiet by design, so it never carries anything the label does not.
- Count: a polite status region.
- Missing name: the field does not compile. TypeScript either names only `aria-labelledby` or says the props are not assignable. Both mean the field has no accessible name.
