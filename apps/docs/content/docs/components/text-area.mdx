## Basic

Pass a label, and a hint if the label cannot say it all. The box is three lines tall and never shorter than 6rem. Enter adds a line, and the reader can drag the corner to make it taller. The placeholder shows an example and never replaces the label.

## States

The states are the ones Text field draws, on the taller box. A changed field gets a light signal orange edge and a clay chip beside its label. An invalid field gets the error edge and an error line, and invalid outranks changed, so the chip steps aside. A disabled field is recessed. A read-only field looks like an enabled one and still submits.

## Length and height

Pass `budget` to count the value's length against about how long it should be. The count appears from 70% of the budget and never blocks typing. Pass `rows` for a taller box: the height is the rows times the line height, plus the padding and the edge, and never less than 6rem.

<Preview name="text-area-counter" />

The count is the value's length as JavaScript and `maxLength` measure it, in UTF-16 code units. A line break counts as one, as it does in the value `onChange` receives, and an emoji, or an accented letter built from two code points, can count as two. A browser sends each line break in a form request as two characters, so a server that measures the request sees one more per line.

The budget is a soft target and the count can pass it. `maxLength` is a hard stop that the counter does not read, so set `budget` at or below `maxLength`.

To word the count another way, such as in another language, pass `counter` with a `label` function. It receives the count, the budget and whether the count is past it, and returns the text. `counter.showFrom` moves the share of the budget the count first appears at.

```tsx
<TextArea
  label="Kurzbeschreibung"
  budget={60}
  counter={{ label: ({ count, budget }) => `${count} von etwa ${budget}` }}
/>
```

The count is announced each time it changes. If that is too often for your readers, build the field from its parts and pass FieldCounter a count that settles after a pause, as [Field parts](/docs/components/field) describes.

## Usage

Every value works controlled and uncontrolled, and a field with a `name` submits in a plain form. `onChange` receives the string, with each line break as `\n`.

```tsx
import { useState } from 'react';
import { TextArea } from '@snapshot-ui/react';

export function ShortDescription({ saved }: { saved: string }) {
  const [value, setValue] = useState(saved);
  return (
    <TextArea
      label="Short description"
      description="One or two sentences, for search results."
      name="description"
      value={value}
      onChange={setValue}
      isChanged={value !== saved}
      budget={120}
      rows={4}
    />
  );
}
```

A field needs a name, and the types require one: a `label`, or an `aria-label` or `aria-labelledby` when the name is shown elsewhere.

For a custom layout, use the parts inside React Aria's own TextField: Label, Description and FieldError from Snapshot UI, and React Aria's TextArea with the classes `input textarea`. There is no bare textarea part, because the pair of classes is all it adds. [Field parts](/docs/components/field) has the layout.

## Accessibility

A native textarea, labelled by the label and described by the hint and the error line, with React Aria handling the wiring. A screen reader reads the Changed chip with the field, after the hint, while the field is changed and valid. An invalid field reads its hint and then its error line, and the chip steps aside.

<Keys rows={[['Tab', 'Moves focus into the field. The edge firms to 1.5px ink and the 2px ring sits outside it.'], ['Shift Tab', 'Moves focus back out.'], ['Enter', 'Adds a new line. It never submits the form.']]} />

The corner handle resizes with a pointer, in the browsers that draw one, and the keyboard has no way to resize, so set `rows` to the height the content needs. The placeholder is taupe, which is quiet by design, so it never carries anything the label does not. The count is a polite status region.
