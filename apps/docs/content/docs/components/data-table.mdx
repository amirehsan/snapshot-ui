## Basic

Pass the rows as `items`, the columns as definitions and a key for each row. Each column says how its cell reads: a string or any node. With `getRowHref`, a press anywhere on a row opens its detail through your router, as a real link in the row header's cell, so a middle click or a modifier click opens a new tab and the link's menu is the browser's. A sortable header is a button: `sortDescriptor` and `onSortChange` are controlled, ascending first and then descending, with no unsorted state. `currentKey` marks the row whose detail is open.

## Figures and totals

A column with `align: 'end'` sets figures: tabular digits, never broken, at the line's end in either direction, so a column of amounts lines up at its last digit. Your strings carry the sign, the currency and the unit. A column's `total` adds one totals row under the rows, its header cell saying "Total". In a card, set `--data-table-surface` to the card's fill so the sticky header matches it.

## Columns that leave

The table never scrolls sideways. A column with `hideBelow: 'md'` leaves when the table's own box is narrower than 48rem, and one with `hideBelow: 'sm'` when it is narrower than 40rem. They are widths of the table's box, not of the screen, so a table beside an open panel drops its columns too. Cells keep to one line and end in an ellipsis; the full text is still the row's name. The row header never leaves.

## Empty and loading

`emptyState` takes an `EmptyState`, drawn across every column when there are no rows. While `isLoading` and there are no rows yet, the table draws skeleton rows in its own shape and says "Loading" once, after a short pause, in a status of its own. While it loads with rows already shown, such as the next page, it keeps them and only marks itself busy.

## Selection

Pass `selectedKeys` and `onSelectionChange` together to turn selection on: a first column of checkboxes, and a bar of bulk actions that sticks to the bottom of the screen while any row is selected. Hold the selection in your page's state, never in the URL, and clear it whenever the rows change, on a new page, sort or filter, as this example clears it on a sort. A press on a row still opens it, and a press on a row without a link does nothing; only the checkbox, Space and X select. The header checkbox selects the rows on this page, and `onSelectionChange` always gets an array of their keys, never "all": to act on every result, offer that in the bar yourself. `bulkActions` are your buttons, shown before Clear selection, and `formatCount` writes the bar's count in your reader's digits. The bar counts only selected keys that are still in `items`, and the table draws only those as selected; a key that is not stays in what `onSelectionChange` gets until you drop it, and is warned about once in the console. Clear selection clears every key. When a bulk action asks first, in a dialog whose confirm clears the selection, the table takes focus back once the dialog has closed. A table inside a dialog keeps its keys.

## Usage

Render DataTable from a client component: its columns, keys and links are functions, which a server component cannot pass. Load the rows in a server page and pass them as data; a node a server rendered can reach a cell as a field of its row. Wrap the app in a `RouterProvider` once, so the row links go through your router. `currentKey` is compared with each row's key by strict equality, so a key read from the URL, which is a string, never matches a numeric key: convert it first, as `Number(params.get('open'))`. The row's link is stretched over the whole row, so text in a row cannot be selected by dragging across it; put text a reader copies in the detail the row opens. A control in a cell takes its own press above the row's link: a button, a link, an input, a label, a field, anything with a control role such as `checkbox`, `switch` or `menuitem`, and anything in the tab order. Give anything else that takes a press the class `data-table-control`. Set `--page-sticky-top` to your header's height on an ancestor, once for every sticky part of the page, so the table's header sticks under yours. The bulk-action bar sticks above `--app-shell-inset-block-end`, which AppShell sets for its bottom tab bar. Every string in the table is yours: the library formats no date, amount or count.

```tsx
'use client';

import { DataTable, EmptyState, type DataTableColumn } from '@snapshot-ui/react';

const columns: DataTableColumn<Transaction>[] = [
  { id: 'date', header: 'Date', cell: (row) => row.dateLabel, allowsSorting: true, width: '7rem' },
  { id: 'payee', header: 'Payee', cell: (row) => row.payee, isRowHeader: true },
  { id: 'category', header: 'Category', cell: (row) => row.category, hideBelow: 'md' },
  { id: 'amount', header: 'Amount', cell: (row) => row.amountLabel, align: 'end', total: '-$1,284.50' },
];

export function Transactions({ rows, sort, openId }: TransactionsProps) {
  return (
    <DataTable
      aria-label="Transactions"
      items={rows}
      columns={columns}
      getKey={(row) => row.id}
      getRowHref={(row) => `?open=${row.id}`}
      currentKey={openId}
      sortDescriptor={sort}
      onSortChange={(next) => writeSortToUrl(next)}
      emptyState={<EmptyState title="No transactions this month" />}
    />
  );
}
```

## Accessibility

The table is a `grid` named by your `aria-label` or heading. Each header is a `columnheader`, with `aria-sort` on the sortable ones; the row header's cell is a `rowheader`, so a screen reader names each row by it. The current row's link is `aria-current`, and the row draws a bar and a bolder name, so the state is never color alone. React Aria announces a sort in its own words. While loading, the table is busy and a polite status outside it says "Loading" once; the skeletons are hidden from assistive technology. The table is one tab stop: no row link or checkbox is in the tab order, and the arrows reach them.

With selection on, the grid is multiselectable and each row says whether it is selected. The header checkbox is named "Select all" and a row's "Select" followed by the row's name, such as "Select Corner Mart". The bar is a toolbar named "Bulk actions". React Aria announces each selection change in its own English words, and the bar's polite status says the count in yours, once the selection has held for a moment, so a run of X presses is said once. Letters never move focus: J and K move as the arrows, X toggles, and every other letter does nothing, on any keyboard layout.
