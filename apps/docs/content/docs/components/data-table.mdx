## Basic

Pass the rows as `items`, the columns as definitions and a key for each row. Each column says how its cell reads: a string or any node. With `getRowHref`, a press anywhere on a row opens its detail through your router, as a real link in the row header's cell, so a middle click or a modifier click opens a new tab and the link's menu is the browser's. A sortable header is a button: `sortDescriptor` and `onSortChange` are controlled, ascending first and then descending, with no unsorted state. `currentKey` marks the row whose detail is open.

## Figures and totals

A column with `align: 'end'` sets figures: tabular digits, never broken, at the line's end in either direction, so a column of amounts lines up at its last digit. Your strings carry the sign, the currency and the unit; write a negative amount with a real minus sign, U+2212, which is as wide as a digit, as these examples do, not a hyphen. A column's `total` adds one totals row under the rows, its header cell saying "Total". When the table shows one page of many, the sum is of this page only: name it with `labels={{ total: 'Page total' }}`, so a reader never takes it for the whole. In a card, set `--data-table-surface` to the card's fill so the sticky header matches it.

## Columns that leave

The table never scrolls sideways. A column with `hideBelow: 'md'` leaves when the table's own box is narrower than 48rem. It is a width of the table's box, not of the screen, so a table beside an open panel drops its columns too. Under 40rem the table gives way to its list, below, where each column goes where its `listSlot` says, so a column needs no width of its own to leave at. Cells keep to one line and end in an ellipsis; the full text is still the row's name. A cell that holds only a control, such as a row menu's button, is never clipped and draws no ellipsis; give its column a width that holds it, the control and 16px either side. The row header never leaves. The example draws the table at the width you choose, in a frame of its own that scrolls sideways where this page is narrower, so the page itself never does. A frame that scrolls is where a table's header sticks, and this page's header is not inside it, so the frame sets `--page-sticky-top` to `0px`: do the same on any element of yours that scrolls, in either direction, around a table.

## On a phone

Where the table's own box is narrower than 40rem, on a phone or beside an open panel on a small laptop, the same rows are a list. Both faces are in the page's HTML and the box shows one, so nothing is measured and the server's page is right at every width. A column's `listSlot` puts its cell on an item's first line (`'title'`, the row header's place by default), on its second line in slate (`'meta'`), at its end (`'end'`, figures as in the table) or nowhere (`'hidden'`, the default for every other column); cells on one line sit a little apart, and any separator is yours. `getGroup` groups the rows under a heading per day: only rows next to each other group, so pass it only while the rows are sorted by date, and the day's label is your string. A row opens and is marked current as in the table, and the totals are a line under the list.

With selection on, the list draws no checkboxes until the reader presses Select above it: then every item has its box, Select all leads that row and the button reads Done, and that row sticks under your header while the list scrolls, so Select all and Done stay in reach. In Select mode a tap anywhere on an item selects or clears it, as a phone's mail and photos do; Enter, or Right to the item's link and Enter there, still opens it. Done hides the boxes and keeps the selection, and a tap opens an item again and never selects it. While anything is selected every item keeps room for a check mark, drawn beside the shade of each selected one, so nothing moves as items are selected, after Done or when they were selected in the table before the box narrowed. Space and X select an item whether the boxes show or not, and the bar is the table's. With more than one end column, the totals line names each figure by its column.

## Column options

A column with `overflow: 'wrap'` reads to two lines and ends in an ellipsis there, for a memo a reader wants to read without opening the row; figures never wrap. `firstSortDirection: 'descending'` makes the first press on a column sort it largest or newest first, and each later press flips it, two states only. A column of row menus takes `isHeaderHidden`: its header draws nothing and is still named by `header` for a screen reader.

A cell can hold a second line under its text, such as a payee's category: write it in a `span` with the class `data-table-cell-meta`, which sets it slate at the cell weight, a quarter rem under the first line, and granite in a hovered or selected row so it keeps its contrast on the wash. Each line ends in an ellipsis when it runs out of room. A row of two lines is 72px, with its text as far off the rules as one line is in a 48px row, and the one-line cells beside it stay centered.

```tsx
const payee: DataTableColumn<Transaction> = {
  id: 'payee',
  header: 'Payee',
  isRowHeader: true,
  cell: (row) => (
    <>
      {row.payee}
      <span className="data-table-cell-meta">{row.category}</span>
    </>
  ),
};
```

## Empty, loading and errors

`emptyState` takes an `EmptyState`, drawn across every column when there are no rows; the empty table is then itself the tab stop and draws the focus ring. While `isLoading` and there are no rows yet, the table draws skeleton rows in its own shape and says "Loading" once, after a short pause, in a status of its own. While it loads with rows already shown, such as the next page, it keeps them, marks itself busy and, after the same pause, draws a quiet line along its header's rule, or in the list one line at the top, under the first day's heading; no text dims. When the rows did not load, pass `error`: with no rows it is the body, in place of the empty state, as an `EmptyState` with a Retry action; with rows shown, a next page that failed, it is a line under the table that a polite status says. `error` wins over `isLoading` and `emptyState`.

## Selection

Pass `selectedKeys` and `onSelectionChange` together to turn selection on: a first column of checkboxes, and a bar of bulk actions that sticks to the bottom of the screen while any row is selected. Hold the selection in your page's state, never in the URL, and clear it whenever the rows change, on a new page, sort or filter, as this example clears it on a sort. A press on a row still opens it, and a press on a row without a link does nothing; only the checkbox, Space and X select, and Shift with a press on a checkbox selects every row from the last one chosen. `disabledKeys` turns a row's selection off, and with `disabledBehavior: 'selection'` only that: the row still opens and reads as any other. The header checkbox selects the rows on this page, and `onSelectionChange` always gets an array of their keys, never "all": to act on every result, offer that in the bar yourself. `bulkActions` are your buttons, shown before Clear selection, and `formatCount` writes the bar's count in your reader's digits. The bar counts only selected keys that are still in `items`, and the table draws only those as selected; a key that is not stays in what `onSelectionChange` gets until you drop it, and is warned about once in the console. Clear selection clears every key. When a bulk action asks first, in a dialog whose confirm clears the selection, the table takes focus back once the dialog has closed. A table inside a dialog keeps its keys.

## The Transactions recipe

A list page with the Next App Router, its state in the URL: the sort, the page, the filters and the open transaction. The server page awaits `searchParams`, loads the rows for the sort, the page and the filters, and loads the open transaction too, so its detail is in the server's HTML beside the table. It passes them to a client component, since DataTable's props are functions:

```tsx
// app/transactions/page.tsx, a server component
import { TransactionsList } from './transactions-list';

const PAGE_SIZE = 50;

export default async function TransactionsPage({
  searchParams,
}: {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}) {
  const params = await searchParams;
  const one = (value: string | string[] | undefined) => (typeof value === 'string' ? value : null);
  // ?sort=amount is ascending and ?sort=amount- descending; no sort is the newest first.
  const sort = one(params.sort) ?? 'date-';
  const page = Math.max(1, Math.trunc(Number(one(params.page) ?? '1')) || 1);
  const category = one(params.category);
  const openId = one(params.open);
  const { rows, total } = await loadTransactions({ sort, page, category, pageSize: PAGE_SIZE });
  const open = openId === null ? null : await loadTransaction(openId);
  return (
    <TransactionsList
      rows={rows}
      pageCount={Math.max(1, Math.ceil(total / PAGE_SIZE))}
      rangeLabel={formatRange(page, PAGE_SIZE, total)}
      sort={sort}
      page={page}
      category={category}
      open={open}
    />
  );
}
```

The client component writes the URL with the router, starting from the parameters already there, so a sort keeps the filters and the open row. A sort and a filter are replaced in history and start again at page 1; a page is pushed, so Back returns to the last page. Selection is the page's own state and never the URL's, and it clears whenever the rows change, on a new page, sort or filter: it was made on the rows before. The component clears it as it renders the new rows, so no frame shows the old selection, and the bar never counts a row that has left.

```tsx
'use client';

import { DataTable, Pagination, SidePanel, SidePanelLayout, type Key } from '@snapshot-ui/react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { useState } from 'react';

export function TransactionsList({ rows, pageCount, rangeLabel, sort, page, category, open }: TransactionsListProps) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  // The URL with some parameters changed or deleted; a bare ? is never written.
  const hrefWith = (changes: Record<string, string | null>) => {
    const params = new URLSearchParams(searchParams);
    for (const [name, value] of Object.entries(changes)) {
      if (value === null) params.delete(name);
      else params.set(name, value);
    }
    const query = params.toString();
    return query ? `${pathname}?${query}` : pathname;
  };
  const replace = (changes: Record<string, string | null>) => {
    router.replace(hrefWith(changes), { scroll: false });
  };
  const descriptor = {
    column: sort.replace(/-$/, ''),
    direction: sort.endsWith('-') ? 'descending' : 'ascending',
  } as const;
  // A new page, sort or filter shows other rows: the selection was made on the rows before, so it clears.
  const shown = rows.map((row) => row.id).join(' ');
  const [selected, setSelected] = useState<Key[]>([]);
  const [selectedOn, setSelectedOn] = useState(shown);
  if (selectedOn !== shown) {
    setSelectedOn(shown);
    setSelected([]);
  }
  return (
    <SidePanelLayout
      panel={
        <SidePanel
          key={open?.id ?? 'none'}
          title={open?.payee ?? ''}
          description={open?.dayLabel}
          isOpen={open !== null}
          onClose={() => closePanel(hrefWith({ open: null }))}
        >
          {open && <TransactionDetail transaction={open} />}
        </SidePanel>
      }
    >
      <h1 id="transactions-title">Transactions</h1>
      <TransactionFilters category={category} onChange={(next) => replace({ category: next, page: null })} />
      <DataTable
        aria-labelledby="transactions-title"
        items={rows}
        columns={columns}
        getKey={(row) => row.id}
        getRowHref={(row) => hrefWith({ open: row.id })}
        currentKey={open?.id ?? null}
        sortDescriptor={descriptor}
        onSortChange={(next) => {
          const written = `${String(next.column)}${next.direction === 'descending' ? '-' : ''}`;
          replace({ sort: written === 'date-' ? null : written, page: null });
        }}
        // Sorted by date, each day's rows are next to each other: the list groups them under the day.
        getGroup={descriptor.column === 'date' ? (row) => ({ id: row.date, label: row.dayLabel }) : undefined}
        selectedKeys={selected}
        onSelectionChange={setSelected}
        bulkActions={<ExportButton />}
        labels={{ total: 'Page total' }}
      />
      <Pagination
        page={page}
        pageCount={pageCount}
        rangeLabel={rangeLabel}
        getPageHref={(n) => hrefWith({ page: n === 1 ? null : String(n) })}
      />
    </SidePanelLayout>
  );
}
```

- Wrap the app once in a `RouterProvider` whose `navigate` is `router.push(href, { scroll: false })`, so the row links and the page links go through the router and the page never jumps.
- Opening a row from the list pushes an entry, so Back closes the panel. Close the panel the same way when your page pushed that entry: with `router.back()`, so no second entry with the list's URL is left for Back to land on. A row that arrived with the page, from a link or a reload, closes with `router.replace`. Opening another row while one is open replaces the open row's entry, so Back and Close still return to the list, as the example does:

```tsx
const opened = useRef<string | null>(null); // the entry this page pushed as it opened a row
const here = () => `${window.location.pathname}${window.location.search}`;

const navigate = (href: string) => {
  const before = new URLSearchParams(window.location.search).get('open');
  const after = new URL(href, window.location.href).searchParams.get('open');
  if (before !== null && after !== null && after !== before) {
    if (opened.current === here()) opened.current = href;
    router.replace(href, { scroll: false });
  } else {
    if (before === null && after !== null) opened.current = href;
    router.push(href, { scroll: false });
  }
};

const closePanel = (closedHref: string) => {
  if (opened.current === here()) {
    opened.current = null;
    router.back();
  } else {
    router.replace(closedHref, { scroll: false });
  }
};
```
- Set `--page-sticky-top` once to your header's height, on the AppShell or an ancestor, such as `style={{ '--page-sticky-top': '4rem' }}`. The table's header, the list's day headings and the panel stick under it.
- Start the `SidePanelLayout` right under your header, with the title, the filters, the table and the pager in its content, so the panel's footer is in view from the start. In an AppShell under 1440px, the open panel folds the rail to its icons, so the table keeps its columns.
- Pass `getGroup` only while the rows are sorted by date: only rows next to each other group.
- Strings are yours: the dates, the amounts, the day headings and the range. React Aria announces a sort and a change of selection in its own English words, even on a Persian page; the bar's count is yours, through `formatCount`.

The example below is the same page in a client component, since this site is static: it reads the URL in the browser, so here the open row's detail appears once scripts run, where an app's server page draws it at once. A 4rem header stands in for your app's, under this site's own, and the offset is both. Sort by amount, go to page 2 and open a row, then reload: the URL holds all three. While the panel is open this site folds its menu to its icons under 1640px, as AppShell folds an app's rail under 1440px, since the examples sit in a narrower column than an app's content.

## Usage

Render DataTable from a client component: its columns, keys and links are functions, which a server component cannot pass. Load the rows in a server page and pass them as data; a node a server rendered can reach a cell as a field of its row. Wrap the app in a `RouterProvider` once, so the row links go through your router. `currentKey` is compared with each row's key by strict equality, so a key read from the URL, which is a string, never matches a numeric key: convert it first, as `Number(params.get('open'))`. The row's link is stretched over the whole row, so text in a row cannot be selected by dragging across it; put text a reader copies in the detail the row opens. A control in a cell takes its own press above the row's link: a button, a link, an input, a label, a field, anything with a control role such as `checkbox`, `switch` or `menuitem`, and anything in the tab order. Give anything else that takes a press the class `data-table-control`. Set `--page-sticky-top` to your header's height on an ancestor, once for every sticky part of the page, so the table's header sticks under yours; this site sets it from its own header, which is why the examples' headers stop under it. A row that focus reaches keeps clear of the sticky header and of the bulk-action bar. The bulk-action bar sticks above `--app-shell-inset-block-end`, which AppShell sets for its bottom tab bar. A table inside an element of yours that scrolls, a frame, a panel or a pane, sticks its header inside that element: set `--page-sticky-top` to `0px` on it, unless your header scrolls inside it too, which DataTable cannot tell. Every string in the table is yours: the library formats no date, amount or count.

Both faces are in the page's HTML, so a page's weight grows with its rows: show about 50 rows a page, with [Pagination](/docs/components/pagination) under the table. Fifty rows of five columns, grouped by day, are about 130 kB of HTML for both faces, about 7 kB once compressed, as servers send it; 200 rows are about 480 kB, 20 kB compressed, and with selection on about 700 kB.

```tsx
'use client';

import { DataTable, EmptyState, type DataTableColumn } from '@snapshot-ui/react';

const columns: DataTableColumn<Transaction>[] = [
  { id: 'date', header: 'Date', cell: (row) => row.dateLabel, allowsSorting: true, width: '7rem' },
  { id: 'payee', header: 'Payee', cell: (row) => row.payee, isRowHeader: true },
  { id: 'category', header: 'Category', cell: (row) => row.category, hideBelow: 'md', listSlot: 'meta' },
  { id: 'amount', header: 'Amount', cell: (row) => row.amountLabel, align: 'end', total: '−$1,284.50', listSlot: 'end' },
];

export function Transactions({ rows, sort, openId }: TransactionsProps) {
  return (
    <DataTable
      aria-label="Transactions"
      items={rows}
      columns={columns}
      getKey={(row) => row.id}
      getRowHref={(row) => `?open=${row.id}`}
      currentKey={openId}
      // Sorted by date, so each day's rows are adjacent: the list groups them under the day.
      getGroup={sort.column === 'date' ? (row) => ({ id: row.date, label: row.dayLabel }) : undefined}
      sortDescriptor={sort}
      onSortChange={(next) => writeSortToUrl(next)}
      emptyState={<EmptyState title="No transactions this month" />}
    />
  );
}
```

## Accessibility

The table is a `grid` named by your `aria-label` or heading. Each header is a `columnheader`, with `aria-sort` on the sortable ones; the row header's cell is a `rowheader`, so a screen reader names each row by it. The current row's link is `aria-current`, and the row draws a bar and a bolder name, so the state is never color alone. React Aria announces a sort in its own words. While loading, the table is busy and a polite status outside it says "Loading" once; the skeletons are hidden from assistive technology. An error under the rows is a polite status too. A column whose header is hidden keeps its name. A row that focus reaches is scrolled clear of the sticky header and the bulk-action bar, so it is never hidden behind them. The table is one tab stop: no row link or checkbox is in the tab order, and the arrows reach them.

The list is a second `grid` of the same name, shown where the table is not, so a screen reader meets one; each day is a `rowgroup` named by its heading, and each item is named by its row's name and described by its second line and its end, so a screen reader hears the category and the amount too. With selection on, the list's Select button is a plain button whose name says what it does next, Select or Done, and focus stays on it when it is pressed; its items say whether they are selected whether their boxes show or not. On a touch screen Select, Done and Select all are 44px tall. A table or list with no rows takes focus itself and draws the ring. The list has no typeahead at all, so every letter reaches the page.

With selection on, the grid is multiselectable and each row says whether it is selected. The header checkbox is named "Select all" and a row's "Select" followed by the row's name, such as "Select Corner Mart". The bar is a toolbar named "Bulk actions". React Aria announces each selection change in its own English words, and the bar's polite status says the count in yours, once the selection has held for a moment, so a run of X presses is said once. Letters never move focus: J and K move as the arrows, X toggles, and every other letter does nothing, on any keyboard layout.
