## Basic

A float panel centred on the scrim, with 16px clear on every side. From the top: an optional icon well, the title, a description, a body and an action row. Each part shows only when given. The `title` is required and renders as an `h2` in the card title step.

## Danger

`tone="danger"` tints the icon well with error, for a question that loses something. It changes only the well. The actions are yours: end the row with a tertiary Cancel, then a danger Button.

## Long content

A tall body scrolls inside the panel, and the head and action row stay put.

- A scrolling body with nothing to focus, such as a page of terms, is its own Tab stop so the keyboard can scroll it.
- `hasCloseButton` adds an X in the top end corner, for a long dialog. Escape and the scrim already close it.
- `size="lg"` widens the panel from 28rem to 40rem. Both widths are capped at the screen less 2rem.

## Usage

Open a dialog from a `DialogTrigger`, which holds the button and the dialog. Or control it with `isOpen` and `onOpenChange`, or start it open with `defaultOpen`. Dialog is a client component, and a server component can render it, as the examples here do. To close it, use a button with `slot="close"`, or pass `children` and `actions` as functions that receive `close`.

For input, put a form with an `id` in `children`, and its submit button in `actions`, linked by the button's `form` attribute. The button and Enter in a field both submit. The form's `onSubmit` reads the values, does the work and closes the dialog:

```tsx
'use client';

import { Button, Dialog, DialogTrigger, TextField } from '@snapshot-ui/react';
import { useId } from 'react';

export function RenameWorkspace({ name, onRename }: { name: string; onRename: (name: string) => void }) {
  const formId = useId();
  return (
    <DialogTrigger>
      <Button variant="secondary">Rename the workspace</Button>
      <Dialog
        title="Rename the workspace"
        description="The new name shows in the header and in every invite."
        actions={
          <Button type="submit" form={formId}>
            Rename
          </Button>
        }
      >
        {({ close }) => (
          <form
            id={formId}
            onSubmit={(event) => {
              event.preventDefault();
              const next = new FormData(event.currentTarget).get('name');
              if (typeof next === 'string') onRename(next);
              close();
            }}
          >
            <TextField label="Workspace name" name="name" defaultValue={name} isRequired />
          </form>
        )}
      </Dialog>
    </DialogTrigger>
  );
}
```

The body and action row are not exported. Everything in `children` lands in the body, so buttons there scroll away. `actions` is the one row that stays in view.

- Stacking: a dialog opened from a dialog stacks over it, such as a confirm over the form it guards. One scrim shows, Escape closes the top one, and focus returns to the first.
- Theme: a dialog takes the theme, shape and density of what opened it, so one opened from a dark card is dark on a light page. See [Theming](/docs/theming#overlays).
- Layering: dialogs do not use the browser's top layer. `--z-modal` (1000) orders modal surfaces and their scrims, and `--z-toast` (1100) the toast region above them. Raise both if your app's chrome uses larger numbers. A third-party overlay with a very large z-index can still cover a dialog.
- Focus after removal: when the action removes the button that opened the dialog, such as deleting a row, move focus yourself to the next row or the list.

## Accessibility

The dialog is named by its title and described by its description. On open, focus moves to the dialog, or to a control inside that requests it, and Tab stays inside. On close, focus returns to the button that opened it. While open, the page behind is hidden from assistive technology and does not scroll.
