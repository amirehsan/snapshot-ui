## Shapes

A `line` is the height of one line of the text it stands for and fills its holder's width; a `block` is a field tall; a `circle` is 40px, the size of a target. Set `width` and `height` as CSS lengths, such as `12rem` or `60%`.

## A card that is loading

Draw the shape of what is coming: a circle and two lines for a header, a block for the body. When the content arrives it takes the same room, so nothing on the page moves.

## Usage

Skeleton is static. It renders in a server component and ships no client JavaScript. It is hidden from assistive technology, so say "Loading" once in your own status, as the data table does, and mark the holder `aria-busy`. Keep the status outside the busy holder and mounted all the time, and give it its text when loading starts: a screen reader may hold back what changes inside a busy part, and a live region that appears with its text already in it is often not announced. Size each shape as the content it stands for. The shape pulses gently, and stands still when the reader asks for reduced motion.

```tsx
import { Skeleton } from '@snapshot-ui/react';

export function LoadingRow({ isLoading }: { isLoading: boolean }) {
  return (
    <>
      {/* Your app's visually hidden class: the library ships none. */}
      <p role="status" className="visually-hidden">
        {isLoading ? 'Loading' : ''}
      </p>
      <div aria-busy={isLoading}>
        <Skeleton shape="circle" />
        <Skeleton width="60%" />
      </div>
    </>
  );
}
```

## Accessibility

A skeleton is `aria-hidden`, holds no text and takes no focus. Saying that the page is loading is the holder's job: one polite status, outside the busy part and always mounted, that says "Loading", and `aria-busy` on the part that is loading. In forced colors the shape keeps a fill of its own, so it does not vanish.
