## Basic

A [Dialog](/docs/components/dialog) that asks one question with two answers: Cancel, then a confirm button that names what it does. The title asks, and the required description says what will happen. Only the confirm button means yes. Escape, a press on the scrim and Cancel all mean no.

Use the default tone when the answer loses nothing, even if it cannot be taken back, such as sending an invoice. The confirm button is primary and takes focus on open.

## Danger

Use `tone="danger"` when the answer loses something: data, money or work. It shows the warning triangle in the error well and the danger Button, and focus starts on Cancel, the safe answer. `icon` replaces the triangle. Name the outcome on the confirm button, such as Delete the workspace, never OK.

The tone is required. A destructive question shown as harmless is the costly mistake, and a harmless one shown as destructive teaches people to ignore the warning.

## Asking from code

`useConfirm()` asks from an event handler. `confirm(options)` opens the dialog and returns a promise that is `true` only when the confirm button is pressed. Render `dialog` once, in the component that asks. It is `null` until the first question.

- Silence is never yes. A second question over an open one answers the first no. Unmounting answers an open question no, and so does a question asked after unmount.
- Questions asked back to back, over an open one or chained after an answer, are one run. Each opens in the theme of the button that asked first and starts on its own answer. After the last answer, focus returns to that button.
- The hook has no pending state. Show the work after a yes in your own interface, or render a `ConfirmDialog` directly with `onConfirm`.

When the action removes the button that asked, such as a row's Delete, focus has nowhere to return. Move it yourself after the action. This example moves it to the row that takes the removed row's place.

## Usage

Open a confirm dialog from a `DialogTrigger`, or control it with `isOpen` and `onOpenChange`, as with Dialog. Inside a `DialogTrigger`, put `onOpenChange` on the trigger. On the dialog it is not called, and the library warns once.

`onConfirm` runs when the confirm button is pressed, and `onCancel` on every other way out. When `onConfirm` returns a promise, the dialog is pending until it settles:

- The confirm button shows its spinner and keeps its label. Cancel is disabled, and Escape and the scrim do nothing.
- On resolve, the dialog closes.
- On reject, it stays open and leaves the pending state so the question can be answered again. The error goes to `reportError`, as if uncaught.
- `isPending` shows the same state for work you track yourself. The dialog stays open until you close it.
- `pendingLabel` names the spinner and is read with the confirm label. Use the outcome's verb, such as Deleting.

```tsx
'use client';

import { Button, ConfirmDialog, DialogTrigger } from '@snapshot-ui/react';

export function DeleteWorkspace({ onDelete }: { onDelete: () => Promise<void> }) {
  return (
    <DialogTrigger>
      <Button variant="danger">Delete the workspace</Button>
      <ConfirmDialog
        tone="danger"
        title="Delete the workspace?"
        description="Its 12 projects and their history go with it. This cannot be undone."
        confirmLabel="Delete the workspace"
        onConfirm={onDelete}
      />
    </DialogTrigger>
  );
}
```

A press on the scrim cancels. For a question that must be answered, set `isDismissable={false}`. Escape still cancels.

## Accessibility

An `alertdialog`, named by its title and described by its description, so both are read on open. Focus starts on Cancel in the danger tone and on the confirm button in the default tone. Tab moves between the two buttons, and on close focus returns to the button that opened it. While pending, the confirm button's name is its label then the spinner's, such as Delete 3 transactions Deleting, and React Aria announces it.
