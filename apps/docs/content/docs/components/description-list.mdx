## Layouts

A list of named values: each row is a term, its value and, if it has any, the row's actions. The list's own width decides the layout, not the screen's. From 30rem of the list's width the terms sit in a column beside their values, and under it each term stands above its value. A list beside a side panel or in a narrow card stacks on a wide screen, and every list stacks on a phone.

The list is a size container, so it takes its width from its column, never from its content, and has no width of its own to give. A block, a `flex: 1` item or a `1fr` grid track gives it one. A holder that sizes it from its content, such as a flex item without `flex: 1`, `width: max-content` or an `auto` grid track, must give it a width, or it draws nothing wide.

```css
.details {
  flex: 1;
}
```

`layout` holds one layout at every width: `horizontal` or `stacked`. The term column is 30% of the row, which holds "Routing number" on one line from 30rem; set `--description-list-term-size` on the list for a wider or narrower one. Rows follow density, and a rule separates each row from the next.

## Actions

`actions` puts a row's controls in a cell of their own after the value: at the end of the row side by side, and at the end of the term's line when stacked. Name each control with its term, as GOV.UK names its "Change" links: it shows "Edit" and reads "Edit Nickname", with `aria-label` or visually hidden words. The name starts with the word it shows, so voice control finds it. A value that is missing takes no action beside "Not set": pass a link to add it as `emptyValue`, so it stands where the value would.

A status is a value too. Put its word in a [Badge](/docs/components/badge) and the fix in a link after it: a bank feed that failed to sync is a failure, so its Badge is `error`, and an account that is open is neutral, never `success`, which means a save.

## Empty, long and numeric values

A value that is absent, `null`, `false`, `true`, an empty string, or an array of nothing but those shows "Not set" in slate. Pass `emptyValue` for your own words, or a link to add the value, as GOV.UK's summary list does: the link stands where the value would, and the row has no action of its own. `0` is a value.

A long value wraps, and a long unbroken word, such as an IBAN or an email address, breaks anywhere inside its column. Nothing is cut off with an ellipsis.

Set `isNumeric` on amounts, limits, percentages and the last four digits of a card: tabular figures, read left to right and starting at the line's start, on a Persian page too.

## In a card

Make the list a card's body for an account's details. A row whose controls would sit in the card's rounded corner, the last row of a list that ends the card or the first of one that starts it, grows by the card's corner inset, so its controls stand clear of the curve and stay on the column's end edge. The list does this itself: 7px more in Rounded, nothing in Soft and Square. It does so in a card's body, directly in a card, and at the end of a [collapsible card](/docs/components/collapsible-card)'s body. Stacked, the last row's controls stand on the term's line at the row's top, clear of the curve, so the row keeps its spacing.

## The Accounts recipe

An app's account pages, from the list to a card's credit tab, built from the library's parts. The example below is one client component, since this site is static: the three pages are `?account=` and `&tab=credit` on this page's URL, read with `useSearchParams` inside a `Suspense` and opened through a [RouterProvider](/docs/routing) whose `navigate` is `router.push(href, { scroll: false })`.

- **Accounts.** Four [StatTiles](/docs/components/stat-tile) sum up cash, investments, what is owed and net worth, with its change in words. Under them a [DataTable](/docs/components/data-table) per type lists each account: the bank's [Avatar](/docs/components/avatar), its name and last four digits, which statements you hold, the bank feed as a neutral Badge, or an error Badge and a Reconnect link when it failed, a warning Badge for a possible duplicate, and the balance with its date. Each row opens its account.
- **An account.** A [PageHeader](/docs/components/page-header) with its trail, the balance as a [LineChart](/docs/charts/line-chart), and the Details card: the list as its body and, in its header, Edit and a More menu ([CardActions](/docs/components/card#actions-in-the-header), at most two visible). Edit opens a [Dialog](/docs/components/dialog) to set a nickname; the empty Nickname row's "Add a nickname" opens the same form. More holds Merge, a Dialog, and Remove, a [ConfirmDialog](/docs/components/confirm-dialog) in the danger tone. Closing a dialog gives focus back to the button that opened it, and to Edit once a saved nickname has replaced the add link; removing the account opens the list with focus on its heading, never the page's body. Opening another page, an account from the list, the list from the trail, gives that page's heading focus; a tab keeps it on the tab.
- **Credit**, a card's second tab. The score is a [Gauge](/docs/components/gauge): an `lg` semicircle on 300 to 850, its figure and its word, and marks at 580, 670, 740 and 800. The range's ends under it are the app's text, hidden from assistive technology since the meter reports the range, and a legend of the five bands follows. Fair and Poor are both `warning`, never `error`, which means something failed: the word under the figure and the arc's place between the marks tell them apart. Utilization is an `md` ring with its two thresholds in words, and under it a table of the cards with a 32px ring on each row, whose marks carry no words, so the thresholds are said once above the table. Statement coverage is a [MonthGrid](/docs/components/month-grid) in a card, with its sentence and its hidden table.

In an app the account's page is a server component: the header, the Details card and its list, the gauges and the month grid render there with no client JavaScript, and the chart's svg and table render there too. Only the leaves that hold state are client components: the chart's keys and readout, the tables, the tabs, Edit's Dialog, the More menu and its dialogs. The server formats every figure, date and word, in the reader's language, before it reaches a part.

```tsx
// app/accounts/[id]/page.tsx, a server component.
<Card as="section" aria-labelledby="details-title">
  <CardHeader>
    <CardTitle id="details-title" level={2}>
      Details
    </CardTitle>
    <CardActions>
      {/* 'use client' leaves: each opens its own Dialog. */}
      <EditDetails account={account} />
      <MoreActions account={account} />
    </CardActions>
  </CardHeader>
  <CardBody>
    <DescriptionList>
      <DescriptionListItem term="Name">{account.name}</DescriptionListItem>
      <DescriptionListItem term="Last four" isNumeric>
        {account.lastFour}
      </DescriptionListItem>
      <DescriptionListItem term="Credit limit" isNumeric>
        {format.money(account.creditLimit)}
      </DescriptionListItem>
    </DescriptionList>
  </CardBody>
</Card>
```

## Usage

The list is static: a server component renders it with no client JavaScript. It is composed, so a value can be any node, such as a Badge or a link, and each row takes its own props. A `DescriptionListItem` belongs in a `DescriptionList`: on its own it is a `div` of a `dt` and `dd` with no list around them, which is invalid HTML. The library writes "Not set" in English, so a page in another language passes its own `emptyValue`, or wraps `DescriptionListItem` in a component that does.

```tsx
import { DescriptionList, DescriptionListItem, Link } from '@snapshot-ui/react';

<DescriptionList>
  <DescriptionListItem term="Name">Everyday Visa</DescriptionListItem>
  <DescriptionListItem term="Credit limit" isNumeric>
    $5,000.00
  </DescriptionListItem>
  <DescriptionListItem
    term="Nickname"
    emptyValue={<Link href="/accounts/visa/nickname">Add a nickname</Link>}
  />
</DescriptionList>;
```

## Accessibility

The list is a real `dl`, each row a `div` holding a `dt` and its `dd`s, which the HTML standard allows. No role is added: `role="list"` would drop the term and definition semantics. VoiceOver announces a description list and its terms; NVDA and JAWS announce less, and every reader reads each term and its value in order. Tab moves through the rows' actions in reading order; the list has no keys of its own. Name each action with its term, so a list of Edits reads as Edit Name, Edit Nickname.
