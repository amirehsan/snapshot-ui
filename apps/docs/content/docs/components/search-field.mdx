## Basic

Pass a label, and a hint if the label cannot say it all. The placeholder shows what the field searches and never replaces the label. Once there is text, a clear button shows at the end; while the field is empty it leaves, so there is no stray target. Escape clears the text too, and Enter submits it to `onSubmit`.

## In a toolbar

Above a list there is often no room for a label row. Name the field with `aria-label` and give it a placeholder that says what it searches. With no visible label the placeholder is the only words a sighted reader gets, so it is drawn in slate rather than the quieter taupe: it is the one place a placeholder is read, the exception the command palette's field also makes.

## States

A disabled field is recessed and its magnifier turns taupe. An invalid field draws the error edge and its error line. There is no changed state: a query is not saved data, so it is never unsaved.

## Usage

Keep the query in the URL, so a search can be shared, reloaded and gone back to. Keep the text being typed in state, pass it as `value`, and write the URL after a pause of your own in `onChange`. Take the query again whenever the URL changes under the field, as Back and Forward do, and read the URL as it is when the pause ends, so a tab or a page chosen meanwhile is kept. With the Next App Router:

```tsx
'use client';

import { useEffect, useRef, useState } from 'react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { SearchField } from '@snapshot-ui/react';

export function TransactionSearch() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const q = searchParams.get('q') ?? '';
  const [text, setText] = useState(q);
  // The query the field last took from the URL, or last wrote to it.
  const [seen, setSeen] = useState(q);
  const pause = useRef<ReturnType<typeof setTimeout>>(undefined);

  // The URL changed under the field, by Back, Forward or a link: show its query.
  if (q !== seen) {
    setSeen(q);
    setText(q);
  }

  useEffect(() => () => clearTimeout(pause.current), []);

  return (
    <SearchField
      aria-label="Search transactions"
      placeholder="Search transactions"
      value={text}
      onChange={(next) => {
        setText(next);
        clearTimeout(pause.current);
        pause.current = setTimeout(() => {
          // The parameters as they are now, not as they were at the keystroke.
          const params = new URLSearchParams(window.location.search);
          if (next) params.set('q', next);
          else params.delete('q');
          const query = params.toString();
          setSeen(next);
          router.replace(query ? `${pathname}?${query}` : pathname);
        }, 300);
      }}
    />
  );
}
```

On a statically rendered route, `useSearchParams` needs a `Suspense` boundary: render the search inside `<Suspense>`, or the build stops and asks for one.

For a search that runs only on Enter, such as one that queries a slow service, write the URL in `onSubmit` and in `onClear` instead, and let `onChange` keep only the text. Start from the parameters already there, so the tab, the page and the filters stay:

```tsx
export function TransactionSearchOnEnter() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const q = searchParams.get('q') ?? '';
  const [text, setText] = useState(q);
  const [seen, setSeen] = useState(q);

  if (q !== seen) {
    setSeen(q);
    setText(q);
  }

  const search = (next: string) => {
    const params = new URLSearchParams(searchParams);
    if (next) params.set('q', next);
    else params.delete('q');
    const query = params.toString();
    router.push(query ? `${pathname}?${query}` : pathname);
  };

  return (
    <SearchField
      aria-label="Search transactions"
      placeholder="Search transactions"
      value={text}
      onChange={setText}
      onSubmit={search}
      onClear={() => search('')}
    />
  );
}
```

The field has no debounce of its own. How long to wait, and whether to wait at all, belongs to the app's router and its data fetching, which already know what a request costs; a pause hidden inside the field would be a second timer the app cannot see.

## Accessibility

A native input of type `search`, so a `searchbox`, named by its label or by `aria-label` and described by the hint and the error line. The clear button is named "Clear search", or `clearLabel`, and is out of the tab order, because Escape does the same from the field; a press clears the text and leaves focus in the input. The magnifier is hidden from assistive technology.
