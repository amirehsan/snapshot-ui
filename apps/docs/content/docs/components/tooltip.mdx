## Basic

A tooltip is a short ink label with canvas text that names an icon button, or adds a hint to a control, beside it. It shows after the pointer rests on its trigger for 400ms, and at once when the trigger takes focus from the keyboard. It sits 12px from the trigger, above it by default, with a small arrow pointing at it, and flips to the other side where the screen has no room. Long text wraps at 20rem.

## With a shortcut

`shortcut` draws a key after the text, such as `Mod K`, in the one key look, inverted for the ink: `Mod` is Cmd on Apple platforms and Ctrl elsewhere. `placement="end"` puts the tip after the trigger, as a collapsed navigation rail shows its names.

## Usage

Wrap the trigger and the tip in `TooltipTrigger`. The trigger must be focusable and take React Aria's hover and focus, as `Button`, `IconButton` and `Link` do; a static element, such as an icon in a sentence, needs React Aria's `Focusable` around it, and a disabled control cannot take focus, so it gets no tip. TooltipTrigger and Tooltip are client components, and a server component can render them, as the examples on this page do. A tip forced open with `isOpen` or `defaultOpen` is drawn only in the browser: the server's HTML gives the trigger a description that points at a tip it does not hold until the page hydrates.

The tip opens after 400ms of hover (`delay`) and closes 120ms after the pointer leaves (`closeDelay`), so the pointer can cross onto the tip and rest there. Once one tip has opened, the next opens at once for about half a second after it starts to close, so moving along a row of buttons shows each name without a wait. Escape, a press of the trigger, a scroll of a box around it and a resize of the window close it. Set `isDisabled` while the label is visible anyway, as a navigation rail does when it is expanded. `isOpen`, `defaultOpen` and `onOpenChange` control it.

A tooltip never shows for touch, which has no hover, so nothing a touch user needs may live only in a tip. A tip opened from a dark card is dark while the page stays light: it takes the theme, the shape and the density of its trigger, as [Theming](/docs/theming#overlays) explains.

## Accessibility

A tooltip is supplementary. While it is open it is the trigger's description, so a screen reader reads it after the trigger's name; on an icon button it mirrors the `aria-label`, which a screen reader may read twice. It is never the only name of anything: an icon button keeps its `aria-label`. The tip never takes focus. Whether the repeated name reads well is still to be checked with VoiceOver and NVDA; if it does not, the fallback is to hide such a tip from assistive technology, since a tip that only repeats a name adds nothing to it.
