## Basic

A short ink label that names an icon button or adds a hint to a control. It shows after the pointer rests on its trigger for 400ms, and at once on keyboard focus. It sits 12px above the trigger by default, with a small arrow, and flips to the other side when there is no room. Long text wraps at 20rem.

## With a shortcut

`shortcut` shows a key after the text, such as `Mod K`. `Mod` is Cmd on Apple platforms and Ctrl elsewhere. `placement="end"` puts the tip after the trigger, as a collapsed navigation rail shows its names.

## Usage

Wrap the trigger and the tip in `TooltipTrigger`. The trigger must be focusable and take React Aria's hover and focus, as `Button`, `IconButton` and `Link` do.

- A static element, such as an icon in a sentence, needs React Aria's `Focusable` around it.
- A disabled control cannot take focus, so it gets no tip.
- A tooltip never shows for touch, so nothing a touch user needs may live only in a tip.

The tip opens after 400ms of hover (`delay`) and closes 120ms after the pointer leaves (`closeDelay`), so the pointer can cross onto it. Once one tip has opened, the next opens at once for about half a second, so moving along a row of buttons shows each name without a wait. Escape, a press of the trigger, a scroll of a box around it, or a window resize closes it. `isOpen`, `defaultOpen` and `onOpenChange` control it. Set `isDisabled` while the label is visible anyway, as an expanded navigation rail does.

TooltipTrigger and Tooltip are client components, and a server component can render them, as the examples here do. A tip forced open with `isOpen` or `defaultOpen` renders only in the browser. Until the page hydrates, the server's HTML gives the trigger a description that points at a tip it does not hold.

A tip takes the theme, shape and density of its trigger, so one opened from a dark card is dark while the page stays light. See [Theming](/docs/theming#overlays).

## Accessibility

A tooltip is supplementary. While open, it is the trigger's description, read after the trigger's name. It is never the only name of anything, so an icon button keeps its `aria-label`. The tip never takes focus.

On an icon button the tip repeats the `aria-label`, which a screen reader may read twice. This is not yet checked in VoiceOver and NVDA. If it reads badly, such tips will be hidden from assistive technology, since a repeated name adds nothing.
