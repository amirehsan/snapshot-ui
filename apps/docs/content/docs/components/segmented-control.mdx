## Basic

Pass a label, and the options as children, each with its own `value`. The chosen option is the ink pill. A segmented control is for a few short options that are all worth seeing at once. For more, or for options that need explaining, use a list.

## States

The track's edge carries the state, as in every field. A changed control gets a light signal orange edge and a clay chip beside its label. An invalid control gets the error edge and an error line, and invalid outranks changed, so the chip steps aside. A disabled control is recessed, and its chosen option stays in view as a quiet taupe pill. A single option can be disabled on its own, with `isDisabled` on its item, and the rest stay open. The compact size, `sm`, draws 32px options in a 40px track and still hits each one at 40px.

## Stacking

The options are all in one row or all in a column, never some of each. When the row does not fit the room the control has, it stacks one option per row, each 40px tall. When the room comes back, the row does too. The control compares its own row with its own width, so give it a column to fill, as you would a text field. A control sized to its content, in a flex row or a centered grid, has no room to compare with and never stacks. Stacking is decided in the browser, so before the page hydrates, or with scripts off, a row that does not fit overflows its root. Give the control's spacing outside it, as a margin or a wrapper: horizontal padding added to the root through `className` makes the room the control measures wider than the room its track has.

## Usage

Every value works controlled and uncontrolled, and a control with a `name` submits the chosen `value` in a plain form. `onChange` receives the value. A `value` of `null` is a controlled control with nothing chosen.

```tsx
import { useState } from 'react';
import { SegmentedControl, SegmentedControlItem } from '@snapshot-ui/react';

export function Appearance({ saved }: { saved: string }) {
  const [mode, setMode] = useState(saved);
  return (
    <SegmentedControl
      label="Appearance"
      name="appearance"
      value={mode}
      onChange={setMode}
      isChanged={mode !== saved}
    >
      <SegmentedControlItem value="light">Light</SegmentedControlItem>
      <SegmentedControlItem value="dark">Dark</SegmentedControlItem>
      <SegmentedControlItem value="system">System</SegmentedControlItem>
    </SegmentedControl>
  );
}
```

Without a visible label, name the control with `aria-label`, as a toolbar's switch is named by what it sits beside. One of the two is required.

## Accessibility

A native radio group: each option is a radio, the control is named by its label, and React Aria handles the wiring. A screen reader reads the Changed chip with the control, after the hint, while the control is changed and valid. An invalid control reads its error line alone. The group is one tab stop, and focus lands on the chosen option, unless that option is disabled (see below).

<Keys rows={[['Tab', 'Moves focus into the control, onto the chosen option, or the first when nothing is chosen.'], ['Right Down', 'Chooses the next option, and wraps from the last to the first.'], ['Left Up', 'Chooses the previous option, and wraps from the first to the last.'], ['Space', 'Chooses the focused option.']]} />

The 2px ring sits outside an option that is not chosen. On the chosen option, which is an ink fill, the ring is drawn inside it in the canvas color, so it still reads. A disabled option is skipped by the arrow keys. A read-only control keeps its choice and takes no hover wash. Do not disable the chosen option of a control the reader can still change: React Aria gives the tab stop to the chosen option alone and takes it from a disabled one, so Tab skips the control.
