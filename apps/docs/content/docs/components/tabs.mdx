## Basic

A row of pills over one panel per tab. Give each `Tab` and its `TabPanel` the same `id`. Only the selected panel is mounted. The arrow keys select as they move (automatic activation), since showing a panel already in the page is instant.

## Tabs that are links

When each view has its own URL:

- Give each `Tab` an `href`.
- Pass `selectedKey` from the URL, and no `onSelectionChange`. The selection moves when the route does.
- Set `keyboardActivation="manual"`. The arrows move focus without loading a route, and Enter, Space or a press follows the link through `RouterProvider`.
- Render one `TabPanel` whose `id` is the selected key, holding the route's content, so `aria-controls` points at it.

A modified or middle click opens the link as the browser would.

<Preview name="tabs-links" />

Tabs are for views of one page. For top navigation between whole pages, use plain links with `aria-current="page"` instead.

## Unsaved edits

Set `isChanged` to show a clay dot after the name of a tab whose panel holds unsaved edits. Use it for nothing else: clay means unsaved. A screen reader reads "Changed", or your `changedLabel`, after the tab's name. On the selected ink pill the dot gets a canvas ring so it stays visible.

For a count or a "new" marker, put a `Badge` in the tab's name. It takes the tab's color, so it reads on the ink pill and on hover.

## A row that does not fit

The row scrolls inside its track, and the page never scrolls sideways. Keep names short and this rarely shows.

- A focused tab scrolls into view, as the browser does for focus.
- After hydration, the row scrolls itself (never the page) to the selected tab. The server's HTML shows the start of the row.
- It also scrolls when the selection moves while the selected tab is not focused, as Back does with link tabs.
- A row mounted hidden waits until it is shown.

## Usage

Keep the view in the URL so it can be shared, reloaded and reached with Back. With the Next App Router, the server page reads the search parameter and passes it to a client component that renders the tabs. The route's content goes in the one panel:

```tsx
// app/transactions/page.tsx, a server component
import { TransactionList } from './transaction-list';
import { TransactionViews } from './transaction-views';

const VIEWS = ['all', 'spending', 'income'];

export default async function TransactionsPage({ searchParams }: { searchParams: Promise<{ view?: string }> }) {
  const { view = 'all' } = await searchParams;
  const current = VIEWS.includes(view) ? view : 'all';
  return (
    <TransactionViews view={current}>
      <TransactionList view={current} />
    </TransactionViews>
  );
}
```

```tsx
// app/transactions/transaction-views.tsx
'use client';

import type { ReactNode } from 'react';
import { Tab, TabList, TabPanel, Tabs } from '@snapshot-ui/react';

export function TransactionViews({ view, children }: { view: string; children: ReactNode }) {
  return (
    <Tabs selectedKey={view} keyboardActivation="manual">
      <TabList aria-label="Transactions">
        <Tab id="all" href="?view=all" routerOptions={{ scroll: false }}>
          All
        </Tab>
        <Tab id="spending" href="?view=spending" routerOptions={{ scroll: false }}>
          Spending
        </Tab>
        <Tab id="income" href="?view=income" routerOptions={{ scroll: false }}>
          Income
        </Tab>
      </TabList>
      <TabPanel id={view}>{children}</TabPanel>
    </Tabs>
  );
}
```

The links go through the `RouterProvider` at the app's root, set up in [Routing](/docs/routing), so each tab is a soft navigation.

- `routerOptions={{ scroll: false }}` stops Next's router from scrolling to the top of the segment on every push.
- If the URL has other parameters, such as a search or a page number, build each `href` from them so choosing a view keeps them.

## Accessibility

A `tablist` of `tab`s with `aria-selected`, named by `aria-label` or `aria-labelledby` on the `TabList`. Each `tabpanel` is named by its tab.

- A panel with nothing focusable is itself the next Tab stop after the row.
- The changed dot is hidden and read as the tab's description, so the tab's name is unchanged.
- Link tabs keep the tab roles and arrow keys. With manual activation, a key press never loads a page.
- A disabled tab is skipped by the arrows and cannot be selected.
