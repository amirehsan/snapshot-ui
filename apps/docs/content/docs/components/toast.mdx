## Tones

A toast reports an event that just happened, such as a save. It shows in the bottom end corner, 16px in, above every dialog.

- Tone: a 4px stripe at its start, in slate for `info`, or in `success`, `warning` or `error`.
- Text: a title says what happened, and an optional second line in slate says more.
- Timing: it leaves after 6 seconds, or 12 for an error. Its X dismisses it sooner.
- Stacking: the newest sits nearest the corner. Three show at once, and a fourth hides the oldest until one leaves.

## With an action

A toast can offer one action, such as Undo, as a secondary button before its X. A toast with an action stays until the action is used or the toast is dismissed, so the reader has time to reach it. The action runs, then the toast closes.

## Usage

Mount `<ToastRegion />` once at the app root, beside your client providers, as this site does in its docs layout. Then call `toast()` from any client code: a press handler, an effect, or the line after a server action returns. `tone` is required. The title and second line are text that a status region reads out, so never put a link or button in them. Use `action` for the toast's one control.

```tsx
'use client';

import { Button, toast } from '@snapshot-ui/react';
import { saveBudget } from './actions';

export function SaveBudget({ budget }: { budget: Budget }) {
  return (
    <Button
      onPress={async () => {
        // A new save starts, so the last result is stale.
        toast.clear();
        const result = await saveBudget(budget);
        toast(
          result.ok
            ? { title: 'Saved', tone: 'success' }
            : { title: 'The budget was not saved', description: result.message, tone: 'error' },
        );
      }}
    >
      Save
    </Button>
  );
}
```

Toasts follow the page's theme and corners, not the scope around the button that raised them, since a toast reports on the app. See [Theming](/docs/theming#overlays).

- `toast()` returns the toast's id, and `toast.dismiss(id)` closes that toast.
- `toast.clear()` drops every toast, errors included. Call it when a new save starts, since the last result is stale.
- `timeout` sets milliseconds, or `null` (or zero) to stay until dismissed. The defaults are 6 seconds, 12 for an error, and no timeout with an action.
- Hovering or focusing the toasts pauses every timer, including for a toast that arrives meanwhile. The timers restart when both pointer and focus leave.
- With no region mounted, a toast shows nothing and the console warns once. A second region also warns, since it would show and announce every toast twice.

Say the outcome in the title, in words. The stripe only repeats it, and in Windows high contrast it is repainted in the text color. Keep one toast with an action at a time: since three show at once and action toasts stay, extra ones push the oldest Undo out of sight. When a newer action replaces an older one, dismiss the older one, as the example above does.

## Accessibility

The toasts sit in a landmark region that F6 reaches from anywhere. It is named by React Aria's localized count of notifications unless `aria-label` names it. Each toast is a non-modal alert dialog, named by its title and described by its second line.

- An error is announced assertively, as an alert.
- Other tones are announced politely through a status region that `ToastRegion` renders before any toast. Each toast is announced once, even when its words repeat. A screen reader only reliably announces a live region that was already there.
- Toasts stay pressable and announced while a dialog is open, and pressing one never closes the dialog.
- When a focused toast leaves, focus moves to the next toast, or back to where it was.
- With reduced motion, a toast appears without its rise.
