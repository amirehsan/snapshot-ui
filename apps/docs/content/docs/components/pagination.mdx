## Links from a server page

The row shows your formatted range, then Previous, the first page, the current page with one page each side, the last page, gaps for the rest, and Next.

Pass `getPageHref` and every control is a link it builds. Pagination has no client directive, so a server page can render it and pass the function. Only the links and the status region are client components. In an app, the server page reads `searchParams.page` and formats the range. The docs are static, so this example reads the page from the URL in the browser.

## Buttons

Pass `onPageChange` instead of `getPageHref` and every control is a button that calls it with its page. Pressing the current page calls nothing. Use button mode from a client component, since a function cannot pass from a server page to the client.

## Narrow

The row responds to its own width, not the viewport's, so a narrow column on a wide page narrows too.

- Under 36rem: the step words hide but remain the steps' names.
- Under 30rem: the numbers and gaps hide too, leaving Previous, the range and Next, with two 40px targets.

`hasPageNumbers={false}` gives the short row at every width.

## In a row

Pagination works as a plain item in any parent, with no wrapper:

- In a block, or a grid column sized with `fr`, it fills the width.
- In a flex row, wrapping or not, it takes the room its siblings leave, so a link such as "Show 100 a page" keeps its own width at the end.
- In a column sized by its content, such as a grid column of `auto` or a parent of `width: fit-content`, it is as wide as the narrow row: the range between the two steps. Give that column `minmax(0, 1fr)` for the full row.

On a phone it narrows with the row it is in, never below the range's longest word between the steps, and the range wraps between words.

## More siblings

`siblingCount` sets how many pages show each side of the current one, 1 by default. Since the step words hide under 36rem, the numbers still fit just above 30rem. Here two siblings each side fit in a 30.5rem column. If the row is still wider than the nav, as with many siblings on a phone's larger controls, the list wraps to the end of the row instead of scrolling the page sideways.

## Page size

Pass `pageSize` and `onPageSizeChange` together and the row starts with a rows-per-page picker, labelled "Rows per page" (`labels.pageSize`), with the page controls at its end. It offers 10, 25, 50 and 100 rows, or your `pageSizeOptions`, written with `pageLabel` like the page numbers. `onPageSizeChange` gets the size chosen and the page that holds the first row of the current page at that size, so the reader keeps their place: page 3 at 25 a page starts at row 51, which is on page 6 at 10 a page. Set both, and write the new range, which is announced once it settles.

The picker is the library's [Select](/docs/components/select), with a visible label. Where the row is narrow it takes a line of its own above the steps, and a right-to-left page puts it at the right. It calls your function, so render Pagination from a client component to show it, in link mode or button mode; from a server page, render it without a picker, or move it into a client component, as this example and the [Transactions recipe](/docs/components/data-table#the-transactions-recipe) do. The size belongs in the URL beside the page:

```tsx
'use client';

const SIZES = [10, 25, 50, 100];
const DEFAULT_SIZE = 25;

function Pages({ page, size, total }: { page: number; size: number; total: number }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  // The URL with some parameters changed; the defaults write none, and a bare ? is never written.
  const hrefWith = (changes: Record<string, string | null>) => {
    const params = new URLSearchParams(searchParams);
    for (const [name, value] of Object.entries(changes)) {
      if (value === null) params.delete(name);
      else params.set(name, value);
    }
    const query = params.toString();
    return query ? `${pathname}?${query}` : pathname;
  };
  return (
    <Pagination
      page={page}
      pageCount={Math.ceil(total / size)}
      rangeLabel={formatRange(page, size, total)}
      getPageHref={(n) => hrefWith({ page: n === 1 ? null : String(n) })}
      pageSize={size}
      pageSizeOptions={SIZES}
      onPageSizeChange={(nextSize, nextPage) => {
        router.replace(
          hrefWith({
            size: nextSize === DEFAULT_SIZE ? null : String(nextSize),
            page: nextPage === 1 ? null : String(nextPage),
          }),
          { scroll: false },
        );
      }}
    />
  );
}
```

A new size is replaced in history, as a sort is, with `{ scroll: false }`, so the page does not jump. Read the size back from the URL and check it against your sizes, as the page is checked.

## Without numbers

For a cursor-paged list, where the API says only whether another page follows, pass `hasPageNumbers={false}` and `pageCount={hasMore ? page + 1 : page}`. While there is more, the count is one past this page, which enables Next. On the last page it equals this page, which disables Next. Write the range from what you know, here "1 to 25" with no total.

## Other digits

`pageLabel` writes a page number your way. Here it gives Persian digits with a string replacement and no `Intl`, so the server and the browser agree. Each page's name is `labels.page` called with that text, and the other labels translate the rest. In right to left, the list runs from the right and the chevrons point the way they go. ## Usage

Keep the page in the URL so it can be shared, reloaded and returned to. With the Next App Router, the server page reads the search parameter, formats the range and renders Pagination, with no client component of its own:

```tsx
// app/transactions/page.tsx, a server component
import { Pagination } from '@snapshot-ui/react';

const PAGE_SIZE = 50;

export default async function TransactionsPage({ searchParams }: { searchParams: Promise<{ page?: string }> }) {
  const { page: param = '1' } = await searchParams;
  const total = await countTransactions();
  const pageCount = Math.max(1, Math.ceil(total / PAGE_SIZE));
  const page = Math.min(Math.max(1, Number.parseInt(param, 10) || 1), pageCount);
  const first = (page - 1) * PAGE_SIZE + 1;
  const last = Math.min(page * PAGE_SIZE, total);
  const range =
    total === 0 ? 'No transactions' : `${formatCount(first)} to ${formatCount(last)} of ${formatCount(total)}`;
  return (
    <>
      <TransactionList page={page} />
      <Pagination page={page} pageCount={pageCount} rangeLabel={range} getPageHref={(n) => '?page=' + String(n)} />
    </>
  );
}
```

`formatCount` is yours. Pagination never formats a number, so you also word the range when there are no rows.

The links go through the `RouterProvider` at the app's root, as [Routing](/docs/routing) sets up. A page change is then a soft navigation, and the status region stays mounted to announce the new range. If it is silent after a navigation, render Pagination in a layout segment that persists. When the URL has other parameters, such as a search or a view, build each `href` from them so changing the page keeps them.

- The row always has 2 times `siblingCount` plus 5 slots, seven by default, so the controls never move under the pointer. Choose a page size that keeps the page count steady while a person pages.
- For an endless or cursor-paged list, use `hasPageNumbers={false}`, as [Without numbers](#without-numbers) shows.
- `pageCount` and `siblingCount` count whole pages. A `pageCount` that is not a finite number means no pages.
- A `page` that is not a whole number from 1 to `pageCount` shows as the nearest page, with a console warning.

## Accessibility

A `nav` named "Pagination" (or `labels.navigation`) holds a list of links or buttons. The current page has `aria-current`: "page" on a link, "true" on a button. With two on one page, give each its own name, as the examples here do.

- Names: each page is named "Page" and its number, and the steps by their words, even when the narrow row hides them.
- Announcements: the range is announced once, 600ms after it last changed, so three quick presses of Next announce one range. Nothing is announced on page load, and the visible range is not live, so it is never read twice.
- The page size picker: a Select labelled "Rows per page", named by its label and its value, inside the navigation landmark. A new size changes the range, which is announced as a page change is.
- Disabled steps: they leave the tab order. If a focused step disables, as Next does on the last page, focus moves to the current page, or to the other step when the numbers are hidden.
