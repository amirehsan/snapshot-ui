## Basic

A plain number takes a label and, with `hasStepper`, a minus and a plus button at the end. The arrow keys step by `step`, 1 unless given, and Page Up and Page Down step as the arrows do. An arrow first snaps the value to the step and then moves, so from an empty field it starts at the lower bound. Enter commits the value and formats it. Home and End move the caret, as in any text box, and still reach your `onKeyDown`. Each stepper is hit past its circle, 40px tall even when compact density draws it at 24px, and the two split the 2px between them, so a press lands on the button under it. `formatOptions` takes `Intl`'s options for a decimal, a percent or a unit, but not compact notation, whose rounding only `Intl` knows.

## Money

Pass `money={{ symbol: '$' }}` and the value becomes an integer count of minor units: `123450` is 1,234.50. A URL and a database hold it exactly, and sums never drift. `fractionDigits` is 2 unless given, from 0 for a currency with no minor unit to 3. An amount is exact up to `2 ** 52 / 10 ** fractionDigits` minor units, about 45 trillion cents, and the field warns in the console past that. The readout under the example shows the value the field holds.

The symbol is drawn beside the figure, slate, and never typed, so the caret can never land in it. A copied figure that carries it, "$1,234.50", pastes as the amount, and your `onPaste` still runs. There is no currency style: the app writes its own strings, and `Intl`'s currency style would put the caret inside the symbol and decide its place while the page renders. A money field has no steppers and no wheel: an amount is typed, never nudged, and a typed 12.50 is never snapped to a whole step.

## Negatives

Values under zero are off unless `allowsNegative` is set, and the lower bound is then 0. With it, a sign button sits at the field's start: a toggle, pressed while the value is under zero, that negates it, held within `minValue` and `maxValue`, or on an empty field or at zero puts a minus in it and focus there, so the field never shows "-0.00" and `onChange` never receives -0. It is there because neither the iPhone's nor Android's decimal keyboard has a minus key; a minus typed on a hardware keyboard works too, and the button follows it. A negative amount is ink, with its sign: never red, since nothing failed. On a disabled or read-only field the sign button is disabled too, and a negative value draws it pressed but recessed, a light ink fill with a taupe minus.

## Right to left

Name the symbol's side with `symbolPosition`, in the field's direction: "تومان" at the end on a Persian page, and "$" at the end there too, where Persian writing puts it left of the digits. The figure stays left to right on every page, so its sign stays in front of its digits; React Aria writes it in the locale's digits after the page loads.

## Usage

Keep an amount filter in the URL as minor units, `?min=2000`. A client component reads the parameter with `Number()`, reading an absent or malformed one as `null`, passes it as `value`, and writes the URL in `onChange`, which fires when the value commits, on blur, Enter, a step or the sign button, never on a keystroke. With the Next App Router:

```tsx
'use client';

import { useState } from 'react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { NumberField } from '@snapshot-ui/react';

const minorOf = (raw: string | null): number | null =>
  raw === null || raw === '' || !Number.isSafeInteger(Number(raw)) ? null : Number(raw);

export function MinimumAmount() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const min = minorOf(searchParams.get('min'));
  const [value, setValue] = useState(min);
  const [seen, setSeen] = useState(min);

  // The URL changed under the field, by Back, Forward or a link: show its amount.
  if (min !== seen) {
    setSeen(min);
    setValue(min);
  }

  return (
    <NumberField
      label="Minimum amount"
      money={{ symbol: '$' }}
      value={value}
      onChange={(next) => {
        setValue(next);
        setSeen(next);
        const params = new URLSearchParams(searchParams);
        if (next === null) params.delete('min');
        else params.set('min', String(next));
        const query = params.toString();
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    />
  );
}
```

On a statically rendered route, render it inside `<Suspense>` with the same field, empty, as the fallback. In a form, `name` sends the minor units in money mode and the number for a plain field.

Before the page hydrates, the field shows the plain figure, "1234.50", in ASCII digits with no grouping, and React Aria's formatted text, "1,234.50" or "۱٬۲۳۴٫۵۰", from the next render. The server's HTML is then the same in every locale and time zone, and nothing moves when the text changes.

## Props

Every React Aria NumberField prop is accepted except the steppers' names, which come from `labels`. These are the ones Snapshot UI adds or shapes. `validate` receives the value as `onChange` does: minor units in money mode, the number otherwise, and `null` for an empty field.

## Accessibility

A `textbox`, since React Aria removes the spin button role, named by its label and described by its hint, its symbol and the Changed chip, so "Amount, 1,234.50, $" is heard. The sign button is a toggle with `aria-pressed`, named "Negative" or `labels.negative`, and is its own tab stop. The steppers are named "Increase" and "Decrease" followed by the field's label, and are out of the tab order, since the arrows do the same from the field. React Aria announces a committed value in its own strings.
