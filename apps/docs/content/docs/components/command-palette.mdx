## Basic

A command palette is a dialog near the top of the screen with a field over a list. Type to filter: an item stays when every word you type appears in its label, its second line or its keywords, whatever the case and accents, so "cafe lumiere" finds Café Lumière. The arrows move the active row while focus stays in the field, and Enter opens it. Each item can have a 16px icon, a second line in slate, a value at its end such as a balance, given already formatted, and a key hint drawn as a key. Items with a `section` are grouped under it, in the order the sections are first seen, after the items with none. With `storageKey`, the palette remembers the last five items chosen in this browser and lists them first, under Recent, while the field is empty.

Cmd or Ctrl+K opens and closes a palette, and `shortcut` changes the key. The key is matched by the letter it types, and on a layout that types another script, such as Persian, Arabic, Hebrew or Russian, by where it sits, so Ctrl+K works there too. This site's own search already owns Cmd or Ctrl+K, so the example below listens for Cmd or Ctrl+J.

## Async results

When the results come from your server, take over the filtering: `filter={null}` is manual mode, in which the palette shows `items` as given. Control the field with `inputValue` and `onInputChange`, search, rank and cap the results yourself, and pass them as `items`. While a search runs, `isLoading` turns the spinner at the end of the field row, and the list keeps what it has until the new results land. Here a 400ms timer stands in for the request, and the palette opens from its button only.

## Usage

There is no trigger to import: your app's own button opens the palette through `isOpen` and `onOpenChange`, and a `Kbd` beside it can show the key. The shortcut listens on the whole page while the palette is mounted, open or closed. It leaves a key that something else has already handled, such as an editor that uses the same key, and a key typed while composing text. It does nothing while another of this library's modals is open (a Dialog, ConfirmDialog, Drawer or Sheet), so a confirm dialog is never skipped past. A modal of your own is not in that count: while one is open, call `preventDefault()` on the shortcut's keydown in it, or pass `shortcut={false}`. `shortcut={false}` also turns it off for good.

`onAction` receives the item, as you passed it, once the palette has closed and focus has gone back to where it was. So navigate there, or move focus, and nothing the palette does afterwards fights it. There is no `href` and no routing inside the palette.

```tsx
'use client';

import { CommandPalette } from '@snapshot-ui/react';
import { useRouter } from 'next/navigation';
import { PAGES } from './pages';

interface AppSearchProps {
  isOpen: boolean;
  onOpenChange: (isOpen: boolean) => void;
}

export function AppSearch({ isOpen, onOpenChange }: AppSearchProps) {
  const router = useRouter();
  return (
    <CommandPalette
      label="Search"
      items={PAGES}
      isOpen={isOpen}
      onOpenChange={onOpenChange}
      storageKey="app-search"
      onAction={(item) => {
        router.push(`/${String(item.id)}`);
      }}
    />
  );
}
```

`labels` replaces any of the palette's own words: the placeholder, which is the `label` unless you give one, the empty line, the spinner's name, the Recent heading, the status line, and the key hints. To keep the history yourself, on your server for example, pass `recentIds`, newest first, and `onRecentChange`, which receives the new list each time an item is chosen, your keys as given; the palette then stores nothing. Without `recentIds`, `onRecentChange` still hears each new list, as stored, so every id in it is a string. A remembered id that is no longer in `items` is dropped rather than shown with a stale name. Values in `end` are shown as given, so format them before you pass them. On a right-to-left page, wrap a signed amount in an element with `dir="ltr"`, so its sign stays in front of the figure.

## Accessibility

A dialog named by `label`, over a field named by it too. The field keeps DOM focus, and the list has virtual focus: the field points at the active row, so a screen reader reads the row as the arrows move, and the active row is drawn as the ink fill, since no focus ring can show where Enter goes. A status line, in the page from the moment the palette opens, says how many results there are once typing has paused, and says nothing while you type. Escape closes the palette at once, with or without text, and focus goes back to where it was.
