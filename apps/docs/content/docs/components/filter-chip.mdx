## One choice

A `FilterChip` with `selectionMode="single"` opens Select's list under the pill. The list gets a filter field at nine options or more. A press or Enter chooses and closes. With a value, the chip is the ink fill, shows its label and value, and is followed by a clear button. The list has no empty choice, as React Aria's single mode has none, so the clear button is the way back to none. It is a tab stop.

## Several choices

With `selectionMode="multiple"`, a press, Enter or Space toggles a row and the list stays open. `onChange` receives every chosen id each time. The chip summarizes the chosen options' text in list order, whatever the order of the value: "Groceries", "Groceries, Rent", or "Groceries, Rent and 2 more". The default summary is English and uses no `Intl`. Pass `labels.summary` for another language, or `valueLabel` to write it yourself.

## Your own content

Without `selectionMode`, the chip opens a panel with 16px padding around your content, such as two money fields, a range calendar or a segmented control.

- `valueLabel`: the value the chip shows. Without it, the chip is at rest.
- `onClear`: called by the clear button. Without it, there is no clear button.
- A function child receives `close`, for a Done or Apply button.

## States

- At rest: a boundary edge with no fill, the label at 500 and a slate chevron.
- Active: the ink fill, the label at 450 and the value at 700.
- Disabled: taupe on a faint edge. It keeps its value on the disabled fill and has no clear button.

A filter is neither consent nor unsaved, so a chip is never signal orange and never clay.

## Usage

A chip is always controlled. Its value, a key or a list of keys, belongs in the URL, and a FilterBar draws each chip twice. Read the value from the search parameters and write it back with the router:

- Start from the current parameters so the other filters stay.
- Delete the parameter for no value, and never write a bare `?`.
- Pass `{ scroll: false }` so the page does not jump.

Show a mirror of the value in your own state. A write goes through the router before the new parameters arrive, and until then the chip would show its old value. `seen` holds the value it last read or wrote, and the mirror reloads from the URL only when it changes under the chip, by Back, Forward or a link:

```tsx
'use client';

import { FilterChip, PickerOption, type Key } from '@snapshot-ui/react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { useState } from 'react';

export function CategoryFilter() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const category = searchParams.get('category');
  const [value, setValue] = useState<Key | null>(category);
  const [seen, setSeen] = useState(category);

  // The URL changed under the chip, by Back, Forward or a link: show its category.
  if (category !== seen) {
    setSeen(category);
    setValue(category);
  }

  return (
    <FilterChip
      label="Category"
      selectionMode="single"
      value={value}
      onChange={(next: Key | null) => {
        setValue(next);
        setSeen(next === null ? null : String(next));
        const params = new URLSearchParams(searchParams);
        if (next === null) params.delete('category');
        else params.set('category', String(next));
        const query = params.toString();
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    >
      <PickerOption id="groceries">Groceries</PickerOption>
      <PickerOption id="rent">Rent</PickerOption>
    </FilterChip>
  );
}
```

- Multiple chips: write one parameter per key with `params.delete('tag')`, then `append` each key. Read them back with `searchParams.getAll('tag')`, and use the whole query as `seen`.
- Several chips share one mirror and one `seen`, as the [FilterBar recipe](/docs/components/filter-bar#the-transactions-recipe) shows.
- On a statically rendered route, read the parameters inside `<Suspense>`, with the same chip, empty, as the fallback.

A closed chip ignores letters and Left and Right. A Select turns those into a choice nobody sees, which on a filter would be a query and a URL write behind the reader's back. The popover is modal, so a press on the next chip first closes this one. Inside a FilterBar, a chip is also a titled section of More and of the Filters sheet.

## Accessibility

A list chip is a button with `aria-haspopup="listbox"`, named by its label and then its value, as shown: "Category Groceries". Its list is named by the label. A chip with your content is a button that opens a `dialog` named the same way. The clear button is named "Clear" plus the label, from `labels.clear`, and is a tab stop after the chip. The popover is modal: focus moves into it, the page behind is inert, and focus returns to the chip on close. React Aria's own announcements have no Persian.
