## Basic

A `FilterBar` lays out your `search` first and then its `FilterChip`s in a group named "Filters" that wraps when it runs out of room. Nothing is measured: a chip with `isSecondary` and no value starts behind More, a padded panel that holds it as a titled section, and a chip with a value is always in the row, after the primary chips, so every active filter shows with its clear button. With no inactive secondary chip, More is not drawn. While any filter is active and you pass `onClearAll`, Clear all sits at the end of the row.

## On a phone

Under 768px of viewport the row, More and Clear all give way to one Filters button beside the search, with the active count in a neutral badge. It opens one sheet titled "Filters" holding every filter as a section, primary and secondary alike, in the order you declared them. The sheet is live: each change calls your `onChange` at once, so the URL and the results behind it follow, and Done only closes it. Swipe, Escape and the close button close it the same way. Name Done with your result count through `labels.done`, such as "Show 128 results", written by your app.

</Section>

## Chips in your own components

The bar reads the chips that are its children, directly or in fragments, and a chip behind a condition such as `{isAdmin && <FilterChip />}`, so the count and More are in the server's HTML. A chip inside your own component cannot be read: it stays in the row, never behind More, and your `activeCount` gives the count, counting every filter, since it replaces the bar's own. Give each chip a label of its own: the bar tells them apart by it.

## The Transactions recipe

With the Next App Router the URL is the only state. The server page awaits `searchParams`, reads every filter (`category`, `account` repeated, `min` and `max` in minor units, `from` and `to`), computes the result count and each custom chip's `valueLabel` with its own formatters, and renders a client component with them:

```tsx
// app/transactions/page.tsx, a server component
import { TransactionFilters } from './transaction-filters';

// An absent or malformed amount reads as none, as on the number field page.
const minorOf = (raw: string | string[] | undefined): number | null =>
  typeof raw !== 'string' || raw === '' || !Number.isSafeInteger(Number(raw)) ? null : Number(raw);

export default async function TransactionsPage({
  searchParams,
}: {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}) {
  const params = await searchParams;
  const list = (value: string | string[] | undefined) => (value === undefined ? [] : [value].flat());
  const filters = {
    category: typeof params.category === 'string' ? params.category : null,
    accounts: list(params.account),
    min: minorOf(params.min),
    max: minorOf(params.max),
    from: typeof params.from === 'string' ? params.from : null,
    to: typeof params.to === 'string' ? params.to : null,
  };
  const count = await countTransactions(filters);
  return (
    <TransactionFilters
      filters={filters}
      count={count}
      amountLabel={formatAmountRange(filters.min, filters.max)}
      dateLabel={formatDateRange(filters.from, filters.to)}
    />
  );
}
```

The client component writes each chip's change with the router, starting from the parameters already there so the search and the other filters stay. A repeated parameter is deleted and then appended once per key, a filter with no value deletes its parameter, a bare `?` is never written, and `{ scroll: false }` keeps the page where it is. Clear all deletes every filter parameter in one write.

It also mirrors the filters in its own state and shows that mirror, not the props. A write goes to the server and back before new props arrive, and until then a chip would show its old value: a multiple list would undo a toggle under the pointer, and a cleared chip would stay active. The mirror takes each change at once; the `seen` key, the query it last read or wrote, takes the server's filters again only when the URL changes under it, by Back, Forward or a link. The amount and date words come from the server's own formatters, so the mirror holds them too and blanks them as their chip clears. The sheet's Done names the server's count, "Show 1 result" or "Show 128 results":

```tsx
'use client';

import { FilterBar, FilterChip, PickerOption, SearchField, type Key } from '@snapshot-ui/react';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { useState } from 'react';
import { AmountFields, DateFields } from './filter-fields';

const FILTERS = ['category', 'account', 'min', 'max', 'from', 'to'];

interface Shown {
  category: Key | null;
  accounts: readonly Key[];
  amountLabel?: string;
  dateLabel?: string;
}

interface TransactionFiltersProps {
  filters: { category: string | null; accounts: string[] };
  count: number;
  /** The server's words for the two custom chips. */
  amountLabel?: string;
  dateLabel?: string;
}

export function TransactionFilters({ filters, count, amountLabel, dateLabel }: TransactionFiltersProps) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const query = searchParams.toString();
  const fromServer: Shown = { ...filters, amountLabel, dateLabel };
  const [shown, setShown] = useState(fromServer);
  // The query the bar last read from the URL, or last wrote to it.
  const [seen, setSeen] = useState(query);
  if (query !== seen) {
    setSeen(query);
    setShown(fromServer);
  }
  const write = (next: Partial<Shown>, change: (params: URLSearchParams) => void) => {
    setShown((current) => ({ ...current, ...next }));
    const params = new URLSearchParams(searchParams);
    change(params);
    const written = params.toString();
    setSeen(written);
    router.replace(written ? `${pathname}?${written}` : pathname, { scroll: false });
  };
  return (
    <FilterBar
      search={<SearchField aria-label="Search transactions" />}
      labels={{ done: count === 1 ? 'Show 1 result' : `Show ${count} results` }}
      onClearAll={() =>
        write({ category: null, accounts: [], amountLabel: undefined, dateLabel: undefined }, (params) =>
          FILTERS.forEach((name) => params.delete(name)),
        )
      }
    >
      <FilterChip
        label="Category"
        selectionMode="single"
        value={shown.category}
        onChange={(category) =>
          write({ category }, (params) =>
            category === null ? params.delete('category') : params.set('category', String(category)),
          )
        }
      >
        <PickerOption id="groceries">Groceries</PickerOption>
        <PickerOption id="rent">Rent</PickerOption>
      </FilterChip>
      <FilterChip
        label="Account"
        selectionMode="multiple"
        value={shown.accounts}
        onChange={(accounts) =>
          write({ accounts }, (params) => {
            params.delete('account');
            for (const key of accounts) params.append('account', String(key));
          })
        }
      >
        <PickerOption id="checking">Checking</PickerOption>
        <PickerOption id="savings">Savings</PickerOption>
      </FilterChip>
      <FilterChip
        label="Amount"
        valueLabel={shown.amountLabel}
        onClear={() =>
          write({ amountLabel: undefined }, (params) => {
            params.delete('min');
            params.delete('max');
          })
        }
      >
        {({ close }) => <AmountFields onDone={close} />}
      </FilterChip>
      <FilterChip
        label="Date"
        isSecondary
        valueLabel={shown.dateLabel}
        onClear={() =>
          write({ dateLabel: undefined }, (params) => {
            params.delete('from');
            params.delete('to');
          })
        }
      >
        <DateFields />
      </FilterChip>
    </FilterBar>
  );
}
```

`AmountFields` and `DateFields` are your own: two money NumberFields writing `min` and `max`, and a RangeCalendar writing `from` and `to`, in the same way. The words for a new amount or range are the server's, so they arrive with its next render. Render it inside `<Suspense>` with the same bar, at its first state, as the fallback. The search keeps its own pause before it writes, as the search field page shows. The example below writes `category` and a repeated `tag` and reads them back after a reload.

## Accessibility

The row is a `group` named "Filters", from `labels.filters`. More is a button that opens a `dialog` it names, and each section in it, and in the sheet, is a region named by its `h3` title. The sheet is a `dialog` titled "Filters". The Filters button is named by its text and the count, "Filters 2". Focus never falls to the page: after Clear all it goes to the first chip, after a secondary chip is cleared in the row it goes to More, as it does when a secondary chip's list or panel closes with its value gone (the chip stays in the row while it is open), after a choice in More leaves nothing behind it the closing panel gives focus to that chip in the row, after Clear all in the sheet it goes to Done, and when the sheet closes with the Filters button hidden, as on a phone turned wide, it goes to the first chip.
