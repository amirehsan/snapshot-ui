## A report

`Prose` gives the HTML inside it the library's type and spacing: headings by the heading steps, paragraphs at the body size with a 1.6 line height, lists, quotes, code, tables, figures and rules. Running text stops at 70 characters, a comfortable line; tables, code and figures take the whole width. Blocks sit 24px apart, a heading 32px under what came before it and 8px over what follows it, so a heading reads with its section. Here a report you write is rendered from Markdown by react-markdown in a server component, so the page sends no JavaScript for it.

## Rendering Markdown safely

Render Markdown on the server, with react-markdown and remark-gfm for tables, in a server component. Text a model writes is not yours to trust: it can hold a link to anywhere, a picture from anywhere and HTML. So for model output, pass `skipHtml`, which drops every tag, and give react-markdown a `components` map that turns a link into its text, `span.prose-unlinked`, and an image into its alt text, `span.prose-image`. The reader is never sent to an address and never shown a picture from one; a paragraph that held a link holds its words and reads the same, since Prose lays nothing out by `a` or `img`. The same map puts a table in a `ProseScroll` and gives a code block `tabIndex={0}`, so it scrolls by keys in every browser. Your own content, such as a help article, keeps its links: give it the map without `a` and `img`.

<Preview name="prose-markdown" />

HTML from a CMS is not Markdown. Sanitize it first, with a library such as DOMPurify or sanitize-html, then pass it to the element as React's raw HTML attribute, which Prose passes on like any other. Prose never parses or injects HTML, and has no prop that would.

## Wide tables

A table with four or more columns of figures is wider than a phone. Put it in a `ProseScroll`: a region that scrolls sideways inside the article, so the page never does, and that takes focus, so a keyboard reader can scroll it with the arrow keys. Its name is required, since a region a screen reader lists needs one: name the table, such as "October by category, table". The table keeps its rows and columns. A table outside one keeps to the width it is given by breaking its cells anywhere, which keeps the page whole but makes figures hard to read, so wrap every wide table.

## In a card and a page column

In a [Card](/docs/components/card), Prose is one part of the body: the card's padding is the article's inset, since the first and last blocks carry no outer margin, and a code block or an image takes the card's concentric corner wherever it falls. Start it at a paragraph or an `h2`, and leave the title to the card. On an article page, put `Prose as="article"` in the [PageColumn](/docs/components/page-header) under a PageHeader: text keeps its measure from the column's start edge, under the title, and tables and figures take the column's width.

## Persian

Under `lang="fa"` a list's markers, a quote's rule and an indent sit on the right, ordered lists count in Persian digits, headings drop their tracking, which would pull a cursive script apart, and emphasis is weight 500 and upright, since Vazirmatn has no italic. Code, inline and in blocks, stays left to right, and so do figures. Sofia Sans has no Persian letters, so load Vazirmatn and put it first in the stack under `lang="fa"`, as the [installation](/docs/installation) page shows. A renderer that mixes Persian and English paragraphs writes `dir="auto"` on each; Prose sets no direction.

## Usage

- Prose and ProseScroll are static. They render in a server component and ship no JavaScript, so a report rendered on the server costs the page nothing. They render inside a client component unchanged, for text that streams in.
- Put the `prose` class on any element, or use `Prose`, which renders a `div`, an `article` or a `section` through `as`. Every rule has the specificity of one class and `prose.css` comes before every component in `styles.css`, so a library component inside an article draws as it does anywhere. To leave a subtree alone, such as a chart in a report, give it the `not-prose` class.
- Text stops at `--prose-measure`, 70ch. Set it to `none` for a narrow column, or a smaller length. Headings take `--prose-scroll-margin` above them when a link jumps to one; set it to your sticky header's height.
- A Markdown `#` is an `h1`, and a page has one. Shift the headings down one level in your renderer, such as react-markdown's `components` mapping `h1` to `h2`, and the look follows the element.
- Load Sofia Sans's italic as well as its roman, as the installation page shows; without it, emphasis is upright.
- Tailwind Typography also names its class `prose`. Use one or the other on an element: with both, Tailwind's unlayered rules win over the library's, which sit in the components layer.

```tsx
import { Prose, ProseScroll } from '@snapshot-ui/react';
import Markdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

export function MonthlyReport({ markdown }: { markdown: string }) {
  return (
    <Prose as="article">
      <Markdown
        remarkPlugins={[remarkGfm]}
        skipHtml
        components={{
          a: ({ children }) => <span className="prose-unlinked">{children}</span>,
          img: ({ alt }) => <span className="prose-image">{alt}</span>,
          table: ({ children }) => (
            <ProseScroll aria-label="Report, table">
              <table>{children}</table>
            </ProseScroll>
          ),
          pre: ({ children }) => <pre tabIndex={0}>{children}</pre>,
        }}
      >
        {markdown}
      </Markdown>
    </Prose>
  );
}
```

## Accessibility

The elements are yours, and Prose adds none: a screen reader reads your headings, lists, quotes and tables as they are. `Prose as="article"` is not a landmark; `as="section"` is a region landmark only when you name it. A `ProseScroll` is a named region that takes focus, so a keyboard reader can scroll a wide table, and its focus ring shows where focus is; a code block mapped with `tabIndex={0}` scrolls the same way. A neutralized link is text: no tab stop, no role and no underline, so nothing looks like a link that goes nowhere. Real links are underlined, so they are never told by color alone.
