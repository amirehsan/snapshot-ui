## Basic

A list of actions that opens from a button, in a [Popover](/docs/components/popover).

- Items: each has a label, and can have an icon, a second line, a preformatted value at its end and a key hint. `Mod` in a hint is Cmd on Apple platforms and Ctrl elsewhere.
- Sections: group items under a heading. A separator rules between groups.
- Danger: `variant="danger"` shows the label and icon in the error color, for an item that loses something.

Rows are 40px tall, and 44px on a touch screen.

## Selection

A menu can also choose. Set `selectionMode` on the menu, or on a section to make it choose apart from the rest, as the theme and panels do here.

- `selectionMode="single"`: items are radios. The chosen row is the ink pill with a check, and a choice closes the menu.
- `selectionMode="multiple"`: items are checkboxes. A chosen row shows only the check, and the menu stays open.
- `shouldCloseOnSelect` overrides closing on the menu, a section or one item.

Every row in a selectable list reserves room for the check, so the width never changes.

## Links

An item with `href` is a real link, an anchor with `role="menuitem"`, so a middle or modified click opens it as the browser would. A plain press navigates through React Aria's `RouterProvider`, as [Link](/docs/components/link) does. One provider at the app's root routes every link, set up in [Routing](/docs/routing).

To render your router's own link, use the item's inherited `render` prop in a client component. An item without `href` renders a `div`:

```tsx
<MenuItem
  id="settings"
  href="/settings"
  render={(props) => ('href' in props ? <NextLink {...props} href={props.href} /> : <div {...props} />)}
>
  Settings
</MenuItem>
```

## Usage

Put a button and a `Menu` in a `MenuTrigger`. To control it, pass `isOpen`, `defaultOpen` and `onOpenChange` to `MenuTrigger`. Menu is a client component, and a server component can render it, as the selection example does with `defaultSelectedKeys`. A menu that runs a handler or keeps its choice in state needs a client component, as the other two examples do.

- `onAction` on the menu receives the `id` of the item that ran. An item's own `onAction` runs first, with no argument.
- A danger item usually asks first. Pair it with a [Confirm dialog](/docs/components/confirm-dialog) whose confirm button names the same outcome.
- The popover opens under the button at its start edge, and flips where the screen has no room. `placement` changes that.
- The popover is at least 12rem wide, or the button's width if wider. A long menu scrolls inside it.
- A menu opened from a dark card is dark on a light page, as [Theming](/docs/theming#overlays) explains.

## Accessibility

A true `role="menu"`, named by its trigger, which says that it opens a menu and whether it is open. Items are menu items, or radios and checkboxes in single and multiple selection. Each is named by its label and described by its second line and key hint.

- A disabled item is announced as unavailable, and the arrows skip it.
- Opened from the keyboard, focus starts on the first item, or the last with Arrow Up. Opened with a pointer, it starts on the list, or on the chosen item when the menu selects.
- Focus stays in the open menu until a choice, Escape or a press outside closes it, then returns to the trigger.
