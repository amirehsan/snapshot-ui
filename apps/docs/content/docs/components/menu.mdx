## Basic

A menu is a list of actions that opens from a button, in a [Popover](/docs/components/popover). Each item has a label and can have a 16px icon at its start, a second line under the label in slate, a value at its end such as an amount, given already formatted, and a key hint after it, drawn as a key: `Mod` in a hint is Cmd on Apple platforms and Ctrl elsewhere. Sections group items under a heading, and a separator rules between groups. An item that loses something takes `variant="danger"`, which draws its label and icon in the error color. Rows are 40px tall, and 44px on a touch screen.

## Selection

A menu can also choose. `selectionMode="single"` makes its items radios: the chosen row is the ink pill with a check, and a choice closes the menu, so there is no doubt that it registered. `selectionMode="multiple"` makes them checkboxes: a chosen row shows the check alone, without the fill, and the menu stays open for the next one. Every row of a selectable list keeps the check's room, so the list never changes width as the choice moves. Set the mode on the menu, or on a section, which then chooses apart from the rest, as the theme and the panels do here. `shouldCloseOnSelect` overrides the close on the menu, on a section or on one item.

## Links

An item with `href` is a real link, an anchor with `role="menuitem"`, so a middle click or a modified click opens it as the browser would. A plain press navigates through React Aria's `RouterProvider`, which [Link](/docs/components/link) uses too, so wrap your app in it once. Import it from `@snapshot-ui/react`: it is the library's own copy of React Aria's, so the provider and the items always share one router, whatever else the app installs. With the Next.js App Router, that is a small client component around the app, with the `RouterConfig` augmentation so `routerOptions` is typed:

```tsx
'use client';

import { useRouter } from 'next/navigation';
import type { ReactNode } from 'react';
import { RouterProvider } from '@snapshot-ui/react';

declare module '@snapshot-ui/react' {
  interface RouterConfig {
    routerOptions: NonNullable<Parameters<ReturnType<typeof useRouter>['push']>[1]>;
  }
}

export function ClientProviders({ children }: { children: ReactNode }) {
  const router = useRouter();
  return (
    <RouterProvider
      navigate={(href, options) => {
        router.push(href, options);
      }}
    >
      {children}
    </RouterProvider>
  );
}
```

Render `<ClientProviders>` around `{children}` in `app/layout.tsx`.

The one trade-off: React Aria renders a plain anchor, so Next does not prefetch the page as the link comes into view. Prefetch it yourself with `router.prefetch(href)` from the item's `onHoverStart` and `onFocus`, or draw Next's own `Link` for an item with the `render` prop it inherits, from a client component:

```tsx
<MenuItem
  id="settings"
  href="/settings"
  render={(props) => ('href' in props ? <NextLink {...props} href={props.href} /> : <div {...props} />)}
>
  Settings
</MenuItem>
```

## Usage

Compose `MenuTrigger`, the button that opens the menu, and `Menu`, which opens in its own popover. `MenuTrigger` takes `isOpen`, `defaultOpen` and `onOpenChange` to control it. Menu is a client component, and a server component can render it, as the selection example on this page does with `defaultSelectedKeys`; a menu that runs a handler or keeps its choice in state lives in a client component, as the other two do.

`onAction` on the menu receives the key, the `id`, of the item that ran. An item's own `onAction` runs first, with no argument, and then the menu's. A danger item usually asks first: pair it with a [Confirm dialog](/docs/components/confirm-dialog) whose confirm button names the same outcome. The popover opens under the button at its start edge, `placement` changes that, and it flips to the other side where the screen has no room. It is at least 12rem wide, or as wide as the button when that is wider, and a long menu scrolls inside it. A menu opened from a dark card is dark while the page stays light, as [Theming](/docs/theming#overlays) explains.

Focus moves into the menu, and the arrow keys move it from item to item, as the table below lists. It stays in the menu until a choice, Escape or a press outside closes it, and then goes back to the button.

## Accessibility

A true `role="menu"`, named by its trigger, which says that it opens one and whether it is open. Its items are menu items, radios in single selection and checkboxes in multiple, named by their labels and described by their second lines and their keys. A disabled item is announced as unavailable and the arrows pass it by. Opened from the keyboard, focus starts on the first item, or on the last with Arrow Up; opened with a pointer, it starts on the list, and on the chosen item when the menu itself selects. Escape closes the menu and focus goes back to the trigger. React Aria holds focus inside the open menu, so Tab does not leave it.
