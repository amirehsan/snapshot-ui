## Basic

Pass a `label`, an optional hint, and the options as `PickerOption`s. Until one is chosen, the field shows "Choose an option" or your `placeholder`. Use a select for one value from a list known in advance. For a few short options that fit side by side, use a segmented control instead.

## Rows

Options use the menu's row:

- `icon`: shown at the start.
- `description`: a hint under the label, for options that need telling apart.
- `end`: a preformatted value at the end, such as this month's total.

Group options with `PickerSection`, whose title is an overline heading. The trigger shows only the chosen option's icon and label. A string label is also the option's text value, used by typeahead, the filter and the trigger. A label that is not a string needs a `textValue`.

## Filtering

With nine or more options, the list opens with a filter field at its top. Pass `isFilterable` to show it on a shorter list, or `isFilterable={false}` to hide it on a longer one.

- An option matches when every word typed appears in it, in any order, ignoring case and accents. "cafe" finds "Café" and "rent home" finds "Home rent".
- A section with no matches hides, and "No matches" shows when nothing matches.
- The field is empty each time the list opens.
- On a phone the filter does not take focus on open, so the keyboard does not cover the list. Tap the field to filter.

## States

A changed select shows the Changed chip and the light signal orange edge until the value is saved. An invalid one shows the error edge and its error line. A disabled one is recessed, with its text and chevron in taupe.

## Usage

Keep the choice in the URL so a filtered view can be shared, reloaded and reached with Back. Pass the search parameter as `value` and write the URL in `onChange`. With the Next App Router:

```tsx
'use client';

import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { PickerOption, Select } from '@snapshot-ui/react';

export function CategoryFilter() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  return (
    <Select
      label="Category"
      value={searchParams.get('category') ?? 'any'}
      onChange={(key) => {
        const params = new URLSearchParams(searchParams);
        if (key === null || key === 'any') params.delete('category');
        else params.set('category', String(key));
        const query = params.toString();
        // No bare "?" once the last filter goes, and no jump to the top: the reader stays at the field.
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    >
      <PickerOption id="any">Any category</PickerOption>
      <PickerOption id="groceries">Groceries</PickerOption>
      <PickerOption id="rent">Rent</PickerOption>
    </Select>
  );
}
```

- Use `value`, `defaultValue` and `onChange`. React Aria's deprecated `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are not accepted.
- A select has no clear action. When "any" is a real answer, add it as an option, as above.
- In a plain form, give it a `name` to submit the chosen key.

When the options come from data, pass them as `items` and render each with a function child. Each item needs an `id` or a `key`, which becomes the option's key:

```tsx
<Select label="Account" items={accounts}>
  {(account) => <PickerOption end={account.balance}>{account.name}</PickerOption>}
</Select>
```

## Accessibility

The trigger is a button with `aria-haspopup="listbox"`, named by its value and label: a screen reader hears "Groceries, Category, button". It opens a `listbox` of `option`s.

- An option is named by its label and described by its end value and hint.
- The chosen option has a check as well as the filled row, so the choice never relies on color alone.
- With a filter, focus stays in the field and the arrows move the active option. On a touch screen focus starts in the list.
- React Aria's own announcements, such as the list's name while filtered, use its own strings, which have no Persian.
