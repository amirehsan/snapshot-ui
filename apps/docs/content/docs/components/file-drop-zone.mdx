## A field

`FileDropZone` is a field that takes files: a dashed box to drop them on, a button that opens the file picker, your rules under it, and a line for the files it refused. Drag a file over it and the edge turns solid ink with "Drop to upload"; drop it, choose it, or focus the button and paste it. On a phone, which cannot drag a file into a page, the hint is not drawn and the button stays; `capture` opens the camera instead of the picker, so a receipt can be photographed. The "Take a photo" button below shows only on a touch screen.

## Errors in your words

Every drop, paste and choice runs one check, and `onFiles` gets the files that passed and the ones that did not, each with its reason: `'type'`, `'size'`, `'empty'` or `'count'`. A drop of five with one too large adds four. By default the zone says how many were not added; `errorMessage` replaces that line with your own, such as one that names each file in the GOV.UK Design System's words: "The selected file must be smaller than 10 MB".

## The whole page

`PageDropZone` takes a drop anywhere on the page. It draws nothing until files are dragged over the window; then an overlay covers the workspace, clear of the rail, and says what a drop does. It is for the pointer and hidden from assistive technology, so every page zone has a button: put a `FileButton` beside the page's title. Turn the switch on and drag a file from your desktop onto this page.

## A button alone

`FileButton` is React Aria's FileTrigger around the library's Button, with the same check and the same `onFiles`. React Aria clears its input as it is pressed, so choosing the same file again after a failure fires again.

## Usage

The library never reads or sends a file: `onFiles` gives you `File` objects and the refusals with their reasons, and your app uploads them and tells the upload tray how each is going. The check is a courtesy to the reader. Check every file again on your server, since a renamed file passes any check by its name (OWASP's File Upload Cheat Sheet).

- `acceptedFileTypes` takes what an `<input accept>` takes: MIME types (`'application/pdf'`), wildcards (`'image/*'`) and extensions (`'.heic'`). A browser that does not know a file's type gives it none, as some do for a phone's HEIC photos, and such a file is checked by its extension alone, so list `.heic` where you take photos.
- `allowsMultiple` takes several files at once, and `maxFiles` caps how many one drop, paste or choice may add; without `allowsMultiple` it is one. Files past the cap are refused as `'count'`.
- A dropped folder is refused as `'type'`, carried as an empty `File` with the folder's name; its contents are never read.
- A page has a page zone or inline zones, never both, and one page zone at a time: a second warns in development and stays idle.
- While a zone is mounted, a file dropped beside it does nothing, rather than open in the tab and leave the page.
- `capture` is `'environment'` for the back camera and `'user'` for the front. A desktop browser ignores it and opens the file picker.
- The zone has no `name` and does not submit with a form: the files reach your app through `onFiles` only.

```tsx
import { FileButton, FileDropZone, PageDropZone } from '@snapshot-ui/react';

<FileDropZone
  label="Receipts"
  description="PDF, JPG or PNG, up to 10 MB"
  acceptedFileTypes={['application/pdf', 'image/jpeg', 'image/png', '.heic']}
  maxFileSize={10 * 1024 * 1024}
  allowsMultiple
  onFiles={(accepted, rejected) => upload(accepted)}
/>;

// A whole page, with its keyboard twin beside the title.
<>
  <FileButton allowsMultiple onFiles={(accepted) => upload(accepted)}>
    Upload
  </FileButton>
  <PageDropZone title="Drop files to upload" allowsMultiple onFiles={(accepted) => upload(accepted)} />
</>;
```

## Accessibility

The zone is a `group` named by its label, with one tab stop: its button, "Choose files", described by your rules. The button also takes a paste, so a keyboard reader adds files from the clipboard where a pointer drops them.

- Every drag has a single-pointer twin (WCAG 2.5.7): the zone's button, and a `FileButton` beside every page zone.
- Refusals are said once, politely, by a status mounted with the zone, and the button is described by them while they show.
- The page overlay is for the pointer and hidden from assistive technology.
- A disabled zone says so to assistive technology, and its button opens nothing.
- In forced colors the dashed edges keep the reader's text color and a drop target's edge turns the highlight color.
