## Folding

The title is the toggle: press it, or focus it and press Enter or Space, to fold the body under the header and to open it again. The title row is the target, and the chevron at its end turns toward the title while the card is folded. The header stays as it is, and the space and the rule between the header and the body fold away with the body, in 200ms, or at once under reduced motion.

## Actions

Controls passed as `actions` sit at the end of the header row, outside the toggle, and stay usable while the card is folded, so a Reset button never hides with the fields it resets. The title and the note keep at least 12rem beside them. Where the row cannot give them that, the actions move under the note, so the note always stays directly under the title and the title never narrows to a column of letters.

## Remembering the fold

Give a card a `storageKey` and it remembers its fold in this browser: fold it, reload the page, and it is still folded. Cards with the same key fold together, on the page and in other tabs, and a card that find-in-page opens is remembered as open. Every remembered card on the site keeps its fold in one `localStorage` entry, `snapshot-ui:collapsed`, so give each card a key of its own, such as its page and its title. Where the browser blocks storage or refuses a write, the card still folds and opens, but a fold lasts only while a card with a `storageKey` is on the page.

The entry is a plain list of the folded keys, and a key that was never stored means open, so `defaultExpanded={false}` does not apply under a `storageKey`. A card that `isExpanded` controls reads and stores nothing. `onExpandedChange` is called when someone uses this card, by its toggle or by find-in-page. A card that follows another card or tab with the same key is syncing state, not being used, and does not call it.

<Preview name="collapsible-card-remembered" />

A server-rendered page shows a remembered fold only after it has loaded. The server cannot see the browser's storage, so it draws the card open, and the card folds as the page hydrates, at once, with no transition. An app that needs the first frame right controls the card itself, with `isExpanded` from a state the server can read, such as a cookie.

</Section>

## The changed marker

While a card is folded, a clay dot after its title, the color of the Changed chip, says that its body holds a change, so a change never goes out of sight. The card finds the change itself: any element in its body that carries `data-changed`, as every Snapshot UI field's root does while its `isChanged` is true, marks the card, and so does a changed field in a card nested in the body. For a change that no field reports, pass `isChanged` to the card. Its root then carries `data-changed` too, so a collapsible card around it counts the change. Open, the card shows no marker, and each field shows its own Changed chip.

<Preview name="collapsible-card-changed" />

A screen reader reads the toggle's title, then collapsed, then `changedLabel`, which is "Changed" unless you give other words. The dot is for the eye, and a screen reader skips it. A folded title keeps room for the dot, so the title stays where it is when the dot comes or goes. The card watches its body only while it is folded, and looks once as it folds, so a field changed while the card was open marks it at once. The server cannot look in the body, so on a server-rendered page the dot for a changed field appears once the page has hydrated. A card the server draws folded with `isChanged` shows its dot from the first frame.

</Section>

## Opening for an invalid field

A folded card opens itself when a field in its body fails the browser's validation on submit, or when a script calls the form's `checkValidity()` or `reportValidity()`, so the field can be seen and fixed. A field among the header's actions is in view already, so it leaves the card folded. The card hears the browser's `invalid` event before the field takes focus, and opens the way its toggle does: a remembered fold is forgotten, and `onExpandedChange` is called with `true`, once however many fields fail, so a card that `isExpanded` controls opens once the app sets it open. The open has no transition, and neither has a card with the same `storageKey` that opens with it, so the body is its full height when the field takes focus, and the browser scrolls the field into view however deep in the body it sits, with motion or without. That holds for a React Aria field and for a plain input with `required` alike.

This covers fields that leave validation to the browser, which React Aria does by default, with `validationBehavior="native"`. With `validationBehavior="aria"` the browser sees nothing wrong, fires no `invalid` event and lets the form submit, so the card stays folded. Open it from your own state, with `isExpanded`, when your validation fails.

</Section>

## Usage

A card is open on its first render. Pass `defaultExpanded={false}` to start it folded, or control it with `isExpanded` and `onExpandedChange`. The children are the body, laid out as a card's body is. CollapsibleCard is a client component, and a server component can render it, as the first example on this page does. A card that never folds should stay a [Card](/docs/components/card), which is static and ships no JavaScript. In a parent that sizes the card to its content, such as a shrink-to-fit box, the card's width can change between folded and open, since a folded card holds only its header, so give the card a width from its container.

```tsx
import { Button, CollapsibleCard } from '@snapshot-ui/react';

export function Notifications() {
  return (
    <CollapsibleCard
      title="Notifications"
      note="Where we reach you, and how often."
      actions={<Button variant="secondary">Reset</Button>}
    >
      <p>Product updates, when something ships.</p>
    </CollapsibleCard>
  );
}
```

## Accessibility

The title is a heading that holds a button, so the card is in a screen reader's list of headings, and the button says the title and then whether the body is expanded or collapsed. The chevron is decoration. A folded body leaves the tab order and the accessibility tree. In a browser that supports `hidden="until-found"`, find-in-page can still find its text: the card opens at once, so the browser scrolls to where the match stays, and reports it through `onExpandedChange`. A text fragment link into a card that is folded when the page loads is less sure. The server's HTML hides a folded body completely, and the card makes it findable only once the page has hydrated, so the link works only if the browser is still looking for its text by then. In our measurements Firefox did not look again at all, and Chromium and WebKit stopped within about 1.5 and 5 seconds of the load, so leave open a card that a link must reach. A browser without `until-found` hides a folded body completely, and find-in-page does not search it. When a card folds while focus is in its body, as after a Done button there, focus moves to its toggle. The toggle spans the block the title and the note share, at least 40px tall, and the actions are never inside it.

<Keys rows={[['Enter Space', 'Folds or opens the card.'], ['Tab', 'Moves to the toggle, then to the actions. A folded body takes no focus.']]} />

A card is a div unless `as` says otherwise. A `section` with a name, from `aria-label` or from `aria-labelledby` pointing at an element in the title, is a region landmark. An `article` is not a landmark, named or not.
