## Folding

The title is the toggle. Press it, or focus it and press Enter or Space, to fold or open the body. The chevron at the end of the title row turns toward the title while the card is folded. The header stays put, and the body folds away in 200ms, or at once under reduced motion.

## Actions

Controls in `actions` sit at the end of the header row, outside the toggle. They stay usable while the card is folded, so a Reset button never hides with the fields it resets. The title and note keep at least 12rem. When the row is too narrow for that, the actions move under the note.

## Remembering the fold

With a `storageKey`, the card remembers its fold in this browser across reloads. Cards with the same key fold together, on the page and in other tabs. All remembered cards share one `localStorage` entry, `snapshot-ui:collapsed`, so give each card a unique key, such as its page and title.

- The entry lists only folded keys, and an unstored key means open. So `defaultExpanded={false}` does not apply under a `storageKey`.
- A card controlled by `isExpanded` reads and stores nothing.
- `onExpandedChange` is called when someone uses this card, by its toggle or by find-in-page. A card that is only syncing with another card or tab does not call it.
- A card that find-in-page opens is remembered as open.
- If the browser blocks storage or refuses a write, the card still folds, but the fold lasts only while a card with a `storageKey` is on the page.

<Preview name="collapsible-card-remembered" />

The server cannot read the browser's storage, so a server-rendered card is drawn open and folds at once, with no transition, when the page hydrates. To get the first frame right, control the card with `isExpanded` from state the server can read, such as a cookie.

</Section>

## The changed marker

While a card is folded, a clay dot after its title says its body holds a change. The card finds changes itself: any element in its body with `data-changed` marks it. Every Snapshot UI field's root carries `data-changed` while its `isChanged` is true, and a changed field in a nested card counts too. For a change no field reports, pass `isChanged` to the card. Its root then carries `data-changed` as well, so an outer collapsible card counts it. An open card shows no marker, since each field shows its own Changed chip.

<Preview name="collapsible-card-changed" />

- Screen readers: the toggle reads its title, then collapsed, then `changedLabel` ("Changed" by default). The dot itself is hidden from them.
- Layout: a folded title keeps room for the dot, so the title does not shift when it appears.
- Timing: the card checks its body as it folds and watches it while folded, so a field changed while open marks it at once.
- Server rendering: the dot for a changed field appears after hydration. A card drawn folded with `isChanged` shows its dot from the first frame.

</Section>

## Opening for an invalid field

A folded card opens itself when a field in its body fails the browser's validation, on submit or on a call to the form's `checkValidity()` or `reportValidity()`. A field among the header's actions is already in view, so it leaves the card folded.

The card opens the way its toggle does: a remembered fold is forgotten, and `onExpandedChange` is called once with `true`, however many fields fail. A card controlled by `isExpanded` opens once your app sets it. The open has no transition, so the body is full height when the field takes focus and the browser can scroll it into view. This works for React Aria fields and for plain inputs with `required`.

This needs browser validation, which React Aria uses by default (`validationBehavior="native"`). With `validationBehavior="aria"`, the browser fires no `invalid` event and the card stays folded. Open it yourself with `isExpanded` when your validation fails.

</Section>

## Usage

A card starts open. Pass `defaultExpanded={false}` to start it folded, or control it with `isExpanded` and `onExpandedChange`. The children are the body, laid out like a card's body. CollapsibleCard is a client component that a server component can render, as the first example does. For a card that never folds, use a [Card](/docs/components/card), which is static and ships no JavaScript. A folded card holds only its header, so in a shrink-to-fit parent its width can change. Give it a width from its container.

```tsx
import { Button, CollapsibleCard } from '@snapshot-ui/react';

export function Notifications() {
  return (
    <CollapsibleCard
      title="Notifications"
      note="Where we reach you, and how often."
      actions={<Button variant="secondary">Reset</Button>}
    >
      <p>Product updates, when something ships.</p>
    </CollapsibleCard>
  );
}
```

## Accessibility

The title is a heading that holds a button, so the card appears in a screen reader's list of headings. The button reads the title, then expanded or collapsed. The chevron is decoration. The toggle covers the title and note, is at least 40px tall, and never contains the actions. A folded body leaves the tab order and the accessibility tree. When a card folds while focus is in its body, such as after a Done button, focus moves to its toggle.

<Keys rows={[['Enter Space', 'Folds or opens the card.'], ['Tab', 'Moves to the toggle, then to the actions. A folded body takes no focus.']]} />

Find-in-page:

- In browsers that support `hidden="until-found"`, find-in-page still searches a folded body. The card opens at once so the browser can scroll to the match, and reports it through `onExpandedChange`.
- In other browsers, a folded body is hidden completely and not searched.
- Text fragment links into a card folded at load are unreliable. The server's HTML hides the body completely until hydration. In our measurements Firefox never looked again, and Chromium and WebKit stopped looking within about 1.5 and 5 seconds. Leave open a card that a link must reach.

A card is a div unless `as` says otherwise. A `section` named by `aria-label`, or by `aria-labelledby` pointing into the title, is a region landmark. An `article` is not a landmark, named or not.
