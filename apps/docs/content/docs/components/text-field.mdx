## States

The edge carries the state. A changed field gets a light signal orange edge and a clay chip beside its label. An invalid field gets the error edge and an error line, and invalid outranks changed, so the chip steps aside. A disabled field is recessed. A read-only field looks like an enabled one and still submits.

## Validation

Set `isRequired`, a `type`, or a `validate` function, and the browser's own checks run when the form is submitted. The error line then shows the message, or the one you build from the validation result. The first failed submit shows the error and moves focus to the field.

## Length count

Pass `budget` to count the value's length against about how long it should be. The count appears from 70% of the budget and never blocks typing. It is the value's length as JavaScript and `maxLength` measure it, in UTF-16 code units, so an emoji, or an accented letter built from two code points, can count as two. The budget is a soft target and the count can pass it. `maxLength` is a hard stop that the counter does not read, so set `budget` at or below `maxLength`. [Field parts](/docs/components/field) shows it in use.

To word the count another way, such as in another language, pass `counter` with a `label` function. It receives the count, the budget and whether the count is past it, and returns the text. `counter.showFrom` moves the share of the budget the count first appears at.

```tsx
<TextField
  label="Kurzbeschreibung"
  budget={60}
  counter={{ label: ({ count, budget }) => `${count} von etwa ${budget}` }}
/>
```

The count is announced each time it changes. If that is too often for your readers, build the field from its parts and pass FieldCounter a count that settles after a pause, as [Field parts](/docs/components/field) describes.

## Usage

Every value works controlled and uncontrolled, and a field with a `name` submits in a plain form. `onChange` receives the string.

```tsx
import { useState } from 'react';
import { TextField } from '@snapshot-ui/react';

export function ShortDescription({ saved }: { saved: string }) {
  const [value, setValue] = useState(saved);
  return (
    <TextField
      label="Short description"
      description="One sentence, for search results."
      name="description"
      value={value}
      onChange={setValue}
      isChanged={value !== saved}
      budget={60}
    />
  );
}
```

A field needs a name, and the types require one: a `label`, an `aria-label` when no label is shown, or an `aria-labelledby` that points at a label shown elsewhere.

For a custom layout, use the parts inside React Aria's own field: Label, Input, Description and FieldError. Field parts has the example. For text that runs to several lines, use [Text area](/docs/components/text-area), which takes the same props.

## Accessibility

A native input, labelled by the label and described by the hint and the error line, with React Aria handling the wiring. A screen reader reads the Changed chip with the field, after the hint, while the field is changed and valid. An invalid field reads its hint and then its error line, and the chip steps aside.

<Keys rows={[['Tab', 'Moves focus into the field. The edge firms to 1.5px ink and the 2px ring sits outside it.'], ['Enter', 'Submits the form the field is in.']]} />

The placeholder is taupe, which is quiet by design, so it never carries anything the label does not. The count is a polite status region.

A field with no name does not compile, and TypeScript's message either names only `aria-labelledby` or says the props are not assignable; either one means the field has no accessible name.
