## States

The edge carries the state.

- Changed: a light signal orange edge and a clay chip beside the label.
- Invalid: the error edge and an error line. Invalid outranks changed, so the chip hides.
- Disabled: the field is recessed.
- Read-only: looks like an enabled field and still submits.

## Validation

Set `isRequired`, a `type`, or a `validate` function, and the browser's checks run on submit. The error line shows the message, or one you build from the validation result. The first failed submit moves focus to the field.

## Length count

Pass `budget` for about how long the value should be. The count appears from 70% of the budget and never blocks typing, so it can pass the budget. [Field parts](/docs/components/field) shows it in use.

- Length is in UTF-16 code units, as JavaScript and `maxLength` measure it. An emoji, or an accented letter built from two code points, can count as two.
- `maxLength` is a hard stop the count does not read. Set `budget` at or below it.

To word the count another way, such as in another language, pass `counter` with a `label` function. It receives the count, the budget and whether the count is past it, and returns the text. `counter.showFrom` sets the share of the budget where the count appears.

```tsx
<TextField
  label="Kurzbeschreibung"
  budget={60}
  counter={{ label: ({ count, budget }) => `${count} von etwa ${budget}` }}
/>
```

The count is announced each time it changes. To announce it less often, build the field from its parts and pass FieldCounter a count that settles after a pause, as [Field parts](/docs/components/field) describes.

</Section>

## Usage

Every value works controlled and uncontrolled. A field with a `name` submits in a plain form. `onChange` receives the string.

```tsx
import { useState } from 'react';
import { TextField } from '@snapshot-ui/react';

export function ShortDescription({ saved }: { saved: string }) {
  const [value, setValue] = useState(saved);
  return (
    <TextField
      label="Short description"
      description="One sentence, for search results."
      name="description"
      value={value}
      onChange={setValue}
      isChanged={value !== saved}
      budget={60}
    />
  );
}
```

The types require a name: a `label`, an `aria-label` when no label is shown, or an `aria-labelledby` that points at a label shown elsewhere.

For a custom layout, use the parts inside React Aria's own field: Label, Input, Description and FieldError. Field parts has the example. For text of several lines, use [Text area](/docs/components/text-area), which takes the same props.

## Accessibility

A native input, labelled by the label and described by the hint and the error line. While the field is changed and valid, a screen reader reads the Changed chip after the hint. An invalid field reads its hint, then its error line.

<Keys rows={[['Tab', 'Moves focus into the field. The edge firms to 1.5px ink and the 2px ring sits outside it.'], ['Enter', 'Submits the form the field is in.']]} />

The placeholder is taupe and quiet by design, so it never carries anything the label does not. The count is a polite status region.

A field with no name does not compile. TypeScript's message names only `aria-labelledby` or says the props are not assignable. Either one means a missing accessible name.
