## Basic

Type part of a name and the list opens with the options that contain it, with case and accents aside, so "cafe" finds "Café Luna" and "co" finds "Corner Mart" and "Cobalt Coffee". The button at the field's end, or the down arrow, opens every option. Choose with Enter or a press, and the field shows the option's text. A combo box beats a select when the list is long, or when people know the option by name and would rather type it than scroll to it. The options are the select's: `PickerOption` and `PickerSection`, with their hints, icons and end values.

## From a server

When the options live on your server, control the text and the options: pass `items` and `inputValue`, fetch in `onInputChange`, and set `isLoading` while you wait. The field shows a spinner before its button, and the list keeps what it has until the new results arrive, or says "Loading" while it has nothing yet. React Aria does no filtering of items you control, so your server filters, ranks and caps them; the example waits 300ms as a request would and returns at most eight.

React Aria puts the chosen text back on Escape and on leaving the field by finding the chosen option among the items, so keep it there: hold the chosen item from `onChange` and pass it first, then the results without it. A choice also writes its own text back through `onInputChange`, so skip the search when the text is the chosen option's. And drop an answer that arrives after a newer request: abort the last fetch with an `AbortController`, or number your requests and keep only the latest, as the example does.

## States

When nothing matches, the list stays open and says "No matches" rather than vanishing, which would read as a broken field. A changed combo box shows the Changed chip and the light signal orange edge until the value is saved. An invalid one draws the error edge and its error line. A disabled one is recessed, its text in taupe.

## Usage

Keep the choice in the URL, so a filtered view can be shared, reloaded and gone back to. Pass the search parameter as `value` and write the URL in `onChange`. With the Next App Router:

```tsx
'use client';

import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { ComboBox, PickerOption } from '@snapshot-ui/react';

export function MerchantFilter({ merchants }: { merchants: { id: string; name: string }[] }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  return (
    <ComboBox
      label="Merchant"
      defaultItems={merchants}
      value={searchParams.get('merchant')}
      onChange={(key) => {
        const params = new URLSearchParams(searchParams);
        if (key === null) params.delete('merchant');
        else params.set('merchant', String(key));
        const query = params.toString();
        // No bare "?" once the last filter goes, and no jump to the top: the reader stays at the field.
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    >
      {(merchant) => <PickerOption>{merchant.name}</PickerOption>}
    </ComboBox>
  );
}
```

The combo box takes `value`, `defaultValue` and `onChange`; React Aria's older `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are deprecated and not accepted. Emptying the field clears the value, and `onChange` reports `null`, unless you control both `value` and `inputValue`, when clearing it is yours to do in `onInputChange`. Leaving the field puts the chosen option's text back, and so does scrolling the page while the list is open, which closes it; pass `allowsCustomValue` to keep free text instead, which is then what a form submits. In a plain form, give it a `name` and the chosen key is submitted, or its text with `formValue="text"`.

## Accessibility

The input is a `combobox` with `aria-expanded` and `aria-controls` over a `listbox` of `option`s, named by the field's label; the button is named "Show options" and the label, and stays out of the tab order, since the down arrow does the same from the field. Focus stays in the field while the list is open, and the active option moves with `aria-activedescendant`, which VoiceOver on iOS follows unevenly; how it reads with VoiceOver and TalkBack is not yet verified. React Aria announces the number of options and the choice in its own strings, which have no Persian, so on a Persian page they stay English; the button's name and the list's lines are the library's own `labels`. While the list is open, React Aria hides the rest of the page from assistive technology, the spinner too, so a list with nothing yet says "Loading" itself. Scrolling the page while the list is open closes it and puts the chosen text back, since the list would otherwise drift from its field; the soft keyboard opening on a phone resizes the page without closing it. Without a visible label, name the field with `aria-label`; its placeholder is then slate, since it is the only words shown.
