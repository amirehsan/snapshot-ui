## Basic

A text field over a list. Type part of a name and the list shows the options that contain it, ignoring case and accents: "cafe" finds "Café Luna", and "co" finds "Corner Mart" and "Cobalt Coffee". The button at the field's end, or the down arrow, shows every option. Choose with Enter or a press, and the field shows the option's text.

Use a combo box over a select when the list is long, or when people know the option by name. The options are the select's `PickerOption` and `PickerSection`, with their hints, icons and end values.

## From a server

To search on your server, pass `items` and `inputValue`, fetch in `onInputChange`, and set `isLoading` while you wait. The field shows a spinner, and the list keeps its results until new ones arrive, or says "Loading" while it has none. React Aria does not filter items you control, so your server filters, ranks and caps them. The example waits 300ms and returns at most eight.

- Keep the chosen item in `items`. React Aria finds it there to put its text back on Escape and on leaving the field. Hold it from `onChange` and pass it first, then the results without it.
- A choice writes its text back through `onInputChange`, so skip the search when the text is the chosen option's.
- Drop answers that arrive after a newer request. Abort the last fetch with an `AbortController`, or number requests and keep only the latest, as the example does.

## States

- No matches: the list stays open and says "No matches" instead of vanishing, which would read as a broken field.
- Changed: the Changed chip and the light signal orange edge, until the value is saved.
- Invalid: the error edge and its error line.
- Disabled: recessed, with its text in taupe.

## Usage

Keep the choice in the URL, so a filtered view can be shared, reloaded and revisited. Pass the search parameter as `value` and write the URL in `onChange`. With the Next.js App Router:

```tsx
'use client';

import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { ComboBox, PickerOption } from '@snapshot-ui/react';

export function MerchantFilter({ merchants }: { merchants: { id: string; name: string }[] }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  return (
    <ComboBox
      label="Merchant"
      defaultItems={merchants}
      value={searchParams.get('merchant')}
      onChange={(key) => {
        const params = new URLSearchParams(searchParams);
        if (key === null) params.delete('merchant');
        else params.set('merchant', String(key));
        const query = params.toString();
        // No bare "?" once the last filter goes, and no jump to the top: the reader stays at the field.
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    >
      {(merchant) => <PickerOption>{merchant.name}</PickerOption>}
    </ComboBox>
  );
}
```

- Selection: use `value`, `defaultValue` and `onChange`. React Aria's deprecated `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are not accepted.
- Clearing: emptying the field clears the value, and `onChange` reports `null`. If you control both `value` and `inputValue`, clear it yourself in `onInputChange`.
- Free text: leaving the field, or scrolling the page while the list is open, puts the chosen option's text back. Pass `allowsCustomValue` to keep free text instead, which a form then submits.
- Forms: give it a `name` to submit the chosen key, or its text with `formValue="text"`.

## Accessibility

The input is a `combobox` with `aria-expanded` and `aria-controls`, over a `listbox` of `option`s, named by the field's label. The button is named "Show options" plus the label. It stays out of the tab order, since the down arrow does the same. Without a visible label, name the field with `aria-label`; its placeholder is then slate, since it is the only words shown.

- Focus: stays in the field while the active option moves with `aria-activedescendant`. VoiceOver on iOS follows it unevenly, and reading with VoiceOver and TalkBack is not yet verified.
- Announcements: React Aria announces the option count and the choice in its own strings, which have no Persian, so they stay English on a Persian page. The button's name and the list's lines come from `labels`.
- Hidden page: while the list is open, React Aria hides the rest of the page from assistive technology, the spinner too, so an empty list says "Loading" itself.
- Scrolling: scrolling the page closes the list and puts the chosen text back, so the list never drifts from its field. The phone's soft keyboard resizes the page without closing it.
