## Parts

A field is a grid of parts, 8px apart. Label names the control, Description is the hint under it, and the clay chip marks an unsaved value. Type in the box to change it.

## States

Two attributes on the field's root carry its state.

- `data-changed`: shows the Changed chip.
- `data-invalid`: shows the error line and the control's error border, and hides the chip. Invalid outranks changed.

The first field below is changed. The second is changed and invalid.

## Length count

A count advises and never blocks. It stays empty until the value reaches 70% of the budget, then reads "34 of about 40". Past the budget it turns to ink at 700, and the value still grows and saves.

## Usage

[Text field](/docs/components/text-field) renders all of this in one element. For a custom layout, put the parts inside a React Aria field:

- Put the `field` class and `data-changed` on the field's root.
- Keep the chip in the label row, where the stylesheet shows or hides it.
- While the field is changed, pass the chip's `id` in the field's `aria-describedby`.

FieldError appears only while the field is invalid.

```tsx
import { useId } from 'react';
import { TextField } from 'react-aria-components';
import { Description, FieldChanged, FieldCounter, FieldError, Input, Label } from '@snapshot-ui/react';

export function ShortDescription({
  value,
  onChange,
  isChanged,
}: {
  value: string;
  onChange: (value: string) => void;
  isChanged: boolean;
}) {
  const chipId = useId();
  return (
    <TextField
      className="field"
      data-changed={isChanged ? '' : undefined}
      aria-describedby={isChanged ? chipId : undefined}
      value={value}
      onChange={onChange}
    >
      <div className="field-head">
        <Label>Short description</Label>
        <FieldChanged id={chipId} />
      </div>
      <Input />
      <Description>One sentence, for search results.</Description>
      <FieldError />
      <FieldCounter count={value.length} budget={60} />
    </TextField>
  );
}
```

In plain HTML, use the classes `field`, `field-head`, `field-label`, `field-description`, `field-error`, `field-counter` and `field-changed`.

## Accessibility

Label is a real label, so a click on it focuses the control. Description and FieldError join the control's accessible description. The chip sits beside the label, not inside it, so the control keeps its name. Naming the chip in `aria-describedby` has a screen reader read it with the field. A hidden element named there is still read, so Text field also removes the chip while the field is invalid.

The count is a polite status region, in the page and empty from the start, so a screen reader announces it as it changes. To announce less often, pass a count that settles after a pause.
