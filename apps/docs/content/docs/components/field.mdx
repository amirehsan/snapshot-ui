## Parts

A field is a grid of parts with 8px between them. Label names the control, Description is the hint under it, and the clay chip marks an unsaved value. Type in the box to change it.

## States

A field's root carries two attributes. `data-changed` shows the Changed chip. `data-invalid` hides it, because invalid outranks changed: the error line and the control's error border show instead. The first field is changed. The second is changed and invalid.

## Length count

A count advises and never blocks. It stays empty until the value reaches 70% of the budget, reads "34 of about 40", and past the budget turns to ink at 700. Nothing stops the value from growing, and it still saves.

## Usage

[Text field](/docs/components/text-field) renders all of this in one element. For a custom layout, put the parts inside a React Aria field: Label names the control, Description and FieldError become its description, and FieldError appears only while the field is invalid. Put the `field` class and `data-changed` on the field's root, and keep the chip in the label row, where the stylesheet shows or hides it. Give the chip an `id` and pass it in `aria-describedby` while the field is changed, so a screen reader reads it with the field.

```tsx
import { useId } from 'react';
import { TextField } from 'react-aria-components';
import { Description, FieldChanged, FieldCounter, FieldError, Input, Label } from '@snapshot-ui/react';

export function ShortDescription({
  value,
  onChange,
  isChanged,
}: {
  value: string;
  onChange: (value: string) => void;
  isChanged: boolean;
}) {
  const chipId = useId();
  return (
    <TextField
      className="field"
      data-changed={isChanged ? '' : undefined}
      aria-describedby={isChanged ? chipId : undefined}
      value={value}
      onChange={onChange}
    >
      <div className="field-head">
        <Label>Short description</Label>
        <FieldChanged id={chipId} />
      </div>
      <Input />
      <Description>One sentence, for search results.</Description>
      <FieldError />
      <FieldCounter count={value.length} budget={60} />
    </TextField>
  );
}
```

The classes are `field`, `field-head`, `field-label`, `field-description`, `field-error`, `field-counter` and `field-changed`, so the same parts work in plain HTML.

## Accessibility

Label is a real label, so a click on it focuses the control. Description and FieldError join the control's accessible description. The chip sits beside the label, not inside it, so the control keeps its name. To have a screen reader read it with the field, give the chip an `id` and pass that id to the field as `aria-describedby` while the chip shows. A hidden element named in `aria-describedby` is still read, so Text field also leaves the chip out of the page while the field is invalid.

The count is a polite status region that is in the page from the start and empty until it has something to say, so a screen reader announces it as it changes. To announce less often, pass it a count that settles after a pause.
