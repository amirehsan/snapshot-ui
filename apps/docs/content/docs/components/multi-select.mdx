## Basic

Type part of a name and the list opens with the options that contain it, or open every option with the button or the down arrow. A press or Enter toggles an option: the list stays open for the next choice, the input empties so the next search starts clean, and each chosen row shows a check. The chosen values sit in the field as tags, in the order you chose them.

## Many values

The field grows a row at a time, so every chosen value stays in view; nothing collapses into "and 3 more". Its corner is a full pill while it is one row and the surface step once it wraps. A long label ends in an ellipsis past 12rem, and its whole text stays the tag's name.

<Section>

## Removing

Each tag has a remove button. From the keyboard, the tags are one stop before the input: the arrow keys move between them, and Backspace or Delete removes the focused one, after which focus goes to the next tag, or the previous one when it was the last, or the input when none is left. Backspace in an empty input focuses the last tag first and removes it only on a second press, so one key never loses a value you did not see go. While the list is open the tags rest, out of reach of the pointer and the keyboard; Backspace in the empty input closes the list and then focuses the last tag.

</Section>

<Section>

## States

A changed multi-select shows the Changed chip and the light signal orange edge until the values are saved. An invalid one draws the error edge and its error line. A disabled one is recessed, its tags in taupe with no remove buttons, and nothing in it takes focus.

## Usage

The value is `readonly Key[]`, and `onChange` receives `Key[]`. Keep it in the URL, so a filtered view can be shared, reloaded and gone back to: read a repeated parameter with `searchParams.getAll('category')`, or split a comma-joined one, and write it back in `onChange`. With the Next App Router:

```tsx
'use client';

import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { MultiSelect, PickerOption } from '@snapshot-ui/react';

export function CategoryFilter({ categories }: { categories: { id: string; name: string }[] }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  return (
    <MultiSelect
      label="Categories"
      defaultItems={categories}
      value={searchParams.getAll('category')}
      onChange={(keys) => {
        const params = new URLSearchParams(searchParams);
        params.delete('category');
        for (const key of keys) params.append('category', String(key));
        router.replace(`${pathname}?${params.toString()}`);
      }}
    >
      {(category) => <PickerOption>{category.name}</PickerOption>}
    </MultiSelect>
  );
}
```

The multi-select takes `value`, `defaultValue` and `onChange`; React Aria's older `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are not accepted. If you control `inputValue` too, as a server search does, empty it in your `onChange`: React Aria empties the input after a choice only while one of the two is uncontrolled. In a plain form, give it a `name` and every chosen key is submitted as its own value under that name. A tag shows its option's text value, so an option whose label is not a string takes a `textValue`. There is no `allowsCustomValue`: a multi-select chooses from its list, and free text is a tag input's job.

## Accessibility

The input is a `combobox` with `aria-expanded` and `aria-controls` over a `listbox` of `option`s that allows several, named by the field's label; each chosen row has a check as well as its selected state. The tags are a `grid` named "Selected" and the label, one tab stop before the input, and each remove button is named "Remove" and the tag's text; the remove buttons stay out of the tab order, since Backspace and Delete do the same on a focused tag. The input is described by the chosen values, so a screen reader hears them after the field's name. While the list is open React Aria hides the rest of the page from assistive technology, and the tags leave the tab order with it. A disabled field draws its tags in a disabled group, read and never focused. React Aria announces the number of options in its own strings, which have no Persian; the field's names and lines are the library's own `labels`. How it reads with VoiceOver on iOS and TalkBack is not yet verified.
