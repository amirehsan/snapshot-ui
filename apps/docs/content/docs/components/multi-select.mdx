## Basic

Type part of a name to list the options that contain it, or open every option with the button or the down arrow. A press or Enter toggles an option. The list stays open for the next choice, the input empties for the next search, and each chosen row shows a check. Chosen values show in the field as tags, in the order chosen.

## Many values

The field grows a row at a time, so every chosen value stays in view. Nothing collapses into "and 3 more". Its corner is a full pill on one row and the surface step once it wraps. A tag label longer than 12rem ends in an ellipsis, and its full text stays the tag's name.

## Removing

Each tag has a remove button. From the keyboard, the tags are one tab stop before the input.

- Arrow keys move between tags.
- Backspace or Delete removes the focused tag. Focus moves to the next tag, the previous one if it was last, or the input if none are left.
- Backspace in an empty input focuses the last tag, and a second press removes it. One key never removes a value you did not see.
- While the list is open, a remove button still works and closes the list. Backspace in the empty input closes the list, then focuses the last tag.

</Section>

<Section>

## States

- Changed: shows the Changed chip and the light signal orange edge until the values are saved.
- Invalid: shows the error edge and its error line.
- Disabled: recessed, with taupe tags and no remove buttons. Nothing in it takes focus.
- Read-only: tags stay reachable by keyboard for reading, with no remove buttons and no removal.

## Usage

The value is `readonly Key[]`, and `onChange` receives `Key[]`. Keep it in the URL so a filtered view can be shared, reloaded and returned to. Read a repeated parameter with `searchParams.getAll('category')`, or split a comma-joined one, and write it back in `onChange`. With the Next App Router:

```tsx
'use client';

import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { MultiSelect, PickerOption } from '@snapshot-ui/react';

export function CategoryFilter({ categories }: { categories: { id: string; name: string }[] }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  return (
    <MultiSelect
      label="Categories"
      defaultItems={categories}
      value={searchParams.getAll('category')}
      onChange={(keys) => {
        const params = new URLSearchParams(searchParams);
        params.delete('category');
        for (const key of keys) params.append('category', String(key));
        const query = params.toString();
        // No bare "?" once the last filter goes, and no jump to the top: the reader stays at the field.
        router.replace(query ? `${pathname}?${query}` : pathname, { scroll: false });
      }}
    >
      {(category) => <PickerOption>{category.name}</PickerOption>}
    </MultiSelect>
  );
}
```

- Value props: use `value`, `defaultValue` and `onChange`. React Aria's older `selectedKey`, `defaultSelectedKey` and `onSelectionChange` are not accepted.
- Controlled input: if you also control `inputValue`, as a server search does, empty it in your `onChange`. React Aria empties the input after a choice only while one of the two is uncontrolled.
- Forms: give it a `name`, and each chosen key is submitted as its own value under that name.
- Tag text: a tag shows its option's text value, so an option whose label is not a string needs a `textValue`.
- No `allowsCustomValue`: a multi-select chooses from its list. Free text is a tag input's job.

## Accessibility

The input is a `combobox` with `aria-expanded` and `aria-controls`, over a multi-select `listbox` of `option`s named by the field's label. Each chosen row has a check as well as its selected state.

- Tags: a `grid` named "Selected" plus the label (or the field's `aria-label` or `aria-labelledby` when no label is shown), one tab stop before the input.
- Remove buttons: each is named "Remove" plus the tag's text. They stay out of the tab order, since Backspace and Delete do the same on a focused tag.
- Description: the input is described by the chosen values, so a screen reader hears them after the field's name.
- Open list: React Aria hides the rest of the page from assistive technology, tags included, but leaves them focusable. A remove button still works, and Shift+Tab still reaches the tags and closes the list.
- Disabled: the tags are a disabled group, read but never focused.
- Strings: React Aria's option count and its focused tag hint, "Press Delete to remove tag.", have no Persian strings. The field's names and lines come from the library's `labels`.

How it reads with VoiceOver on iOS and TalkBack is not yet verified.
