## Color mode

Set `data-theme="light"` or `data-theme="dark"` on any element. With no attribute on the page, dark follows the system setting.

```tsx
<html data-theme="dark">
```

With `next-themes`, use the attribute mode:

```tsx
<ThemeProvider attribute="data-theme" defaultTheme="system" enableSystem>
```

</Section>

## Corner shape

Set `data-shape` to `rounded`, `soft` or `square`. Every corner comes from one scale, so one attribute recuts all of them. Dots, such as a radio's indicator, stay round in every shape, because their roundness carries meaning.

## Density

Set `data-density="compact"` on any element. Controls and fields inside it are 36px tall (44px on a touch screen), and cards pad 20px. Type, colors, corners and every other space stay the same. `data-density="comfortable"` inside a compact element restores the defaults, and the nearest attribute wins.

<Preview name="density-controls" />

- Touch: compact controls are 44px, taller than comfortable ones, because 44px is the target a finger needs. Comfortable controls are 40px on every screen.
- Segmented control: the one exception. Its track is 44px, and each option is 36px, hit at 40.

Compact on phones is your site's rule, not an attribute value, because an attribute cannot know the screen width. The tokens are public, so set them in a media query:

```css
@media (width < 768px) {
  :root {
    --spacing-card: 20px;
  }
}
```

This site does that for its cards. To make every control compact on a phone, set `--size-control` and `--size-field` the same way.

A popup keeps the density of what opened it, as it keeps the color mode and the corner shape. See [Overlays](#overlays).

</Section>

## Nesting

All three attributes, `data-theme`, `data-shape` and `data-density`, work on any element, and the nearest one wins. A light card inside a dark page takes its own colors and text color.

```tsx
<main data-theme="dark">
  <section data-theme="light" data-shape="square">...</section>
</main>
```

## Overlays

A dialog renders at the end of the page, so it cannot inherit attributes from the element it opened from. Instead it copies `data-theme`, `data-shape` and `data-density` from that element's nearest ancestors that carry them. A dialog opened from a button in a dark card is dark while the page stays light. Every other overlay in the library does the same.

- The toast region follows the page root.
- An overlay opened by a keyboard shortcut copies from whatever holds focus. With nothing focused, it takes the page's theme.
- A dialog that moves focus into a field as it opens still copies from what held focus before.

For an overlay the copy cannot reach, such as one a third-party component opens, use React Aria's `UNSAFE_PortalProvider` from the `react-aria` package. It renders every overlay inside it into a container you choose. Put the container inside the scope:

```tsx
import { UNSAFE_PortalProvider } from 'react-aria';

const [container, setContainer] = useState<HTMLElement | null>(null);

<section data-theme="dark" ref={setContainer}>
  <UNSAFE_PortalProvider getContainer={() => container}>{children}</UNSAFE_PortalProvider>
</section>;
```

Four variables set the stacking order. If your app's chrome uses larger numbers, set the overlay variables higher.

- `--z-toast` (1100): the toast region, above everything.
- `--z-modal` (1000): modal surfaces and their scrims.
- `--z-chrome` (30): fixed chrome, such as the rail and the tab bar.
- `--z-header` (20): a sticky page header.

</Section>

## Tokens

Every value is a CSS variable you can read, such as `var(--color-ink)`, `var(--radius-control)` or `var(--spacing-peer)`. The same tokens are available in JavaScript, with each mode's value:

```tsx
import { tokens } from '@snapshot-ui/core/tokens';

tokens.color.slate.var; // 'var(--color-slate)'
tokens.radius.pill.modes.shape.soft; // '12px'
```

Beyond the original set, the tokens include:

- `--color-warning`: a state that needs a look soon, with its own rule of use.
- `--color-gain`: money that arrived, with its own rule of use.
- `--text-numeral` and `--text-numeral-sm`: type steps for figures.
- `--size-control`, `--size-field` and `--size-target`: control sizes.
- `--spacing-card`: card padding.
- `--spacing-inset`: how far floating chrome sits from the viewport's edge.
- `--container-sidebar`: the rail's width.
- `--z-modal`, `--z-toast`, `--z-chrome` and `--z-header`: the stacking order, described in [Overlays](#overlays).
