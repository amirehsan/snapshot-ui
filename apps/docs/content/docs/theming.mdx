## Color mode

Set `data-theme="light"` or `data-theme="dark"` on any element. With no attribute on the page, dark follows the system setting.

```tsx
<html data-theme="dark">
```

With `next-themes`, use the attribute mode:

```tsx
<ThemeProvider attribute="data-theme" defaultTheme="system" enableSystem>
```

</Section>

## Corner shape

Set `data-shape` to `rounded`, `soft` or `square`. Every corner in the library comes from one scale, so one attribute recuts all of them. Dots, such as a radio's indicator, stay round in every shape, because there roundness carries meaning.

## Density

Set `data-density="compact"` on any element, and the controls and fields inside it draw at 36px, 44px on a touch screen, and its cards pad 20px. Nothing else changes: the type, the colors, the corners and every other space stay as they are. `data-density="comfortable"` inside a compact element restores the defaults for everything inside it, and the nearest one wins, as it does for the other two attributes.

<Preview name="density-controls" />

On a touch screen a compact control is taller than a comfortable one, because 44px is the target a finger needs. A segmented control is the one exception inside: its track is 44px, and each option in it is 36px, hit at 40. Comfortable does not change on touch: its controls are 40px on every screen.

Phone-wide compact is your site's rule, not a value of the attribute, because an attribute cannot know the width of the screen. The tokens are public, so set them where you know it:

```css
@media (width < 768px) {
  :root {
    --spacing-card: 20px;
  }
}
```

This site does exactly that for its cards. A site that wants every control compact on a phone sets `--size-control` and `--size-field` the same way.

A popup keeps the density of what opened it, as it keeps the color mode and the corner shape: see [Overlays](#overlays).

</Section>

## Nesting

All three attributes, `data-theme`, `data-shape` and `data-density`, work on any element, and the nearest one wins. A light card inside a dark page takes its own colors and its own text color.

```tsx
<main data-theme="dark">
  <section data-theme="light" data-shape="square">...</section>
</main>
```

</Section>

## Overlays

A dialog renders at the end of the page, outside the element it opened from, so it cannot inherit that element's attributes. Instead it copies `data-theme`, `data-shape` and `data-density` from the nearest ancestors of the element it opened from that carry them, so a dialog opened from a button in a dark card is dark while the page stays light. Every other overlay the library adds follows the same rule, except the toast region, which follows the page root. An overlay opened by a keyboard shortcut copies from whatever holds focus, and one opened with nothing focused takes the page's own theme. A field inside a dialog that takes focus as it opens does not change this: the dialog records what held focus before its content takes it.

For an overlay the copy cannot reach, such as one a third-party component opens, React Aria's `UNSAFE_PortalProvider`, from the `react-aria` package, renders every overlay inside it into a container you choose. Put the container inside the scope:

```tsx
import { UNSAFE_PortalProvider } from 'react-aria';

const [container, setContainer] = useState<HTMLElement | null>(null);

<section data-theme="dark" ref={setContainer}>
  <UNSAFE_PortalProvider getContainer={() => container}>{children}</UNSAFE_PortalProvider>
</section>;
```

Overlays are stacked by two variables: `--z-modal` (1000) for the modal surfaces and their scrims, and `--z-toast` (1100) for the toast region, which sits above them. The app's chrome sits under both: fixed chrome, such as the rail and the tab bar, at `--z-chrome` (30), and a sticky page header at `--z-header` (20). An app whose own chrome uses larger numbers sets the overlay variables higher.

</Section>

## Tokens

Every value is a CSS variable you can read, such as `var(--color-ink)`, `var(--radius-control)` or `var(--spacing-peer)`. The same tokens are available in JavaScript, with each mode's value:

```tsx
import { tokens } from '@snapshot-ui/core/tokens';

tokens.color.slate.var; // 'var(--color-slate)'
tokens.radius.pill.modes.shape.soft; // '12px'
```

Beyond the original set, the tokens include `--color-warning` and `--color-gain` (a state that needs a look soon, and money that arrived, each with its own rule of use), the `--text-numeral` and `--text-numeral-sm` type steps, the control sizes `--size-control`, `--size-field` and `--size-target`, the card padding `--spacing-card`, `--spacing-inset` (how far floating chrome sits from the viewport's edge), `--container-sidebar` (the rail's width), and `--z-modal`, `--z-toast`, `--z-chrome` and `--z-header`, the stacking order of the modal surfaces, the toast region and the app's chrome, which an app whose chrome uses larger numbers may override.

</Section>
