## Install

Both packages, with React 19 or later.

```bash
pnpm add @snapshot-ui/react @snapshot-ui/core
```

</Section>

<Section>

## Charts

Charts are a package of their own, with versions of their own.

```bash
pnpm add @snapshot-ui/charts
```

It needs `@snapshot-ui/core` 0.3.0 or later, whose `styles.css` already draws the charts, and React 19, and nothing else: no React Aria. See the [Line chart](/docs/charts/line-chart) and [Sparkline](/docs/charts/sparkline) pages.

</Section>

<Section>

## Import the stylesheet

Once, at the root of your app. `styles.css` holds the tokens and every component. `base.css` is optional: it sets the page background, the body type, the font rendering details and an ink focus ring for your own links and fields.

```tsx
import '@snapshot-ui/core/styles.css';
import '@snapshot-ui/core/base.css';
```

The CSS sits in cascade layers, so your own unlayered CSS always wins, and Tailwind's utilities win over the components.

</Section>

## Load the font

Snapshot UI sets body text at weight 450, which only a variable font has. In Next.js, `next/font` self-hosts it and sets the family the tokens read:

```tsx
import { Sofia_Sans } from 'next/font/google';

const sofia = Sofia_Sans({ subsets: ['latin'], display: 'swap', variable: '--font-sans' });

export default function RootLayout({ children }) {
  return (
    <html lang="en" className={sofia.variable}>
      <body>{children}</body>
    </html>
  );
}
```

Anywhere else, install `@fontsource-variable/sofia-sans` and import it once. The font stack already includes its family name.

## React Aria, if you install it too

`@snapshot-ui/react` pins `react-aria-components` to exactly 1.22.1, because the toast parts it wraps are unstable in React Aria. If your app installs `react-aria-components` itself, pin it to that same version, with no range, so the app and the library share one copy of React Aria:

```json
{
  "dependencies": {
    "react-aria-components": "1.22.1"
  }
}
```

Take `RouterProvider` and `I18nProvider` from `@snapshot-ui/react`, which re-exports React Aria's own, so they always reach the library's parts. [Routing](/docs/routing) sets up the router.

</Section>

## Right to left

Every part reads its direction from the locale, through React Aria. A `dir` on a page section lays out what is inside it, but a dialog, a menu, a popover or a tooltip opened from there is portaled to the end of the body and never sees that `dir`. So wrap a right-to-left region, such as a guide in Persian, in `I18nProvider` with the region's locale, beside its `dir` and `lang`:

```tsx
import { I18nProvider } from '@snapshot-ui/react';

export function PersianGuide({ children }) {
  return (
    <I18nProvider locale="fa-IR">
      <section dir="rtl" lang="fa">
        {children}
      </section>
    </I18nProvider>
  );
}
```

A whole app in one right-to-left language wraps its root the same way. A toast follows the locale where `ToastRegion` is mounted, not the region it was raised from, so an app with a right-to-left section mounts its `ToastRegion` inside the same `I18nProvider` if it wants right-to-left toasts.

</Section>

## Next.js server components

Interactive components carry `'use client'`. Static ones carry none, so a server component renders them with no client JavaScript: Heading, Text, Eyebrow, Kbd, Badge, Card, the field counter and chip, Meter, a StatTile without `href`, and Sparkline. React Aria itself must never be imported into a server component.

</Section>

## Tailwind CSS, if you use it

`tailwind.css` exposes the tokens as utilities, such as `bg-canvas`, `text-slate`, `rounded-control` and `p-part`. It also removes Tailwind's default radii, text sizes and shadows, so an off-system value like `rounded-lg` compiles to nothing.

```css
@import 'tailwindcss';
@import '@snapshot-ui/core/tailwind.css';
@import '@snapshot-ui/core/styles.css';
```
